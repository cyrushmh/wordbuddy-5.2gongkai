## 一、参同契全本迁移（ArkTS → Swift）

**动机**：04 指出 Swift 端 `cantongqi` 仅 2 示例章，与 HarmonyOS 端内嵌全本（90 章 + 鼎器歌 + 赞序，约 6000 字）数据契约不一致。本轮对齐。

**迁移口径**（脚本化、可复现）：
- 用「书边界」（`\n  },`）截取 ArkTS `ClassicsData.ts` 的 `cantongqi` 整本书，避免古文中 `[ ]` 干扰括号配平（首版误用配平法，曾把下一本书 `qingjing` 的章节误吞，已改为边界法修正）。
- 字段映射：`label → title`、`id` 自编（`ctq-1 … ctq-90`、`ctq-dingqige`、`ctq-zanxu`）、`original` 直迁、`translation` 留空（与 `hasTranslation:false` 一致）。
- **抓取噪声清洗**（ArkTS 源自带）：
  - 第 6 章：`打开APP阅读全文-->` 标记整段删除；
  - 第 67 章等处跨行换行合并（`没\n水` → `没水`）；
  - 顶部回显标题（如 `乾坤者易之门户乾坤者，…`）的前缀回显剥除；
  - CJK 字符间残留空格归一（古典文本不空格）。

**校验**：编号章连续 `ctq-1 … ctq-90` 无缺无重；`ctq-dingqige`/`ctq-zanxu` 各 1；全文无 `打开APP阅读全文` 残留；Swift 全文件 `{ } ( ) [ ]` 配平通过。

**配套**：Swift `ClassicsData.swift` 顶部说明由「仅含示例章」更新为「已全量迁移，其余书目为示例章」。

## 二、Swift 书架分组 + 朝代时序排序

## 三、双端导入页接入编码防护（落到用户路径）

**动机**：04 建的 `TextEncoding`（BOM 剥离 → 严格 UTF-8 → 严格 GB18030 → 有损 U+FFFD）此前零引用。本轮把它接到「外部导入 txt」入口，防止错配编码（古文码/口字码/锟拷码）污染正文——呼应 `justjavac/unicode-encoding-error-table`。

**iOS / macOS（共用 `ImportView.swift`）**：
- `fileImporter`（`.text`，单选）→ `Data(contentsOf:)` → `TextEncoding.decodeSafe(_:)` → 预览 + `looksLikeMojibake` 指纹自检（命中则橙色告警）。
- 接线：iOS 增第 4 个 Tab「导入」；macOS 分栏「工具」增「导入」按钮 → `pane = .importText` → detail 显示 `ImportView`。
- 依赖 `ContentUnavailableView`（iOS 17 / macOS 14，与 `Package.swift` 平台声明一致）。

**HarmonyOS NEXT（新建 `pages/ImportText.ets`）**：
- `DocumentViewPicker().select({ mimeType: 'text/plain' })` → `fileIo` 读字节 → `decodeTextSafe(bytes)` → 预览 + `looksLikeMojibake`。
- 接线：`Index.ets` 检索框下方增「导入本地文本」按钮 → `router.pushUrl('pages/ImportText')`；`main_pages.json` 注册 `pages/ImportText`。
- 三端解码逻辑同源，差异只在平台 IO（沙箱/选择器）与 UI。

## 七、修真图谱页（数据层 → App 可视化）

**动机**：修真图谱数据层（`research/xiuzhen/build_xiuzhen_map.py`，67 节点 / 66 边，节点全部带 source）此前只存在于引擎侧 `sysweeper/data/xiuzhen_map.json`。本轮让它在 App 里可看、可点、可读屏。

**数据流（可复现，与引擎同源）**：

```
research/xiuzhen/build_xiuzhen_map.py
  → research/xiuzhen/map_canonical.json          （canonical，构建自检悬空边=0）
  → sysweeper/data/xiuzhen_map.json              （引擎 CLI 消费，#359 接线）
  → entry/src/main/ets/model/XiuzhenMap.generated.ts （本页消费，与 canonical 同源同刻）
```

**落点**：

| 文件 | 作用 |
|---|---|
| `model/XiuzhenMapLayout.ts`（新建） | 纯函数层：索引 / 分层布局 / 邻域布局 / 关系文案。无 UI 依赖，可 Node 单测 |
| `pages/XiuzhenMap.ets`（新建） | 三视图页：Canvas 骨架 + Text 覆盖层（标签兼命中区）+ 文本等价列表 + 详情卡 |
| `pages/Index.ets` | 检索框下方增「修真图谱」入口卡（读屏文案含全量说明） |
| `resources/base/profile/main_pages.json` | 注册 `pages/XiuzhenMap`（第 6 页） |

**三种等价视图**（缺一即信息丢失，对应「无障碍保障必须留存」）：
1. **邻域探索**：聚焦节点居中、邻节点环绕（默认 `book:daodejing`，3 个邻节点 / 4 条关联边）；Canvas 连线按结构性边（归属/覆盖，深色）与相关性边（主题/旁引，浅色）分色。
2. **分层全景**：五条横带（道藏部类 23 / 典籍 12 / 专题 7 / 旁参经论 10 / 语料 15）均布全部节点，66 条跨层边画为骨架直线；点击圆点切入邻域模式。
3. **文本等价视图**：始终渲染的关系/节点列表——每条边一条中文行（如「道德经（老子） 属于 道德真经」「……主题 脏腑辨证（命中 135 次）」），点击行可跳转到对端节点。Canvas 是「好看」，列表是「等价」。

**绘制纪律**：Canvas 只用本项目已实证的 2D API（`clearRect/arc/fill/stroke/moveTo/lineTo/fillRect`，先例：`ChartCanvas.ets`/`GoBoard.ets`）；不用 `fillText/font/globalAlpha`（无先例）——文字一律走覆盖层 `Text`，既保证可读屏，又让命中区天然可达。坐标系统一固定 320×280vp，布局确定可测。

**验证（沙箱无 DevEco SDK 下的尽力而为，不伪造成功）**：
- 纯函数层：`tsc --strict` 类型检查通过；`tests/test_xiuzhen_map_layout.cjs`（Node，28 项断言）全绿——覆盖悬空边=0、全 67 节点邻域冒烟（位置/规模合法）、关系文案、边界兜底。
- 页面逻辑层（字段/getter/绘制方法，`struct→class` + ArkUI 打桩后）：`tsc --strict` 通过。
- 未验证：HAP 真机构建（SDK 缺失，#294 诚实阻塞）；`build()` 的声明式 DSL 只能靠既有工程先例背书（`Scroll/Column/Row/Stack/Canvas/List/ForEach/position/layoutWeight/accessibilityText` 均在本工程其他页有据）。
