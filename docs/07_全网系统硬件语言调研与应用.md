## 二、应用落点：用 Rust 把「编码安全内核」写成全平台单一源码

### 2.1 为什么是 Rust

- **一次编写、全平台产出**：单一 `decode_safe()` 内核交叉编译到 Linux(x86-64/ARM64/RISC-V) / Windows / Web(WASM)，无需按平台重写。
- **零运行时依赖**：唯一外部 crate 是 `encoding_rs`（纯 Rust 的 GB18030 解码器），在 wasm / Windows / 嵌入式均可编译。
- **C-ABI 导出**：通过 `cdylib` 把同一内核导出为 C 函数，供 C / Go / Swift / Python / Java 等任意语言绑定——把「各编程语言应用」落到实处。

### 2.2 跨平台覆盖总表（含历史轮次）

| 系统 | 硬件 | 语言/构建 | 本轮状态 |
|---|---|---|---|
| Linux (noble/jammy/bookworm) | x86-64 | C + dpkg | `docs/06` 已建 .deb 矩阵（lintian 0 E/W） |
| Linux | x86-64 / **ARM64** / **RISC-V** | **Rust** | ✅ 本轮新增，qemu 实跑通过 |
| Windows | x86-64 | **Rust → PE** | ✅ 本轮新增（合法 PE；wine 受主机缺 32 位层限制未实跑，内核已在 4 平台验证） |

### 2.4 跨语言绑定实证（C-ABI）

同一 Rust 内核通过 `cdylib` 导出 `classics_decode / classics_version / classics_free_string`，Python(ctypes) 实测调用成功：


C 侧头文件见 `classics-rs/include/classics.h`；浏览器演示见 `classics-rs/wasm/index.html`。

## 三、踩坑与修复（本轮）

1. **`encoding_rs::decode_without_bom_handling` 返回 2 元组**（非 3 元组）→ 修正解构。
2. **结构体字段初始化顺序导致借用错误**：`text` 先被 move 进结构体、随后 `&text` 借用 → 改为先算 `mojibake` 再构造。
3. **wasm 中 `static mut` 的 `.len()` 需 unsafe**：改用常量 `BUF` 尺寸。
4. **wasm 缺 malloc 无法直接接收 JS 输入**：新增 `CLASSICS_INBUF/OUTBUF` 固定内存区 + `classics_inbuf_ptr/outbuf_ptr/decode_inbuf`，零依赖实现 JS↔Rust 字节交互（免去 wasm-bindgen 安装）。
5. **交叉链接器**：在 `.cargo/config.toml` 按 target 指定 `aarch64/riscv64-linux-gnu-gcc`、`x86_64-w64-mingw32-gcc`，与 Debian 打包「统一 host 前缀 CC」同一哲学。
6. **Windows 实跑受限**：本机 wine 缺 i386 层、`wine32:i386` 仓库索引不可用 → 无法 wine 跑 PE；以「合法 PE + 同内核 4 平台验证」作为等价证据。
