## 一、RFC 9846 是什么 / 相对 RFC 8446 改了什么

RFC 9846 是 **TLS 1.3 的 2026 年标准修订版**，状态 Standards Track，废弃并取代：

- RFC **8446**（上一版 TLS 1.3）、**5246**（TLS 1.2）
- 以及 RFC 5077 / 6961 / 7627 / 8422（均属 TLS 1.2 及更早）
- 更新 RFC 5705、6066；并对 **TLS 1.2 实现提出新要求**（Appendix D）

### 1.1 头号变更：密钥交换从「仅 (EC)DHE」泛化为「KEM-based」

> §1.3 / §1.2：「Use more generic language for the asymmetric key exchange, which was
> previously exclusively (EC)DHE, to reflect the use of KEM-based key exchange.」
> 「Other extensions define the use of key-encapsulation mechanisms (KEMs).」

**落地形态**（容易误读，已核实）：KEM 不是新增握手模式——`PskKeyExchangeMode` 仍是
`{ psk_ke(0), psk_dhe_ke(1) }` 不变。KEM 公钥以**新的 NamedGroup**（如 ML-KEM / 混合组）
经 `key_share` / `supported_groups` 扩展承载，复用既有 `KeyShareEntry.key_exchange` 字段。
即：把"密钥协商"抽象成"封装/解封装"，为后量子（NIST FIPS 203 ML-KEM）开了标准口子。

### 1.2 禁止协商旧版本

> §1.2：明确**禁止协商 TLS 1.0 / 1.1**（二者已被 RFC 8996 废止）。

配合 legacy_version 语义：`legacy_version` 字段**必须固定为 0x0303**（TLS 1.2 记录层版本号），
真实版本号走 `supported_versions` 扩展里的 `0x0304`。这是向后兼容中间盒（middlebox）的硬约束。

### 1.3 强制/推荐密码套件（Appendix B.4）

| 套件 | 值 | 要求 |
|---|---|---|
| `TLS_AES_128_GCM_SHA256` | `{0x13,0x01}` | **MUST** |
| `TLS_AES_256_GCM_SHA384` | `{0x13,0x02}` | SHOULD |
| `TLS_CHACHA20_POLY1305_SHA256` | `{0x13,0x03}` | SHOULD |

## 二、规范代码「保留」而非「重写」——落点

RFC 版权声明要求：抽取的代码组件必须附 **Revised BSD License**。本修订的核心规范代码在
**附录 B（Protocol Data Structures and Constant Values）**：线格式 `struct` 定义、握手消息类型、
扩展类型、NamedGroup、密码套件值、Key Schedule HKDF 标签。

**处理原则**：把这些数值与 TLS 表示法结构**逐字留存为参照层**，绝不转写成"我们自己的实现"，
也**不为它们写逐项单测**（我们没有实现 TLS，转写才需要测）。

> 落点文件：`system-optimizer/src/python/sysweeper/data/rfc9846_spec.py`
> - 含 BSD 许可头（满足 RFC 抽取要求）
> - live 常量：`TLS_*` 版本号、`CIPHER_SUITES`、`HANDSHAKE_MESSAGE_TYPES`、
>   `EXTENSION_TYPES`、`NAMED_GROUPS`、`PSK_KEY_EXCHANGE_MODES`、`KEY_SCHEDULE_LABELS`
> - **逐字注释** `APPENDIX_B_VERBATIM`：`ClientHello` / `ServerHello` / `KeyShareEntry` /
>   `PskKeyExchangeMode` 的 TLS 表示法原文

## 三、集成到 toolkit 的推荐（已落地最小可用骨架）

### 3.1 为什么落点是 `sysweeper`（而非 classics / PE）

`sysweeper` 已有 `tasks/cert.py`（证书与加密栈只读审计）、`tasks/network.py`、`registry.py`、
`native/cert.py`——天然是"系统加密态势审计"的家。**现有缺口**：只审计"装了哪些加密库/证书"，
**没有审计"OS 实际允许协商什么 TLS"**。RFC 9846 正好补这块。

> ⚠️ **命名陷阱（务必分清）**：Windows PE 格式里有个 "TLS Directory"，那是 **Thread Local
> Storage**，与 Transport Layer Security 毫无关系。PE 解析器（`Windows/src/.../peinfo`、`pe_inspect.py`）
> **不要**因同名把 RFC 9846 接进去。`classics-*` 各端 App 是内容展示，也与 TLS 配置审计无关。

### 3.2 已创建的文件（只读、低风险）

| 文件 | 作用 | 风险 |
|---|---|---|
| `data/rfc9846_spec.py` | 保留规范代码（常量 + 逐字 struct + BSD 头） | 无（纯参照） |
| `native/tls13.py` | 只读态势审计：读 Schannel 注册表/跨平台安全降级；协议分级处置；`a11y_tls13_summary()` 人话摘要；`tls13_audit_report()` 引擎友好 `(bool,text)` 渲染 | low（只读） |
| `tasks/tls13.py` | 4 个任务：态势审计 + 禁用真淘汰旧版(指引,opt_in) + 老旧设备共存(指引,opt_in) + 后量子就绪(指引,opt_in)，`standards` 引 RFC 9846/8996/FIPS 203 | low/medium(指引) |
| `registry.py` | 注册 `tls13` 模块（两处 import/loop） | 无 |
| `tests/test_tls13.py` | **最小化**冒烟测试（5 项，全绿） | — |

任务设计要点（沿用 `cert.py` 范式）：
- `Action("native", ...)` 只读审计；`Action("manual", ...)` 只给官方步骤、不代执行（严守红线）。
- 写操作（禁用旧 TLS、换 KEM 栈）一律 `opt_in` 指引，绝不自动改注册表。

### 3.3 审计能查什么（non-exhaustive，用户可控）

- **Windows**：读 `HKLM\...\SCHANNEL\Protocols\{SSL 2.0/3.0/TLS 1.0/1.1/1.2/1.3}\{Client|Server}`
  的 `Enabled`/`DisabledByDefault`，断言已废止协议未显式启用。
- **跨平台**：不读 Schannel，改给平台建议（Linux `crypto-policies`、macOS `security` 偏好、OpenSSL 构建核查）。
- **KEM/后量子**：仅检测加密栈是否提供 KEM NamedGroup 以标注 "PQC-ready"，**不实现 ML-KEM**。

## 五、诚实范围声明（防过度承诺）

1. `sysweeper` 是**配置态势审计 + 加固指引**工具，**不是 TLS 库**。我们引用规范、审计 OS 配置，
   不实现握手。
2. **KEM/后量子**相关只是"能力检测 + 迁移指引"，ML-KEM 本身由底层 TLS 栈（OpenSSL 3.x 等）提供。
3. 规范代码**逐字留存**，若 RFC 后续勘误（errata），以 `rfc-editor.org/info/rfc9846` 为准更新常量。
4. 遗篇/旧版兼容（Appendix E 中间盒兼容模式）仅作审计参照，不在本任务实现握手回退逻辑。

## 七、完善推进：适老化 + 老旧设备兼容 + 无障碍对接（v0.6.33）

用户追加要求：**把 RFC 进入整体，保障适老化、老旧设备设施也能用、无障碍必须留存**。本次落地三条硬原则：

### 7.1 适老化 / 无障碍必须留存

- 新增 `native/tls13.a11y_tls13_summary()`：纯文本「人话」状态，屏幕阅读器可朗读、无图形依赖，与既有 `a11y_cert_summary()` 统一口径。
- 措辞适老：不用只读缩写堆砌、不用矛盾标签（曾出现"必须处理……请放心"的冲突措辞，已改正为"放心：……""需要处理：……"）；风险用「放心 / 待确认 / 需要处理 / 由你决定」分级；明示"本工具只读、不擅自改动，你来做主"。
- 打法对齐：`tls13_audit_report()` 报告内嵌「-- 无障碍简述 --」段，与 `cert_audit_report()` 同构。

### 7.2 老旧设备/设施仍能用（关键纠偏）

- 协议处置**分级**，不再一刀切：`retire`（SSL 2.0/3.0、TLS 1.0/1.1，必须禁）／`bridge_keep`（**TLS 1.2 保留**作兼容桥，按 RFC 9846 附录 D 硬化）／`primary`（TLS 1.3 主力 + KEM 就绪）。
- 审计在检测到"TLS 1.2 未启用"时，明确提示老旧设备可能失联并建议保留+硬化，而非误报 PASS。
- 新增 `tls13_legacy_device_coexistence_guidance`（opt_in 指引）：保两头、稳中间——淘汰死的、保留并硬化 TLS 1.2、渐进迁移、隔离或替换收尾。

### 7.3 进入整体（接线纠错）

- 修复引擎契约：动作 op 由指向返回 `dict` 的 `tls13_posture_report` 改为指向返回 `(bool,text)` 的 `tls13_audit_report`——否则 `runner._run_native` 会把 `dict` 的 `repr` 当输出（既不无障碍也不可读）。已实测经 `_run_native('tls13.tls13_audit_report')` 派发生成 1546 字无障碍文本。
- 任务从 3 个扩为 4 个，均注册进 `registry`，`standards` 引 RFC 9846/8996/FIPS 203 / SP 800-52r2。

### 7.4 验证

`tests/test_tls13.py` 5 项全绿（规范常量 / 兼容分级 / 无障碍人话 / 引擎友好渲染 / 任务可注册），`tests/test_cert.py` 9 项不回归。
