## 一、做了什么

把散落三处的「道家修真」知识收成一张**带出处的关系图谱**，并同时落到引擎侧与 App 侧：

```
research/xiuzhen/build_xiuzhen_map.py        # 唯一构建脚本（可复现：SRC= 可指向任意副本）
   ├── classics-harmony-app/.../ClassicsData.ts   # 典籍 12 部 + 道藏部类 23 类 + KEY_TEXTS 11 篇
   ├── research/harvest/analysis.json             # 语料 14 篇的 topic_hits + classic_hits
   └── research/suwen_81_index.json               # 《素问》81 篇收录进度
   ↓
research/xiuzhen/map_canonical.json               # canonical（67 节点 / 66 边，indent=1 美化版）
   ↓ （同脚本同刻输出两处消费副本）
sysweeper/data/xiuzhen_map.json                   # 引擎侧副本（compact 序列化省体积，内容同构）
classics-harmony-app/.../XiuzhenMap.generated.ts  # App 侧副本（扁平化 label/detail，同源同刻）
```

**三道消费**（对应决策①「全都要」）：

| 消费 | 入口 | 说明 |
|---|---|---|
| 引擎 CLI | `sysweeper xiuzhen`（v0.6.46） | overview / layers / list / search / show / edges，纯文本一行一事实，读屏可朗读 |
| App 页 | `classics-harmony-app` 第 6 页「修真图谱」 | 邻域探索（Canvas 骨架）+ 分层全景 + **文本等价视图**（读屏/长辈信息通道） |
| 数据层 | `importlib.resources` 惰性加载 | 不占 import 期；`native/xiuzhen_catalog.py` 只读封装 |

### 1.1 图谱模型（67 节点 / 66 边）

| 层 | 节点数 | 内容 | 数据源 |
|---|---|---|---|
| daozang 道藏部类 | 23 | 三洞四辅十二类 | `DAOZANG_CATALOG`（ClassicsData.ts） |
| classics 典籍 | 12 | 已结构化收录的 12 部道家经典 | `CLASSICS`（同上） |
| topics 研修主题 | 7 | 脏腑辨证/穴位经络/方药食疗/情志疗愈/国学修身/民俗命理/功法导引 | analysis.json topic_hits |
| external 旁参典籍 | 10 | 语料命中但未全文结构化（素问/难经/灵枢/周易…） | analysis.json classic_hits |
| corpus 采集层 | 15 | 公众号语料 14 篇 + 《素问》语料集 | analysis.json + suwen_81_index.json |

关系类型（6 种）：`belongs_to` 11（典籍→部类）、`has_topic` 28（语料→主题）、`mentions` 13（语料→旁参）、`intro_mentions` 8（典籍简介→旁参）、`same_tradition` 4（旁参→同脉典籍）、`corpus_covered_by` 2（旁参→素问语料集）。

### 1.2 纪律（与 RFC 轮一脉相承）

- **节点/边一律带 `source`，无出处不建节点、不连边**——宁缺毋滥。如《清静经》道藏归属已诚实标注「通例归于太玄部，无独立 nid」而不硬造编号。
- 构建期自检：**悬空边 = 0**（任一端点不在节点表即 `sys.exit`）；App 布局层再做一次同名自检。
- canonical 与两处消费副本**内容同构**（nodes/edges/meta/layers 逐元素相等），序列化格式有意不同（canonical 美化便于人工审读，包内 compact 省体积）——不谎称逐字节一致。

## 二、引擎侧：CLI 与只读消费层

```
sysweeper xiuzhen                       # 速览：规模/分层/类型分布/纪律 + 子命令提示
sysweeper xiuzhen layers                # 5 层清单（含每层节点数与层描述）
sysweeper xiuzhen list [--layer X]      # 节点列表（按层过滤）
sysweeper xiuzhen search <词>           # 名称检索（黄庭 3 命中 / 脏腑辨证 1 命中）
sysweeper xiuzhen show <节点>           # 详情：说明/道藏编号/在线原文/出处/关联数
sysweeper xiuzhen edges <节点>           # 全部关联关系中文句
```

节点解析三入口：**精确 id > 显示名（类型优先级 book>部类>语料集>主题>旁参>文章）> 前缀**（书名常带括注，「道德经」命中 `book:daodejing` 而非旁参 `ext:道德经`）；查无返回 None 并诚实提示，不臆造。

## 三、App 侧：修真图谱页（第 6 页）

`pages/XiuzhenMap.ets` + 纯函数布局层 `model/XiuzhenMapLayout.ts`：

- **邻域探索**：聚焦节点居中、邻节点环绕；Canvas 骨架按「结构性边（深）/相关性边（浅）」分色；点节点/点关系行均可跳转。
- **分层全景**：五横带均布全部节点，66 条跨层边画为骨架直线。
- **文本等价视图**：始终渲染——Canvas 是「好看」，列表是「等价」；每条边一条中文行，点击行跳到对端节点。**缺此列表即视障/长辈用户信息丢失**，对应「无障碍保障必须留存」。
- 绘制纪律：Canvas 只用项目内已实证的 2D API（`clearRect/arc/fill/stroke/moveTo/lineTo/fillRect`，先例 ChartCanvas/GoBoard）；不用 `fillText/font/globalAlpha`（无先例）——文字一律走覆盖层 `Text`，命中区天然可读屏。
- 接线：`main_pages.json` 注册第 6 页；`Index.ets` 检索框下方加入口卡（读屏文案含全量说明）。
