# 二十一、编程语言「概念系统」与硬件架构子分类（v0.6.56）

以仓库 **wordbuddy-github 为主目录（概念系统）**，把 `data/langs_docs.json` 的 161 条语言
组织成**分层概念体系**；对可运行语言**实际尝试编程整体**；信息不足之处用 **RFC 等底层标准**补足。

## 一、分层结构（四条分类轴）

```
主目录（概念系统）wordbuddy-github
  ├─ 轴1 执行模型 execution_model（8 类）
  │    native(56) / bytecode-vm(15) / interpreted(44) / jit(3)
  │    transpiled(8) / ir(1) / hdl(2) / non-exec(32)
  ├─ 轴2 硬件架构 target_arch（13 类，「有条件的以硬件架构为子分类」）
  │    isa          : x86-64(51) · arm64(49) · riscv(8)
  │    virtual-isa  : wasm(8)
  │    vm           : jvm(5) · clr(3) · beam(3) · evm(4) · js(10)
  │    accelerator  : gpu-simt(3)
  │    reconfigurable: fpga(2)
  │    host         : 宿主进程(47)   ← 解释/JIT，架构取决于宿主
  │    non-exec     : n-a(32)        ← 配置/查询/标记类，谈架构无意义
  ├─ 轴3 能力域 domain（7 个）：systems / network / data / query / identity / web / security-crypto
  └─ 轴4 底层标准依据 standard_basis：各域挂 RFC / ISO / ECMA / IEEE / Unicode
```

**「有条件」的诚实处理**：能明确目标架构的才按架构归类（如 Rust→x86-64/arm64/riscv/wasm、
Verilog→fpga、Solidity→evm）；解释/JIT 归 `host`；配置/查询/标记等归 `n-a`。
每条语言标 `mapping_source`：`explicit`（人工判定）或 `inferred`（按 category 推断，可逐条细化）。

## 二、各语言各自尝试编程整体（实测，非纸面）

统一**8 面能力契约**，每种语言写一个覆盖「整体」的示例（不是 hello world），**实际编译/运行**：

`LANG / LITERALS / OPS / CONTROL / FUNC / DATA / IO / ERROR / CONCURRENCY`

| 结果 | 语言 |
|---|---|
| **实测通过 15/15** | Python · JavaScript · TypeScript(deno) · Go · Rust · C · C++ · Java · Ruby · Perl · Bash · AWK · Tcl · **F#** · Makefile |

样例落在 `research/plang/samples/`，实测记录 `research/plang/probe_report.json`
（`run_probe.py --check` 校验样例与记录一致）。

> **诚实边界**：只有**本机装有工具链**的语言才实测；没有的一律标「未实测」并写清原因，
> **绝不臆造运行结果**。当前 15 种全部真跑通过（含 C/C++ 的 pthread 并发、Go 的 goroutine、
> Rust 的 thread、Java 的 ExecutorService、F# 的 Async.Parallel）。

## 三、不足的以 RFC 等底层标准补充（且验证过编号）

语言条目自身的 `standard` 字段常常是「无 ISO 标准」——**不足处由所属能力域继承底层标准依据**：

| 能力域 | RFC 依据（经本仓库 `rfc_catalog` 交叉验证） |
|---|---|
| systems | RFC 9293（TCP） |
| network | RFC 9110（HTTP 语义）· 9112（HTTP/1.1）· 8446（TLS 1.3）· 1035（DNS） |
| data | RFC 8259（JSON）· 3629（UTF-8） |
| query | RFC 3629（UTF-8） |
| identity | RFC 3986（URI）· 3339（日期时间）· 5322（消息格式） |
| web | RFC 9110 · 8446 |
| security-crypto | RFC 8446 · **5280（X.509）** |

**关键纪律**：所有 RFC 编号在 `build_plang.py` 构建时**经本仓库 rfc_catalog（10,036 条）
反查存在性**，并把标题回填到 `rfc_title`；`--check` 若发现编号不实即报错退出。
测试 `test_every_rfc_ref_exists_in_rfc_catalog` 再兜一层——**补的是真标准，不是编的编号**。

## 四、数据层与 CLI

- 数据：`data/concepts/plang_taxonomy.json`（由 `research/plang/build_plang.py` 从 `langs_docs.json` 构建；v0.6.59 起概念系统数据统一落 `data/concepts/`）
- 只读层：`concepts/plang.py` —— `info/stats/models/archs/langs_of_arch/langs_of_model/of/domains/standards_of/rfc_refs/probe/probe_of`
- CLI：**`sysweeper plang`**
  - `plang` 概念系统速览（主目录/四轴/各口径说明）
  - `plang archs` 硬件架构子分类清单 · `plang arch <架构>` 该架构下语言（如 `arch fpga` → Verilog/VHDL）
  - `plang models` / `plang model <模型>`
  - `plang of <id>` 单语言完整分类（模型/架构/域/**继承的底层标准**/映射来源）
  - `plang rfc [id]` RFC 依据 · `plang probe` 实测结果 · `plang domains` 域与底层标准

## 五、测试（11 项，`tests/test_plang.py`）

- 规模口径（161 / 8 模型 / 13 架构 / 7 域）
- 架构种类齐备（isa·virtual-isa·vm·accelerator·reconfigurable·host·non-exec）
- 具体分组正确（fpga=Verilog·VHDL；jvm=Java·Kotlin·Scala·Clojure·Ballerina；beam=Erlang·Elixir·Gleam；evm=Solidity·Move·Cairo·Noir）
- **每条语言都有执行模型且架构合法**
- **每个 RFC 编号都能在 rfc_catalog 中查到**（真实性硬约束）
- 按域继承标准、未知语言返回空
- 实测记录 15 条且每条约 8 个能力面齐全
- `build_plang.py --check` 与 `run_probe.py --check` 均通过
