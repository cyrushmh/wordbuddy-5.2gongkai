# 27 · 概念系统中心与目录重构（v0.6.59）

本轮以**概念系统为中心**重构重置目录结构，并一次性引入三个新概念系统：
量子理念（quantum）、编译与工具链（comp）、接口 API（apilab），最终由
**概念系统中心**（注册表 + CLI `concepts` + GUI「概念系统中心」窗口）统一收口。

## 1. 目录重构：三层骨架（以概念系统为中心）

```
src/python/sysweeper/
├── concepts/                       # 只读层：每个概念系统一个成员模块（同构 API）
│   ├── _common.py                  #   共享加载器 load_taxonomy()（importlib.resources + 回退路径，lru_cache）
│   ├── __init__.py                 #   中心注册表 REGISTRY / TAGLINES / systems / load / module / overview / search_all
│   ├── plang.py / netsys.py / daoxue.py / quantum.py / comp.py / apilab.py
└── data/concepts/                  # 数据层：<系统>_taxonomy.json（只读数据，不写业务）
research/<系统>/build_<系统>.py      # 构建层：可复现生成 + --check 防漂移（桥接悬空即失败）
```

重构口径：**新概念系统只需追加三处**——`data/concepts/<name>_taxonomy.json`（数据）、
`concepts/<name>.py`（只读层）、`REGISTRY` 一行（注册）；CLI/GUI 复用共享派发，
不再逐系统复制粘贴。

## 2. 概念系统中心：六系统注册表

| 系统 | 定位 | 规模 | 版本 |
|---|---|---|---|
| `plang` | 编程语言概念系统（执行模型→硬件架构→能力域→底层标准） | 161 条语言 | v0.6.56 |
| `netsys` | 网络与组网概念系统（层次→形态→性质→标准） | 24 模块 + 15 关系边 | v0.6.57 |
| `daoxue` | 道枢治理层概念系统（道德经 81 章为中心） | 15 原则 / 31 桥接 | v0.6.58 |
| `quantum` | 量子理念概念系统（七域） | 54 概念 / 18 桥接 / 7 标准 | v0.6.59 |
| `comp` | 编译与工具链概念系统（五轴） | 50 概念 / 41 桥接 / 15 语言实测 | v0.6.59 |
| `apilab` | 接口 API 概念系统（五轴 + 仓库接口面） | 32 概念 / 12 桥接 / 12 RFC | v0.6.59 |

中心口径：`REGISTRY`（系统名→数据文件）是唯一登记表；`overview()` 逐系统取
`info()`+`stats()` 汇总；`search_all(term)` 跨系统检索，命中带 `system` 字段标明
来源；某系统无 `search` 实现时跳过，不臆造命中。

## 3. 三个新系统的同构骨架

quantum/comp/apilab 共享同一套只读 API 与入口范式：

| 层 | 共享部分 | 系统特有 |
|---|---|---|
| 只读层 | `info/domains/domain/concepts/concepts_of_domain/concept/of/needs_verify/bridges/bridges_of/search/stats` | quantum:`standards`；comp:`lang_needs/lang_need/verified_lang_needs`；apilab:`standards/repo_facts` |
| CLI | `overview/domains/domain/of/bridge/search/verify/stats`（共享派发 helper） | quantum:`standards`；comp:`need/needs`；apilab:`repo/rfc` |
| GUI | 三通用页（分类轴 / 桥接 / 检索·待核实） | quantum=标准登记册页；comp=语言编译需要页；apilab=仓库接口面+RFC 依据页 |

GUI 底部按钮：「量子理念」「编译工具链」「接口 API」+ 既有「道枢治理观」；
新中心按钮「概念系统中心」打开六系统总览窗口（双击某系统惰性展开其面板）。

## 4. 诚实边界与防漂移（全系统统一口径）

- **只读、不联网、不改配置**：三个新系统均不驱动真实动作（不执行量子线路、
  不发起编译、不改网络配置），只做理念/标准/事实登记。
- **needs_verify 不臆造**：quantum 3 条（IEEE 7130 标准 + 2 条概念级）；
  comp 1 条（146 种语言编译需要汇总）；apilab 仅 1 条口径说明——repo-face
  数字要么构建时实测、要么不登记。
- **`--check` 防漂移**：三个构建脚本均支持 `--check`（轴合法、counts 自洽、
  桥接无悬空）；apilab 额外把磁盘登记值与源码实测值（CLI 子命令数 / webapi
  ACTIONS 数）逐键比对，开发期真实检出 99→102→103 漂移链并重建。
- **RFC 交叉验证**：apilab 引用的 12 条 RFC 编号均经本仓库 `rfc_catalog`
  （10,036 条官方 INDEX 解析）验证存在并回填标题。

## 5. 用法

```bash
# 概念系统中心（六系统统一入口）
python3 -m sysweeper concepts                 # 六系统总览
python3 -m sysweeper concepts search 令牌      # 跨系统检索（命中带 system 字段）
python3 -m sysweeper concepts show comp        # 单系统摘要

# 单系统入口（与中心同数据层、同口径）
python3 -m sysweeper quantum | comp | apilab | plang | netsys | daoxue …

# 构建与防漂移（逐系统）
python3 research/quantum/build_quantum.py --check
python3 research/comp/build_comp.py --check
python3 research/apilab/build_apilab.py --check

# GUI：底部「概念系统中心」按钮（六系统总览 + 跨系统检索 + 双击跳转各面板）
```
