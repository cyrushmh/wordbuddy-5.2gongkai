# 28 · 南华真经用户端概念系统与用户端人体工程学（v0.6.60）

> 以仓库 `wordbuddy-github` 为主目录。本文登记第七个概念系统 `zhuangzi`，以及
> 以《南华真经》（《庄子》）核心理念对**用户端**（终端 / 图形界面 / Web 控制台 /
> 报告查看器）的人体工程学改造。只读不联网，不复制经典全文。

## 1. 立意：从治理层走向用户端

docs/23–27 已建立六个概念系统：`plang`（编程语言）、`netsys`（网络组网）、
`daoxue`（道枢治理层，中心《道德经》）、`quantum`（量子理念）、`comp`
（编译工具链）、`apilab`（接口 API）。本系统补上第七块：**用户端**。

治理层回答「工程怎么做才不失衡」（daoxue 的 15 条可审计原则）；用户端回答
**「使用者怎么用才不违其性」**——以《南华真经》为指导思想，用户指定核心理念
三篇：内篇一《逍遥游》、内篇七《应帝王》、内篇六《大宗师》。

## 2. 数据层：四轴 19 条概念

`data/concepts/zhuangzi_taxonomy.json`（构建器
`research/zhuangzi/build_zhuangzi.py`，`--check` 防漂移）：

| 轴 | 条数 | 内容 |
| --- | --- | --- |
| `core` 核心理念 | 3 | 逍遥游（无待一步）/ 应帝王（顺性不抢）/ 大宗师（以使用者意图为宗师） |
| `inner` 内篇辅篇 | 4 | 齐物论（双模平权）/ 养生主（养生不伤）/ 人间世（人间安命）/ 德充符（德充于内） |
| `outer` 外篇与杂篇 | 5 | 秋水 / 天道 / 达生 / 胠箧 + 概览（26 篇未逐篇登记，needs_verify） |
| `ergonomics` 工程原则 | 7 | 七篇理念翻译成的可审计人体工程学原则 |

每篇概念三件套：`gist`（篇旨）→ `detail`（章旨，含经典寓言）→
`engineering`（用户端工程落法，指向本仓库真实功能）。示例落法：

- **逍遥游**：「无待即不预设前提：不依赖记忆、教程、环境配置，常用任务从任意
  状态一屏可达」（→ CLI `guide` 一屏入口地图）。
- **应帝王**：惠子谓樗树「大而无用」，庄子答「树之于无何有之乡……彷徨乎无为
  其侧，逍遥乎寝卧其下」；儵忽为浑沌「日凿一窍，七日而浑沌死」——**不为用户
  凿窍**：默认即最佳、零配置可用、帮助是发现式而非必修（→ 各端默认路径 =
  安全档，`--help`/GUI 提示行/控制台 `/help` 发现式取目录）。
- **大宗师**：「不以心捐道，不以人助天」——意图先行而非规程先行：预测式默认、
  最小惊讶、失败指路可回退（→ 三端错误统一 `hint` 字段、GUI 确认三段式、
  快照先行可回退）。

## 3. 桥接：理念 → 既有系统，构建期强制无悬空

11 条桥接边全部指向目标数据层真实存在的条目（`--check` 逐条校验）：

- **→ daoxue（8 条，治理原则）**：逍遥游→道法自然「无待即不预设前提」；应帝王→
  无为「顺物自然而无容私」；大宗师→知不知「以使用者意图为宗师」；养生主→守中
  「缘督以为经」；齐物论→不争「双模平权」；人间世→信言不美「能力边界诚实告知」；
  德充符→见素抱朴「内容重于形式」；秋水→图难于其易「大事化小展示前提」。
- **→ apilab（3 条，接口概念）**：达生→`repo-cli`「合手则忘」；天道→`repo-webapi`
  「控制台即交互式探索场」；胠箧→`repo-plugins`「白名单制 = 绝钩绳之圣：不给
  未登记入口留门」。

## 5. 三端人体工程学改造（真实落码，非口号）

### 5.1 终端（CLI）

- **`guide` 子命令**（`sysweeper/ergonomics.py` + cli 注册）：一屏入口地图
  （12 场景组），`--principles` 附七原则；**双向校验**——`ungrouped_commands()`
  （子命令漏分组）与 `phantom_commands()`（地图写了不存在的命令，带参表达式取
  首词）由 `tests/test_ergonomics.py` 断言，子命令增减即时暴露。
- **预测式下一步**：`ergonomics.followup_hints()` 按当前命令给建议（不强制）；
  `next_hint()` 统一「完成→下一步 / 未完成→原因+回退」两态格式。

### 5.2 图形界面（GUI）

- **`confirm_risky(parent, title, consequence, rollback)`** 模块级三段式确认
  （养生主·不伤 + 大宗师·失败指路可回退）：后果 → 回退路径（无回退明示不可逆）；
  已替换 4 处 `askyesno` 裸调用：恢复默认、清空留痕、确认载入为参数、
  再次确认执行。无显示环境保守返回 `False`（不确定即不执行）。
- 底部按钮区新增「南华理念」（`show_zhuangzi`，四轴三页 + 用户端面实测页）。

### 5.3 Web 控制台与报告查看器（deno，v0.6.60）

- `console.ts`：启动横幅打印**动作白名单目录摘要**（前 12 条 + 总数/只读写数），
  新增 `GET /manifest`（前端发现式消费，`app.js` 总览页展示「动作白名单 N 个」）；
  bridge 三类错误（写失败 / 后端退出 / 非 JSON）统一带 `hint` 指路；
  `/api` 缺 action 时指向 `/manifest`。
- `report_viewer.ts`：渲染后新增**「返回重来 / 再载入一份（自动出对比）/ 生成
  分享链接」**三按钮（应帝王：输入区不锁死；养生主：分享前明示 URL=公开发布）；
  `tryParse` 失败给具体下一步（整段复制 / 文件下载完整 / 换拖文件入口）；
  静态页 `report_viewer.html` 已由 `tools/gen_report_viewer.py` 重新生成，
  sha256 守护通过（`scripts/check_repo_guard.py`）。

## 6. 入口与用法

```bash
python -m sysweeper zhuangzi userface          # 用户端面实测
python -m sysweeper zhuangzi verify            # needs_verify 挂牌

# 用户端操作层

deno run --allow-net --allow-read --allow-run src/deno/console.ts   # Web 控制台
```

## 7. 诚实边界与红线

1. **不复制经典全文**：只登记篇旨/章旨/落法；用户未上传《南华真经》原典文本，
   全部篇旨按通行本登记并统一挂 `needs_verify`（与 daoxue 心经/论语同口径），
   不逐字臆造原文。
2. **外杂 26 篇只选登 5 条**：秋水/天道/达生/胠箧 + 概览，其余不逐篇臆造。
3. **七原则系理念的工程翻译**，非经典原文；工程落法指向本仓库实测事实
   （`user_face_facts` 构建期实测，`--check` 防漂移）。
4. **改造不破坏既有语义**：CLI 无参数仍默认 `scan`；`guide`/`zhuangzi` 为纯
   新增子命令；GUI 确认从 `askyesno` 迁到三段式封装但保留调用点语义；
   deno 权限面不变（仍不申请 `--allow-write`/`--allow-env`）。
5. **红线延续 apilab/auth**：破坏性操作快照先行、最小惊讶、失败指路可回退；
   令牌禁入 URL/localStorage、私钥不明文。
