02I/O 系统与存储驱动栈

原书第 6 章指出：设备驱动是连接 I/O 管理器与相关硬件的内核模块（.sys），运行在三种上下文之一——发起 I/O 的用户线程、内核系统线程、或中断上下文。

存储驱动栈（Storage Driver Stack）

一次磁盘读请求会自上而下穿过如下分层驱动。理解它才能定位延迟发生在哪一层：

最底层微端口直接对话硬件 分层驱动：每层可加 Filter 驱动 请求逐层封装为 IRP

IRP 与分层驱动模型

原书强调："Windows 中的设备驱动并不直接操作硬件，而是通过调用 HAL（硬件抽象层）例程与硬件交互。" 每个驱动把请求封装成I/O 请求包（IRP）传给下一层。这意味着：

  • Filter 驱动可叠加在任何层：例如磁盘的上层 Filter 驱动可做额外安全检查（原书 Ch.6 举例），文件系统的 Filter 驱动可做镜像、加密、病毒扫描——但每层都会增加一点 I/O 延迟。
  • 越往栈底越靠近硬件：storport 端口驱动与微端口驱动决定队列深度、NCQ/命令调度、MSI-X 中断效率，是延迟的"最后一公里"。
优化含义过多的文件系统过滤驱动（杀软、加密、备份代理）会让每一次读写都穿过更多层。磁盘慢时，应先排查过滤驱动数量与顺序，而非盲目换硬件。

03内存分页与磁盘

原书第 5 章：当物理内存不足时，内存管理器会把部分内存内容换页到磁盘（paging to disk）；线程访问已被换出的虚拟地址时，内存管理器再从磁盘加载回来。

内存压力是磁盘 I/O 的源头

物理内存紧张 → 工作集被修剪 → 页面被写入分页文件 → 后续访问触发页错误（page fault），引发磁盘读。这就是"内存不够时系统变卡且磁盘灯狂闪"的机理。

页面优先级（Page Priority）

原书提到页面优先级与进程 I/O/页面优先级继承：后台进程默认页面优先级 5、I/O 优先级 Normal；可通过 Job/进程属性调低，使其换页与 I/O 不抢占前台。

主动内存管理：SuperFetch

原书在"Proactive memory management"一节描述 SuperFetch 与 ReadyBoost——按使用模式把可能用到的页面预取到内存/ReadyBoost 缓存，减少未来的磁盘读取。

优化含义很多"磁盘问题"实际是"内存问题"。优先保证足够物理内存、合理设置分页文件，可消除大量由换页引起的磁盘读。

04缓存管理器

原书描述缓存管理器：通过让最近引用的磁盘数据驻留内存来加速文件 I/O，并把更新暂存在内存中一小段时间再下刷磁盘（延迟写）——它借助内存管理器的映射文件支持实现。

读缓存（Read Caching）

热点文件重复读命中内存缓存，不落盘。顺序大文件扫描会"污染"缓存——这是大型拷贝后系统变慢的常见原因。

机理：最近引用驻留内存

延迟写（Lazy Write）

写操作先入内存、稍后由延迟写入线程批量下刷。提升吞吐但存在掉电丢数据窗口；关键数据应走 write-through / 强制刷新。

机理：write-back 缓冲
优化含义对数据库、交易类写入，需权衡"延迟写带来的吞吐提升"与"崩溃一致性"。必要时用 FILE_FLAG_WRITE_THROUGH 或电池备份写缓存（BBWC）来既保性能又保安全。

05按介质分类：HDD vs SSD

所有后续优化都受介质物理特性约束。先建立介质模型，才能正确选择动作。

维度HDD（机械盘）SSD（固态盘）
随机读写慢（寻道 + 旋转延迟，毫秒级）快（无寻道，微秒级）
顺序读写尚可（持续吞吐）极快
碎片影响大（随机寻道被放大）几乎无（无机械寻道）
写磨损无有（PE 周期，需 TRIM/均衡）
优化重心减少随机寻道、碎片整理、队列深度TRIM、预留空间、避免不必要写入
结论对 SSD，"碎片整理"应关闭（系统不会对其运行传统 defrag，而是运行 Retrim）；对 HDD，碎片整理仍显著提升随机读取性能。

06碎片整理策略

HDD 推荐

定期碎片整理可把文件连续化，把随机寻道变为顺序读取，直接对应"随机读写慢"的介质特性。用内置 defrag /O（优化 + 常规碎片整理）。

机理：消除随机寻道

SSD 不需要

SSD 无机械寻道，碎片对性能几乎无影响；运行传统碎片整理反而增加写磨损。Windows 对 SSD 自动改为 Retrim（通知 SSD 可回收无效块），由计划任务定期执行。

机理：TRIM 回收
可执行动作defrag C: /O /V 查看优化状态；确认 SSD 的"已通过 Retrim 优化"。对 HDD 设每周计划任务；对 SSD 仅保留 Retrim。

07写入缓存与延迟写

对应缓存管理器的延迟写（write-back）与磁盘类驱动的写缓存缓冲。这是"吞吐 vs 崩溃一致性"的核心权衡。

开启设备写缓存缓冲（Write Cache Buffer Flushing）

在磁盘策略中启用"启用设备上的写入缓存"，可把小写入合并批量下刷，大幅提升吞吐。代价：断电可能丢最近写入。必须配合 UPS 或带电容保护的 RAID 写缓存（BBWC/HBBU）。

关闭"关闭设备写缓存刷新"需谨慎

若禁用写缓存刷新（让 OS 认为每次写都已落盘），会牺牲性能换取更强一致性；仅在无 UPS 且不能容忍丢失时使用。

数据库/日志走 Write-Through

关键事务用 FILE_FLAG_WRITE_THROUGH + 磁盘带保护写缓存，既保崩溃一致性又不牺牲全部吞吐。

风险边界无 UPS、无电池保护时开启写缓存 = 断电即可能丢失已"确认"的写入。笔记本用电池可视为天然 UPS，台式机/服务器务必配 UPS 或 BBWC。

08预取（Prefetcher）与 ReadyBoost

对应第 5 章的"逻辑预取器与 ReadyBoot""主动内存管理（SuperFetch）""ReadyBoost"。

Prefetcher / SuperFetch

按启动与应用使用模式预取页面到内存，减少冷启动后的磁盘读取。默认开启；内存充足时收益最大。

机理：主动内存管理

ReadyBoost

用高速 U 盘/SD 作"缓存补充"，缓存随机读热点。对内存/磁盘受限的老机器有效；对已有充裕 RAM + SSD 的现代机器收益甚微。

机理：随机读缓存

ReadyBoot

启动轨迹预取，加速系统启动 I/O。属于 Prefetcher 的启动场景实现。

机理：启动轨迹
优化含义现代 SSD + 大内存机器上 ReadyBoost 基本无收益，可禁用以省去一层过滤/缓存开销；老 HDD 小内存机器则保留并配高速 U 盘。

10电源与链路电源管理

对应第 6 章电源管理器（Connected Standby / Modern Standby、电源可用性请求）。链路电源管理会在空闲时降低链路功耗，但带来唤醒延迟。

ALPM / HIPM 链路节电 服务器慎用

AHCI/NVMe 链路电源管理在空闲时降功耗，但恢复 I/O 有毫秒级唤醒延迟，会让随机小 I/O 抖动。数据库/低延迟场景建议设为"主动"。

机理：电源管理器链路状态

电源计划 = 高性能 推荐

对存储服务器/工作站，选"高性能"或自定义：禁用磁盘闲置超时（或设很长），避免频繁停转/降速。

机理：电源可用性请求
可执行动作电源选项 → 高级 → 硬盘 →"在此时间后关闭硬盘"设为 0（从不）；"PCI Express → 链路状态电源管理"设为关闭（低延迟场景）。

11I/O 优先级调优

对应第 6 章"I/O 优先级"与第 3/4 章进程/线程优先级继承。原书：每个线程有 I/O 优先级（Critical/High/Normal/Low/Very Low），并继承父进程默认（Normal）。

压低后台任务的 I/O 优先级

备份、索引、杀毒扫描等设 Low/Very Low I/O 优先级，使其不抢占前台交互的磁盘带宽。原书指出 I/O 优先级与页面优先级一并继承。

前台的 I/O 不被饿死

系统本身对前台进程有 I/O/页面优先级提升；为避免反例，勿把所有任务都设为 High/Critical。

容器/作业级隔离

用 Job 对象统一设置 CpuPriorityClass / IoPriority / PagePriority，把批处理作业关进低优先级"笼子"。

可执行动作用 Process Explorer 的"列 → I/O 优先级"查看；用 start /LOW /WAIT 或任务计划程序的"运行级别"约束后台任务；用 wpr/ETW 抓取 I/O 真实分布。

12分页文件与卷布局

综合第 5 章内存管理（分页到磁盘）与第 2 章架构（4K/扇区对齐）。

优化项机理依据建议
分页文件位置换页 I/O 直接落到 pagefile放最快的盘（ preferably SSD）；多盘可分散
分页文件大小过小→频繁修剪/页错误；过大→浪费系统托管或固定为 1–1.5× 物理内存（服务器按负载）
4K 扇区对齐512e/4Kn 盘未对齐会产生读-改-写用 DISKPART 确认分区 4K 对齐；新装系统默认已对齐
卷布局随机 I/O 集中在热点卷系统/数据/日志分开卷，热点数据独立磁盘
常见误区完全禁用分页文件并不能"加速"，反而让内存管理器失去安全阀，极端情况下触发系统受限甚至崩溃。除非物理内存极其充裕且明确负载，否则保留系统托管分页文件。
