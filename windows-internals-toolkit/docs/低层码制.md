# 低层码制（lowcode）：机器码 / 编译码 / 字符编码 / 通信码 / 逻辑转换码

> 版本：0000.0000.0000.0004.20261024　|　入口：`python -m sysweeper code`　|　代码：`system-optimizer/src/python/sysweeper/lowcode/`

## 1. 这是什么

`sysweeper.lowcode` 是 sysweeper 包内的「底层视图」子包。它不优化任何东西，做的是：
**把平时要开网页计算器、翻手册、靠人肉心算的那类底层问题，变成可验证的纯函数。**

| 层 | 模块 | 干什么 | 典型场景 |
|---|---|---|---|
| 位与二进制 | `bits` | 进制、端序、位域、原码/反码/补码、格雷码、BCD、奇偶、IEEE 754 | 抓包里 `0x12345678` 读出来不对；驱动寄存器位域怎么算 |
| 字符编码 | `chars` | ASCII 控制表、Unicode 码点、UTF-8/16/32、Base 系列、百分号/HTML/C/JSON 转义、摩尔斯、字符集互转 | 乱码排查；确认一段字节到底是什么编码 |
| 通信码 | `comm` | CRC（六参数模型 + 8 个内置变种）、校验和、HDLC/SLIP/COBS 成帧、线路编码、汉明码、波特率 | 与协议文档对 CRC；算串口一帧传多久 |
| 逻辑转换码 | `logic` | 布尔求值、真值表、SOP/POS、卡诺图、Quine-McCluskey、NAND/NOR 变换、加法器 | 理解 ALU 与 `add` 指令；化简逻辑表达式 |
| 机器码与字节码 | `machine` | Python 字节码、Java class 常量池与 Code 反汇编、x86-64 指令结构拆解 | 读 .pyc；看 class 文件；拆一条指令的字段 |

设计约束（与全包一致）：

1. **纯标准库、零第三方依赖**——有 `python3` 就能跑，随单文件 `.pyz` 一起分发；
2. **纯函数、只读**——只解析调用方传入的字节，不读文件系统（除 `--file` 显式指定）、不联网、不改系统；
3. **graceful**——非法入参返回带 `error` 的字典而非抛异常；
4. **给标准出处**——每层都有 `STANDARD_REFS`，按「国内 / 国际 / 地区」三层标注；
5. **都带文本渲染函数**——CLI 直接吃，不重复写格式化逻辑。

## 2. 用法

```bash
python -m sysweeper code                                   # 五层概览
python -m sysweeper code bits    [--action explain|endian|float|bcd|gray|bases|base] --value <整数> [--width N] [--base N]
python -m sysweeper code chars   [--action charset|base|escape|morse|mojibake|ascii] --value <文本或十六进制>
python -m sysweeper code comm    [--action crc|checksum|frame|line|hamming|uart|baud] --value <十六进制或位串>
python -m sysweeper code logic   [--action table|sop|pos|kmap|qm|nand|adder] --value <表达式> [--y N] [--width N]
python -m sysweeper code machine [--action py|pyc|x86|java|ident] [--value …] [--file …]
```


RISC-V 64I 反汇编（与 x86-64 形成 CISC/RISC 对照）：覆盖 RV64I 基础整数集 + RV64 双字扩展
（OP-IMM-32 / OP-32）——算术、加载/存储（含 RV64 双字 `ld`/`sd`）、分支（`beq` 等立即数符号扩展）、
跳转/链接（`jal`/`jalr`，`x0` 时化简为 `j`/`ret`）、移位（含 `slli`/`srli`/`srai` 的 6 位 `shamt`）、
`lui`/`auipc`、`fence`/`fence.i`、`ecall`/`ebreak`，以及伪指令（`mv`=`addi rd,rs,0`、`sext.w`=`addiw`）。
寄存器**始终显示 x 编号**（直接对应 bit 位置），不改 ABI 别名以免与编码脱节。

### 进制：使用者视角默认十进制

`bits` 层把"人类可读的十进制"放在屏幕第一眼，二进制 / 三进制 / 十六进制等作为底层参考排在下面（`render_bases`）。这是有意为之：

- **输入**：`--value 255` 默认按**十进制**解读（不是十六进制）。要写其他进制用前缀 `0x`/`0o`/`0b`，或显式 `--base N` 配 `base` 动作。旧的 `from_base` 默认按十六进制解析裸数字（`255` → `0x255` = 597），那是机器视角，已在 `bits` CLI 改为 `default_base=10`。
- **输出**：十进制带千分位逗号（`1,234,567`）；三 / 四 / 八 / 十二 / 二十 / 三十六 / 六十进制等长串按每 3 位空格分组（`10 201`），二进制按 4 位一组（与十六位对齐），只为减少数位数。
- **范围**：进制限 2–36（digit 表 0–9A–Z）。越界项在函数内被**静默跳过**而非抛错，符合本层"永不失败"约定。

> 注意：`render_bases` 把负数显示为带符号的「-二进制 / -三进制」，是符号-绝对值展示，不是补码。要做补码请用 `explain --width N`。

| 汉明(7,4) | 16 个码字 × 7 个单比特错 | 全部纠正回原数据 | Hamming 1950 |

> 关于 Internet 校验和的一个常见误记：RFC 1071 例子里的 `0xDDF2` 是**反码和**，
> 真正填进头部的校验和是它的反码 `0x220D`。接收端把含校验字段的整段重新求和
> 应得 `0xFFFF`；若把校验字段的字节序写反（`0d 22`），这个性质就不成立了——
> 本层提供 `internet_checksum_verify()` 专门验这一点。

## 5. 诚实边界

- **x86-64 是结构化拆解器，不是完整反汇编器。** 它输出前缀 / REX / opcode / ModRM /
  SIB / 位移 / 立即数这些字段，助记符是启发式提示（函数名就叫 `mnemonic_hint`）。
  完整语义请查 Intel SDM Vol.2 Appendix A 或 AMD APM。
- **Java 反汇编是"够用的教学级"。** 覆盖 0x00–0xC9 的操作数长度，遇到未收录操作码
  会明确停止并指出偏移，不会静默跳过。
- **Python 字节码与解释器版本强相关。** 3.11+ 会出现 `RESUME`、`CACHE`、自适应前缀等
  特殊项（PEP 659），属正常现象。
- **CRC 是六参数位运算模型**（宽度/多项式/初值/输入反转/输出反转/异或输出），
  慢但和协议文档一一对应；正确性由 8 个内置变种的标准 check 值 + `zlib.crc32` 交叉校验保证。
- **逻辑化简的最小覆盖**：先取必要质蕴涵项，剩余部分在候选项 ≤ 16 时穷举最优解，
  否则退化为贪心并在结果里标注"不保证全局最小"。
