## 三、逐组件：更新接口 + 安全更新

### 3.1 sysweeper（本体）

**当前状态**
- 源码版本 `0.6.67`（`system-optimizer/src/python/sysweeper/__init__.py` 与 `pyproject.toml` 一致）。
- `dist/` 下发布物为 `sysweeper-0.5.22-py3-none-any.whl` / `.pyz` / `.tar.gz`——**落后源码 2 个次版本**。
- 历史文档（如 `编程语言编年…md` 附项）曾记 `0.6.37`——亦已落后。

**更新接口（如何发布/同步）**
1. 改版本号只在一处：`pyproject.toml` 的 `version`，由 `__init__.__version__` 读取（单一事实源，勿双写）。
2. 构建并产出三件套：
   ```bash
   cd system-optimizer
   python -m build            # wheel + sdist
   python -m zipapp -c -p "/usr/bin/env python3" src/python/sysweeper -o dist/sysweeper-<ver>.pyz
   ```
3. 同步 `dist/` 三个文件版本号到 `0.6.67`（或新版本），并跑 `scripts/audit_standards_eol.py` 与全量测试。

**安全更新**
- 本体为**本地只读/运维工具**，无网络监听面；主要风险在**依赖供应链**：
  - 发布前 `pip-audit` / `uv pip compile --upgrade` 刷新 `requirements`（待核实：当前是否锁定 hash）。
  - `.pyz` 自包含，分发时附 SHA-256（参照 supermium 做法，本仓库尚未附，建议补）。
- 无已知 CVE 直指 sysweeper；**最高优先级修复是消除 `dist` 与源码的版本漂移**，避免用户装到旧构建。

### 3.2 mihomo（clash-meta 内核，K8s 透明代理网关）

**当前状态（来自 `imports/mihomo-kubernetes/`）**
- `mihomo-deployment.yaml` 钉 `image: metacubex/mihomo:Alpha` + `imagePullPolicy: IfNotPresent`——**浮动标签**，每次节点拉取可能拿到不同构建。
- `securityContext.privileged: true` + `capabilities: [NET_ADMIN]`——**特权过宽**（privileged 已隐含所有 capability）。
- README 自述长期运行有**内存泄漏**（GitHub issue MetaCubeX/mihomo#405），用每日 cronjob 重启兜底。

**上游最新（检索日 2026-10-20）**
- 稳定线约 `v1.19.30`；Winget 已发布 `1.19.20`/`1.19.25`。
- `v1.19.25` 变更含 **`fix: CVE-2026-39825 for net/http`**（真实 CVE 修复）。`待核实`：该 CVE 具体影响面与 CVSS。

**更新接口（如何升级/重钉）**
1. **固定版本标签**，弃用 `:Alpha`：
   ```yaml
   image: metacubex/mihomo:v1.19.30     # 或经测试的固定 tag；禁止 :Alpha / :latest
   imagePullPolicy: IfNotPresent
   ```
2. **收敛特权**（去掉 `privileged`，仅留必要 capability + 只读根）：
   ```yaml
   securityContext:
     readOnlyRootFilesystem: true
     capabilities:
       add: ["NET_ADMIN"]
     # 删除 privileged: true
   ```
3. 升级后回归：TPROXY 端口（7893）、mixed-port（7890）、API（9999）、DNS 重定向（1053）连通性；参数变更见 `mihomo-iptables.yaml`。

**安全更新**
- **必须升级到 ≥ `v1.19.25`** 以纳入 `CVE-2026-39825`（net/http）修复；优先稳定版而非 Alpha。
- 内存泄漏（#405）属上游已知问题：固定版本 + 每日 cronjob 重启可缓解，但**应跟进上游是否已在新稳定版修复**，再决定是否保留 cronjob。
- 供应链：镜像从 `metacubex/mihomo` 官方仓库拉取，记录 digest（`@sha256:...`）进一步锁版；CI 内对部署清单做 `kubeconform`/`conftest` 校验，禁止 `privileged: true`。

### 3.3 outline-sdk（网络抗干扰 SDK）

**当前状态（来自 `imports/outline-sdk/go.mod`）**
- `module github.com/Jigsaw-Code/outline-sdk`（**旧路径**）。
- `go 1.25.0` / `toolchain go1.25.5`；关键依赖：`golang.org/x/crypto v0.41.0`、`golang.org/x/net v0.43.0`、`golang.org/x/sys v0.35.0`、`go-shadowsocks2 v0.1.5`、`go-tun2socks v1.16.11`。

**上游最新（检索日 2026-10-20）**
- **模块路径已迁移**：`github.com/Jigsaw-Code/outline-sdk` → `golang.getoutline.org/sdk`（及 `.../sdk/x`）。旧路径已**弃用，不再接收任何更新**——这是最高优先级问题。
- 新路径下根模块 `v0.0.21-alpha.1`、x 模块 `v0.1.0`（libraries.io/pkg.go.dev）。

**更新接口（如何迁移/升级）**
1. **改模块路径**（阻断失更的根因）：
   ```bash
   go mod edit -module golang.getoutline.org/sdk     # 若本仓即 SDK 消费方需同步
   # 消费方：把 import 批量从 github.com/Jigsaw-Code/outline-sdk 改为 golang.getoutline.org/sdk
   go get golang.getoutline.org/sdk@latest
   go get golang.getoutline.org/sdk/x@latest
   go mod tidy
   ```
2. 升级 Go 工具链到仓库声明的 `go1.25.5` 对应稳定版，跑 `go vet` + `staticcheck`（go.mod 已含 `honnef.co/go/tools`）。
3. 刷新 `golang.org/x/*` 到最新补丁，规避已知 crypto/net 公告。

**安全更新**
- **路径迁移本身即安全更新**：留在弃用路径 = 永久收不到上游安全补丁。
- `golang.org/x/crypto`、`golang.org/x/net` 是密码学/传输核心，订阅 [Go 安全公告](https://groups.google.com/g/golang-announce) 与 `govulncheck` 扫描：
  ```bash
  go install golang.org/x/vuln/cmd/govulncheck@latest
  govulncheck ./...
  ```
- Shadowsocks 传输（`transport/shadowsocks`）依赖 `x/crypto` 的 AEAD；确认所用流式加密在最新 `x/crypto` 下无弃用警告。

### 3.4 Supermium for Windows 2000（遗留系统浏览器）

**当前状态（来自 `imports/windows-2000-supermium/README.md`）**
- 基于 Supermium `v144-r5` / Chromium `144.0.7559.256` / 上游 commit `0cdb6d9aa53c`。
- 提供完整资产 SHA-256（zip/exe + 证书包），完整性校验到位。
- 原生运行于 Windows 2000 SP4，**不需 One-Core-API / 扩展内核 / `--no-sandbox`**；启用 legacy Chromium 沙箱。

**上游最新（检索日 2026-10-20）**
- 官方最新 `Release 144.0.7559.256 R5`（supermium.net，约 3 个月前）——**本仓库钉的就是该版，版本未落后**。
- `待核实`：Chromium 144 之后是否有 145+ 安全累积补丁；supermium.net 提及「144 LTS 补丁后音频问题」已在后续构建修复。

**更新接口（如何跟进）**
1. 关注 `supermium.net` 与上游 `win32ss/supermium` Release；本 fork 是**版本锁定 + 二进制补丁链**，每 bump 上游需：
   - 重审补丁偏移（`README` 明确：offsets must be re-audited for every future Supermium version）；
   - 重新生成并**替换资产 SHA-256 表**（保持完整性可验证）。
2. 证书包随根证书轮转更新：随 Windows 2000 Legacy Update 与 Mozilla 根证书包同步。

**安全更新**
- 浏览器直接面对网页，**攻击面最大**：必须跟踪 Chromium 安全公告（[chromium-googlesource issues](https://issues.chromium.org/) / [CVE Mitre CVE-2026-*](https://cve.mitre.org/)）。
- 坚持**不用 `--no-sandbox`**（本 fork 已原生启用 legacy 沙箱，是正确加固）；若被迫降级沙箱即引入严重风险。
- 完整性：**每次更新都校验 README 内 SHA-256**，拒绝哈希不匹配的资产。
- 遗留系统额外面：Windows 2000 自身无安全更新，依赖 Legacy Update 打全 post-SP4 补丁 + 现代根证书包；这两步是 Supermium 安全运行的前提。

## 四、全局安全与供应链建议

1. **禁止浮动镜像标签**：mihomo 由 `:Alpha` 改固定 tag + digest；所有部署清单纳入 CI 校验。
2. **收敛特权**：mihomo Deployment 去掉 `privileged: true`，仅 `NET_ADMIN`；只读根文件系统。
3. **消除模块路径弃用**：outline-sdk 迁移到 `golang.getoutline.org/sdk`，否则永久失更。
4. **统一版本真相**：sysweeper `dist/` 与文档版本对齐源码 `0.6.67`，发布物附 SHA-256。
5. **自动化漏洞扫描**：Go 侧 `govulncheck`；Python 侧 `pip-audit`；镜像侧 `trivy`/digest 锁版。
6. **诚实标注**：本表所有「待核实」项（具体 CVE CVSS、Chromium 144 之后补丁、dist hash 锁定状态）需在下次联网复核时回填，不臆造。

## 五、与概念系统整体指导的呼应

本仓库的「整体指导」为 **因果记录·全息·感应**（见 `concepts/daoxue_taxonomy.json` `_meta.overall_guidance`）。版本追踪的安全纪律与之同构：

- **因果**：版本漂移/浮动标签会在「因」上引入不可复现，升级须可溯源（固定 tag + digest + SHA-256）。
- **记录**：每次更新的 `from→to` 版本、CVE 修复、偏移重审都应写入变更记录（本文件即其一）。
- **感应**：一个组件失更（如 outline-sdk 旧路径）会沿依赖「感应」到整机安全态势——故需组网式整体盯版，而非单点。
