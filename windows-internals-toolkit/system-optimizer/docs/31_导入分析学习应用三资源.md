## 二、概念映射与落地明细

### netsys（网络与组网）—— 新增 9 模块 + 6 条出边
Linux 7.3 八个内核特性 + ios-sweet 的 USB 以太网链路，按既有四轴登记为只读诊断/调优模块：
`sched_ext`、`failfs`、`fchroot`、`binfmt_bpf`、`userfaultfd`、`fuse_io_uring`、`rwf_dontcache`、`nullfs_kthread`、`usb-net`。
模块总数 29 → 38。每个模块带 `redline`（只读登记、不挂载/不调用/不改策略）。

netsys 原先是「只进不出」的汇点（无 `bridges`）。本轮加入桥接发射机制（BRIDGES + 目标池校验 + `--check`），让其成为双向可达，并给弱连接系统补确凿入边：

| netsys 出边 | 目标 | 关系 | 含义 |
|---|---|---|---|
| sched_ext | comp:opt | 运行时调度优化 | BPF cgroup 子调度器 ≈ 可热插拔优化 pass |
| sched_ext | plang:lang:c | 调度程序语言 | eBPF 即受限 C 子集 |
| binfmt_bpf | plang:lang:c | 产物加载语言 | BPF 程序经 LLVM 后端编译进内核 |
| failfs | comp:artifact-container | 隔离语义类比 | 丢弃 fs 状态 ↔ 容器最小暴露面 |
| fchroot | apilab:stdio | fd 锚定接口纪律 | fchroot(2) 以 fd 换根避免路径重解析，与 stdio 长连接同纪律 |
| userfaultfd | comp:opt | 工作集即优化面 | 冷页淘汰属内存侧「按事实优化」 |

### comp（编译与工具链）—— 新增 3 概念
`mlir`（多级 IR 基建，桥接 llvm:tool:mlir / plang:model:ir）、`kernel-fusion`（算子融合，桥接 plang:model:ir）、`bpf-binfmt`（BPF 驱动 binfmt，桥接 plang:lang:c）。
概念总数 50 → 53。每个概念带 `engineering`（真落地/未落地如实写）。

### apilab（接口 API）—— 新增 3 概念
`c-abi`（稳定 C ABI，桥接 plang:lang:c）、`guile-ffi`（GNU Guile 一等语言 FFI，桥接 plang:lang:c）、`fchroot-syscall`（fchroot(2)，桥接 netsys:module:fchroot）。
概念总数 32 → 35。

### plang（编程语言）—— 经桥接增强（不直接增语言条目）
本轮不新增 plang 语言条目（避免 161 语言清单漂移）；但通过 netsys/comp/apilab 的 `lang:c` 桥接，plang 入边 +2（sched_ext、binfmt_bpf、bpf-binfmt 中的 lang:c）。

## 四、诚实边界（未落地 / 待核实）

- **ios-sweet 的 XNU/Mach-O/Swift/Objective-C 语言条目**：未写入 plang（161 语言清单需逐条 probe 才登记，本轮不臆造），仅在工程落法中作为「可复现 CI 构建」思路引用。
- **SonicBoom 的 CUDA / Guile(Scheme) / MLIR 作为 plang 语言条目**：同理未新增，仅在 comp/apilab 概念中以「桥接 lang:c」口径登记其接口基座；如需成为独立语言条目，须走 plang probe 流程。
- **Linux_7.3 的 cgroup 调度权重方法（up/max/concur/tasks）、single runqueue**：属调度实现细节，本轮仅在 sched_ext 模块 `detail` 中提及，未单列概念。
- **failfs 与 nullfs 的「进程彻底丢弃 fs 状态」语义**：仅作隔离类比桥接到 comp:artifact-container，未声称本仓库使用该机制。
