## 1. 四仓导入矩阵（弱网实况如实记录）

沙箱网络条件下采用多通道降级策略（git 直连 → codeload tarball → GitHub tree API →
raw.githubusercontent.com → WebFetch），四个仓库两种结局：

| 仓库 | 体量 | 通道与实况 | 产出 |
|------|------|-----------|------|
| **to-alan/HarmonyOSInstallGMS** | 小 | git clone 直连成功（1m10s） | 实战命令序列、Pitfall、社区源清单 |
| **Zitann/HarmonyOS-Haps** | 小 | git clone 直连成功（2m13s） | apps.yaml 557 行 110 款应用兼容矩阵（多端 60 / 手机平板 42 / 电脑 8） |
| **fenwii/OpenHarmony** | 765 MB | git clone **两次断流**（fetch-pack 意外中断）→ codeload tarball 只拿到 14 字节假文件（**默认分支是 master 不是 main**）→ 降级为 README raw 全文 634 行 + GitHub API 仓库元数据 | 里程碑年表、仓库分层架构、社区发行版谱系 |
| **huaweicodelabs/harmonyos-codelabs** | 124 MB | tarball 单流断在 29 M/124 M（exit 56）→ 降级为 **tree API 全量文件树**（1.5 MB JSON，53 个 demo）+ raw 抽样关键文档 | demo 图谱、FA 范式实证、构建块清单 |

> 如实说明：fenwii 与 codelabs 两个仓库**未取得完整源码**，分析基于全量文件树 +
> README 全文 + raw 抽样 + GitHub API 元数据。结构性结论（目录分层、demo 清单、
> 里程碑）可靠；逐文件深读未覆盖。知识条目一律以官方文档为主源、社区内容标
> `needs_verify`。

## 2. 核心洞察：FA / Stage 双边范式对照系

跨仓库对照得出本轮最有价值的发现（`fa_stage_evolution` 条目）：

| 维度 | FA 模型（API 4-6） | Stage 模型（API 7+） |
|------|-------------------|---------------------|
| 工程配置 | config.json（页面/权限分列） | module.json5（模块化声明） |
| 组件 | pageAbility / serviceAbility | UIAbility / ExtensionAbility |
| 视图 | hml + css（类 HTML 标签） | ArkUI（声明式 TS 扩展语法） |
| 能力判定 | 无（按文档约定） | `canIUse()` 运行期 + `@ohos.*` SystemCapability 分层 |
| 实证来源 | codelabs 旧 demo（53 个中大量仍为 FA） | Haps 生态应用（110 款中主流为 Stage） |

**两个仓库互为年代的实证**：codelabs 与 Haps 正好分别落在范式演进的两端，构成完整
对照系——这正是「触类旁通」方法的落地：不同仓库的同一个概念面互相校准。

## 3. 回灌产物（分层清单）

### 3.1 gmsstd 既有知识库补强（11 → 15 条）

`data/gmsstd_standards.json` +5 条，全部来自 InstallGMS 实战与算例，均标 `needs_verify`：

- `gms_packages_map`——三件套分层：gsf（账号）/ gms（服务）/ vending（商店），
  「GMS 不可用」的排障先分清代管域
- `harmonyos_gms_deploy`——版本边界：仅 HarmonyOS 4.x（AOSP 兼容层）可行，
  NEXT 不支持；老机型（2019-05 前）Go 安装器直接原生装
- `microg_fallback`——MicroG 跳板方案（microG Services Core + 新版 Play 商店 MOD）
- `fcm_push_keepalive`——FCM 连接保活（进度拖到 50% 再禁 gsf，保证 FCM 通）
- `adb_multi_user_control`——多用户按 user 维度诊断（`pm list users` →
  `disable-user --user <id>`），Play 弹窗误报时先分用户不误伤主用户

`native/gmsstd.py` GMS_CHECKS 同步 11 → 15 项（包名分层 / FCM 保活 / 多用户处置 /
版本边界），每项回链知识库 key。
