# 42+1 量子存储交换子系统（qstore）—— v0.6.77

> 用户需求原文：「保持量子架构，文件系统使用 ext4 并且默认 4K 对齐，除使用 CPU 方式缓存外，
> 还可使用 GPU/NPU/TPU/CAN 等进行交互，且按照程序要求进行硬盘储存读取扫描索引等，
> 使用 GPU/NPU/TPU/CAN 进行缓冲，转换硬盘可接受的数列进行储存读取扫描索引等，
> 使用量子架构支持的数字逻辑矩阵进行进制转换。」
>
> **探查结论：这五件事在 v0.6.69 建的量子架构基座里已经全有对应物**——因此不重写量子层，
> 只新建「存储域消费者」`qstore` 读取并驱动它。

## 1. 需求 → 基座对应

| 需求 | 基座既有对应 | 位置 |
|---|---|---|
| 端点交互 | `cpu` 经典寄存器 + `define_pin/set_pin/read_pin` 针脚 | `native/quantum.py` |
| 缓冲 | `PiLink` 环形缓冲（`ceil(ratio·π)` = 7 槽，有 overwrites 计数） | 同上 |
| 进制转换 | `enc k` → 置换矩阵 Π_k（按 k 置 1 位复合 X 门），`decode_number()` 测量还原 | 同上 |
| 不间断交换 | `step()` 每条指令必入链；`run_until_halt(max_steps=4096)` 护栏 | 同上 |
| 硬盘可接受数列 | 经典层：字节流 → 12 位重组 → 4096 进制（=4K 粒度）数列 | 新增 `qstore` |

## 2. 落地只读能力（native/qstore.py，六段报告）

| 报告 | 内容 | 只读来源 |
|---|---|---|
| `endpoint_probe_report` | GPU（/sys/class/drm + lspci 0x03）/ NPU（/dev/accel/* + 0x12）/ TPU（/dev/apex_* + Coral 1ac1:）/ CAN（/sys/class/net/can*）存在性 | sysfs/dev/lspci |
| `alignment_report` | ext4/4K 对齐逐设备判定，三级降级 sysfs→lsblk→statvfs；`alignment_offset` 缺失按 0 | sysfs 优先 |
| `radix_report` | Π_k 保真往返（复位→编码→解码→校验）+ 翻转语义陷阱对照 + 4K 数列打包 | 量子基座 |
| `pipeline_report` | 分块→端点 req/ack 握手→量子转换→4096 打包；全量历史自累积；PiLink 利用率 | 量子基座 |
| `qstore_report` | 四段聚合 + `_SELF_POSITION` 红线声明 | — |
| `capabilities_report` | 端点表/知识回链/红线自检 | — |

端点建模：每端点占 **2 个经典位 req/ack 握手**，4 端点 × 2 位恰好占满 `n_classical=8`；
量子寄存器 `n_qubits=8`（字节宽 Π_k 编码），与经典寄存器解耦（`MAX_QUBITS=20` 上限内）。

## 3. 两条已核实的技术契约（测试锁住）

1. **enc 是翻转语义**：从 `|0…0>` 编码 k 得 `|k>`，但紧接着编码 j 会得到 `|k⊕j>`
   （实测 202→77 不复位得 135=202⊕77）。逐数字编码前必须 `load()` 复位——
   `load()` 重建 StateVector 归零且不清 pins/link，正合长管线需要。
2. **`decode_number()` 真实坍缩态矢量**：解码后同样依赖复位。
   **`snapshot()` 只回最近 7 条**（deque maxlen）：全量历史必须自己累积 step 级记录。

## 4. 诚实边界与红线

- 量子部分是**可逆编码与管线仿真**，不是真的把 GPU/NPU 变成磁盘加速器；
- 端点只做存在性只读探测，绝不加载驱动/提交计算/开 CAN 套接字发帧；
- 写盘/格式化/分区命令（mkfs.ext4/dd/wipefs/sgdisk/parted）**只以文本建议出现**，
  绝不进入执行路径；源码无任何进程执行/网络/动态链接设施；
- 不改 `quantum.py` 任何语义（其 import 白名单与 `quantum_*` 任务数有断言守着）。
