## 3. 量子物理语义层（arch/quantum/kernel/quantum-energy.c）

把「量子物理特性/量子效应/能量激发态」落成内核侧**可编译运行的记账模型**（ℏ=1 虚构普朗克单位，只读自报 `/proc/quantum-energy`）：

| 量子概念 | 内核落法 |
|---|---|
| 离散能级 | `E_n = n×ΔE`（`CONFIG_QUANTUM_ENERGY_STEP=16`，4 个激发态） |
| 叠加与布居 | 每 CPU 每级一个 16.16 定点布居权重，基态 3/4、激发态均分余量 |
| 相位演化 | `φ_n(t) = E_n·t`，空闲期按步推进 |
| 干涉 | `2·w_a·w_b·cos(φ_a−φ_b)`（256 项定点 sin 表 + 线性插值，2^30 定标） |
| 测量/坍缩 | 中断到达即测量：argmax 布居归一、坍缩到确定能级（Bell 对关联记账） |
| 退相干 | T1（激发布居 1/8 漏向基态）/ T2（相干度每 tick 减半） |
| 能级跃迁 | 电偶极型选择定则 `|Δn|=1` 允许，越级记 forbidden；激发吸能、弛豫放能 |
| 虚拟光子 | 弛豫时 `quantum_link_push()` 把 ΔE 事件推进 PiLink 环形缓冲 |
| 纠缠 | Bell 对登记 + 自旋锁下关联簿记 |

空闲路径经 `kernel/sched/idle.c` 弱符号钩子接入：`arch_cpu_idle_enter()`（向基态弛豫一步、放能入链）→ `arch_cpu_idle()`（相位推进 + 节流退相干 + 模式切换）→ `arch_cpu_idle_exit()`（中断=测量→坍缩→激发到运行级）。

## 4. idle= 启动参数（GRUB / LILO）

`early_param("idle", ...)` 解析，三态：**`mwait`（默认，基态等待）**、`poll`（cpu_idle_poll_ctrl + cpu_relax 忙等）、`halt`（最深停机态，模拟语义同 mwait）。
x86 官方已删除 `idle=mwait` 取值（deprecated）但 6.18.57 参数仍然可用——quantum 架构显式保留该语义。

- `arch/quantum/boot/grub.cfg`：GRUB2 `linux /boot/vmlinux-6.18.57-quantum root=/dev/sda1 ro idle=mwait`（另有 `idle=poll` 条目）；
- `arch/quantum/boot/lilo.conf`：LILO `append = "idle=mwait"`（另有 `idle=poll` 映像）。

诚实口径：quantum 是宿主模拟架构，没有真实引导镜像格式（无 bzImage/Image 引导协议），两份配置是**内核命令行契约的参考样例**——bootloader 经命令行把 `idle=mwait` 送进 `arch/quantum` 的空闲路径。

## 6. 诚实边界与红线

- **纯只读**：qarch 绝不执行内核构建、绝不写内核树任何文件、绝不加载内核模块；构建结论只读自树的文件存在性与产物（`build/.config`、`build/vmlinux` 字节数）；
- **不虚报**：vmlinux 已链接是事实，「能在量子处理器上运行」不可达也是事实——两者都必须如实呈现（测试锁住这条边界不回退）；
- 内核内新增代码全部 **GPL-2.0**（内核树纪律），与本仓 MIT 是分发与被分发关系，互不传染；
- 后续可延展项：向 arch/um 级完整宿主模拟推进（需 os-Linux 层与 syscall 透传）、QPU 设备用户态 round-trip 测试。

## 8. 研究架构定位：纯新增、有意留桩、EOL 分支适配

本架构的定位与边界，按用户口径明确如下，避免误读为「借量子的名义补当前架构」：

### 8.1 量子是「架构」，不是对当前架构的修正
- `ARCH=quantum` 是 Linux 内核里一个**真实可编译的新增架构**（`arch/quantum/` 整目录新增），对**另外 21 个既有架构目录零改动**，仅在 `drivers/Kconfig`、`drivers/Makefile`、`Documentation/index.rst` 三处做**纯追加注册**（见 §1 纯新增实证）；
- 各 LTS 补丁（`patches/0001-quantum-architecture-v1-<ver>.patch`）对旧分支的改动，全部是**量子架构自身的端口适配**——例如 `copy_thread`/`elf_core`/`set_pte_at`/`__pte_free_tlb`/`vm_get_page_prot→arch_vm_get_page_prot` 等，是量子按目标内核的 arch 钩子契约提供自己的实现，而不是去「修」通用代码；
- 因此「应用量子」的要点始终是**把这个架构落稳**，而非拿它当遮羞布去补旧内核的洞。

### 8.2 有些能力「无法完善」才是正确的（实验室 / 大厂 R&D 语境）
量子架构作为**研究架构**，以下能力**有意留作桩或声明为记账语义**，这本身就是诚实且正确的状态，不应被强行补全成生产级：

| 能力 | 现状 | 为什么「留桩」是对的 |
|---|---|---|
| gcc 后端 / 真实量子处理器 | 无；vmlinux 是**宿主工具链诚实编译的宿主机器码**（arch/um 同型宿主模拟） | 量子处理器没有 gcc 后端是硬事实，不虚报「能在量子处理器上跑」 |
| 可引导镜像格式 | 无 bzImage/Image 引导协议 | 模拟架构无真实引导硬件；GRUB/LILO 配置只是**命令行契约样例** |
| FPU / `dump_fpu` | `dump_fpu()` **桩返回 0**（无浮点状态可落盘） | 模拟架构无 FPU；`return 0` 是诚实声明，不是缺漏 |
| 能量模型 | 量子力学启发的**记账语义**（`/proc/quantum-energy`，ℏ=1 虚构单位） | 不是物理测量，是内核侧可运行的可视化模型 |
| 显示 / `screen_info` | 符号恒零 | 无真实显示硬件 |
| 真实 QPU | 由 `drivers/quantum/` 以**协处理器子系统**呈现（Π_k 门 / 8q 寄存器 / PiLink） | 宿主侧模拟，非硅上量子里程 |

### 8.3 EOL 旧分支（5.15 / 5.10）：链接限制已解除（三处版本面适配）
- 5.15 / 5.10 是**已 EOL 的古老分支**，其通用代码对 arch 钩子的要求与 6.x 差异极大。历史状态（v0.6.79 及以前）：补丁与 defconfig 就绪，但整树链接 vmlinux 失败，作为已知限制记录在案。
- **本轮（2026-10-25）已逐根因解除**，全部为「量子按目标内核的 arch 钩子契约提供自己的实现」的版本面适配，不触碰通用代码、不构成对当前架构的修改：

| # | 断点 | 根因（逐版查据） | 适配（落点：gen_version_patch.py） |
|---|---|---|---|
| 1 | `multiple definition of quantum_start`（5.15/5.10） | ≤5.15 顶层 Makefile `KBUILD_VMLINUX_OBJS := $(head-y) $(core-y→built-in.a)`，head.o 经 **head-y 与 obj-y 双路**入链；6.1+ 起顶层改为只链 `./built-in.a` 单聚合，head.o 必须留在 obj-y 方能进聚合（旧文档「链接器去重」说法不确，实为顶层 Makefile 组成变化） | `arch/quantum/kernel/Makefile`：obj-y 去掉 `head.o`（`extra-y` 仍构建它，经 head-y 单链；x86/arm64 同款约定） |
| 2 | `undefined reference to pm_power_off`（5.15/5.10） | 6.1+ `kernel/reboot.c` 自带 `__weak (*pm_power_off)` 定义；5.15/5.10 仅 `extern` 声明，须 arch 提供 | `arch/quantum/kernel/process.c` 追加 `void (*pm_power_off)(void);`（NULL = 模拟架构无真实关机硬件；arm64 同款落点） |
| 3 | `undefined reference to trap_init`（仅 5.10） | 5.15 起 `init/main.c` 有 `__weak trap_init`；5.10 无，`start_kernel` 直接调用 | `arch/quantum/kernel/traps.c` 追加 `void __init trap_init(void) {}` 空桩（x86 同款落点；模拟架构无真实陷阱初始化动作） |

- 另两项历史记录点本轮复核结论：`screen_info` 源码早已自备（`arch/quantum/kernel/screen_info.c`，`obj-$(CONFIG_VGA_CONSOLE)` 条件编译，符号恒零）；5.10 uaccess 重定义由生成器「不选 `GENERIC_STRNCPY_FROM_USER`/`GENERIC_STRNLEN_USER`、走 asm-generic 内联」规避（见文档 46 适配表）。
- **受支持的构建目标（2026-10-25 实测，全部三层验收通过）**：Linux **6.18.57**（基线）+ LTS **6.12 / 6.6 / 6.1 / 5.15 / 5.10** **六个版本均真实链接出 `vmlinux`**，`quantum_*` 导出符号各 27 个（见文档 46 验收矩阵）。
- 诚实边界不变：vmlinux 是宿主工具链编译的宿主机器码；无 gcc 量子后端、无可引导镜像格式、能量模型为记账语义——这些是研究架构的诚实声明，与「能否链接」是两个维度的问题。
