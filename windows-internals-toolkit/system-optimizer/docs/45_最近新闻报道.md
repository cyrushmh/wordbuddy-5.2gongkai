## 1. 头条：Linux 7.3 发布（2026-10-18）——史上最重发行，AI 辅助成「新常态」

Linus Torvalds 于 2026-10-18 按计划发布 Linux 7.3（七个 RC 之后），各项规模数据创历史纪录 [1][2]：

| 指标 | 数值 | 口径 |
|---|---|---|
| 非合并提交 | **18,765** | 超过 6.7（2024-01，17,284，其中 bcachefs 历史并入占近 3,000）成新纪录 [1] |
| 贡献开发者 | 3,021 人 | 其中 807 名为首次贡献者 [1][2] |
| 合并窗口提交 | 15,267 | 史上第二繁忙，仅次于 6.7；Torvalds 归因之一是 AMD 显卡代码约占 1/3 [2] |
| 下一版 | 7.4 合并窗 10-19 开启，预计 2026-12 发布；LTS 归属（7.3 还是 7.4）未定 [3] | — |

### 1.1 特性清单中与本仓库 netsys 概念层直接对应的五项

| 7.3 特性 | 内核面事实 | netsys 概念模块（只读登记） |
|---|---|---|
| **failfs** 伪文件系统 + **fchroot(2)** | failfs 上一切操作返回 EOPNOTSUPP；作者 Christian Brauner——进程把根/当前目录置入 failfs 后无法再解析任何绝对路径，必须依赖预先打开的文件描述符，沙箱语义 [3][4] | `failfs`（伪文件系统沙箱）+ `fchroot`（fd 锚定换根） |
| **sched_ext cgroup 子调度器**补齐 | 每个 cgroup 可有自己的 BPF 任务调度器；group scheduling 重新设计，四种权重分配方法面向多核机器 [3][4] | `sched_ext`（BPF cgroup 子调度器） |
| **binfmt_misc 扩展（BPF 驱动）** | binfmt_misc 扩展进入主线 [2] | `binfmt_bpf`（binfmt_misc 的 BPF 驱动处理器） |
| **VRAM 压力处理**（dmem cgroup 生效） | Valve 工程师 Natalie Vock 贡献：显存吃紧时内核优先从「未保护」应用逐出数据到 GTT 系统内存，护住活跃负载 [3][4] | `distcompute` / 图形诊断域可引用 |
| **userfaultfd**（既有机制持续使用） | 7.3 周期无破坏性变更；仍是工作集跟踪的标准接口 | `userfaultfd`（工作集跟踪） |

其余值得记录的：ext4 并行直接 I/O 写入 + iomap 新简化路径（测试负载 1.92→2.19 M IOPS）；Btrfs 直接 I/O 达理论吞吐约 95%（此前 50%）；ntfs3 替代数据流；ksmbd 可选 Apple Time Machine 扩展与按共享区 SMB3 加密；EFS/FreeVxFS 支持移除；Apple M3 Pro/Max/Ultra 初步主线启动支持；2026 Steam Controller 驱动；AMD Zen 6 平台管理准备（HSMP v7）；Intel Xe3P（Nova Lake）图形转正 [3][4]。

### 1.2 AI 辅助开发的「新常态」——一条必须如实呈现的线

- Torvalds 7.2-rc7 时称「lots of fixes … coming from code review by various AI tools」的「new normal」；网络子系统维护者 Jakub Kicinski 在合并请求里直言「We are completely overwhelmed」[3]。
- **Torvalds 本人用 Claude Code 写的 page-cache 补丁系列（分支 `noref-filemap-read-with-llm`）并未合入 7.3**：代码、测试、问题清单与描述初稿由 Claude Code 在其指导下产出。合成基准下 8 补丁版在其笔记本上约 3×（10M→30–33M 次读/秒），rcu-free-v3 十补丁版在 64 线程 Threadripper 上约 23×（13.3M→304M 次读/秒）；但 Kiryl Shutsemau 发现 `filemap_read_rcu_batch()` 竞态，且 Torvalds 自述真实负载收益会小得多、RCU 宽限期内存滞留是设计最弱处 [2]。
- Maintainers Summit 决定取消标识 AI 参与的「Assisted-by」标签 [3]。

> 对本仓库的意义：`webnews` 模块的抽取管线（RSS/网页→优化知识点）应把「AI 辅助内核补丁的审查状态」作为一等字段——**合成基准数字与合入状态必须分开记**，这正是本文书 1.2 节的处理方式。

## 3. 量子计算：纠错路线图提速，「megaquop」临门一脚

### 3.1 Quantinuum：单逻辑比特 5 errors/million（预印本，2026-10-19）

Quantinuum 在官网与 arXiv 贴出论文（arXiv:2610.24077，Lavasani 等），报告 98 量子比特 trapped-ion 机 **Helios** 上的纠错结果 [6][7]：

| 指标 | 数值 | 备注 |
|---|---|---|
| 逻辑保真度 | **99.9995%**（每百万操作约 5 次错误） | 世界纪录；较其 9 月纪录低 10×，较 Google 超导最好公布结果低约 100× [7] |
| 逻辑比特构成 | 每个逻辑比特最多 **37 个物理比特**（色码） | 上一代 Helix 码为 10 个 [7] |
| 纠错抑制因子 λ | **≈10** | Google 2024（Nature）约为 2；λ 越大，达到目标错误率所需物理比特越少 [6] |
| 规模口径 | **仅单个逻辑比特** | megaquop（百万次可靠操作）预计需 50–100 个逻辑比特协同；论文为**预印本，未经同行评审** [6][7] |
| 路线图 | Sol（2027）/ Apollo（2029，通用容错） | CEO Rajeeb Hazra：同一商用硬件上换码（Helix→色码）连降错误率 [7] |

背景锚点：Helios 2025-11-05 上线、98 个 Ba-137 离子、all-to-all 连接、2Q 门 99.921%（Nature 2026-06-17）；Quantinuum 2026-06 Nasdaq 上市（QNT），Q2-2026 营收 $8M、FY 指引 $28–32M [6][7]。

### 3.2 IBM：BB 码距离分析夯实 Starling 路线

- 路线图：Gross [[144,12,12]] → **Kookaburra（2026）**；Two-Gross [[288,12,18]] → **Starling（2028/2029，200 逻辑比特、1 亿门）** [8]；
- 2024 Nature：288 物理比特上 12 个逻辑比特稳定运行约百万周期（p=0.1%，阈值 0.7%）[8]；
- arXiv:2609.39395（2026-09-30，Rowshan & Devitt）：BB 码距离分析，论证 d=4/6/10/10/12/18 的距离序列可行 [8]。

### 3.3 Google：两篇 10 月新论文压纠错开销

| 论文 | 日期 | 要点 |
|---|---|---|
| arXiv:2610.03682「Low-Overhead QEC with Boundary-Connected Planar Modules」 | 2026-10-02 | 模块化双曲表面码/色码，k/n=1/16、d≥22 超过 [[288,12,18]]；较表面码 >30× 开销削减；automorphism walking 电路 [9] |

> 对本仓库（qarch）的意义：这些进展印证 doc 44 的口径——**内核侧 quantum 架构是宿主模拟的记账模型**（量子处理器没有 gcc 后端是硬事实）；真实硬件的纠错路线越清晰，「能级/叠加/退相干」语义在内核里作为可编译记账模型的价值越明确，但两者不能混为一谈。

## 6. netsys 概念层接线（只读）

| 模块 | 新闻触发 | 接线动作 |
|---|---|---|
| `sched_ext` | 7.3 子调度器补齐 | 登记「每 cgroup 独立 BPF 调度器」能力位 |
| `failfs` / `fchroot` | 7.3 新文件系统 + 新系统调用 | 成对登记（fd 锚定语义互为补充） |
| `binfmt_bpf` | binfmt_misc BPF 扩展 | 能力位登记 |
| `userfaultfd` | 持续机制 | 维持既有登记 |
| `tls13` / `cert` | PQC 迁移时间表 | 增列 PQC 就绪度只读维度 |

红线不变：所有 netsys 模块**只读登记、不加载调度器、不改配置、不写 BPF 程序**；新闻只进知识层（`webnews` 缓存 + 概念 taxonomy），不进执行路径。

## 7. 诚实边界与来源

- **预印本≠同行评审**：Quantinuum megaquop 论文（arXiv:2610.24077）为预印本；IBM BB 码分析与 Google 两篇同为 arXiv 预印本；
- **草案≠标准**：IEEE P7130 止步 D14，正式发布目标 2027-01；
- **未合入≠已发布**：Torvalds 的 Claude Code page-cache 系列有竞态未解决，不在 7.3 内；其 3×/23× 数字来自不同补丁版本与不同硬件，不可混用；
- **短期版≠LTS**：Ubuntu 26.10 支持至 2027-07；生产服务器仍应跟随各发行版 LTS 内核的安全回流；
- 量子硬件时间线（Sol 2027 / Apollo 2029 / Starling 2028–2029）均为公司路线图口径，非承诺。
