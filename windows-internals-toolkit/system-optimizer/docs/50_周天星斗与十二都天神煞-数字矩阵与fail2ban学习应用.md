## 1. 两大阵法的指导理念（总纲）

> **道法自然 · 活在当下 · 只有生存才能发展 · 在发展中能更好的生存 · 发展生存，如此循环，亦复如是。**

| 理念 | 周天星斗大阵（冗余数据） | 十二都天神煞大阵（fail2ban 学习） |
|---|---|---|
| 道法自然 | 只读观测不妄为——顺应冗余数据的自然分布，只记录星斗方位与体量，不强行改造一寸磁盘 | 响应顺应攻击的自然节律——阈值分级、退避递进，不一刀切、不骤然绝杀 |
| 活在当下 | 立足当下实际环境——此刻有什么缓存才统计什么，没有就跳过，不虚构、不假设 | 本机装了 fail2ban 才解析其配置，没有就降级为模式学习，不虚构战果 |
| 只有生存才能发展 | denylist（个人数据与关键资产）是系统生存的根基，清理永不涉足——**生存优先于发展** | 先设 ignoreip 白名单防误封——把自己封在门外是生存事故，**生存优先于防护** |
| 在发展中能更好的生存 | 清掉可再生冗余腾出空间与性能，反哺系统更好地存续 | 分级封禁与累犯升级提升安全，反哺系统更好地存续 |
| 如此循环，亦复如是 | 观测 → 清理 → 再观测，每一轮都比上一轮更清明 | 观测 → 响应 → 再观测，每一轮防御都比上一轮更精准 |

五大句是一个环：**生存**是环的底座（没有生存一切免谈），**发展**是环的动力
（不发展则生存质量停滞），循环上升、亦复如是——这正是「原路返回」的哲学根基：
顺应系统本来的状态，读一遍、还回去，不留下不该留下的痕迹。

## 2. 周天星斗大阵 · 数字矩阵冗余数据（matrix）

### 2.1 概念

数字量子无法实体，散落全盘的**冗余数据**成为星斗：缓存、临时目录、包管理器缓存、
回收站、日志轮转——它们可再生、可再生成，如满天星斗散布一周。本子系统只读
观测其分布与体量，**绝不触碰任何一颗「星」**。

### 2.2 生存红线：allowlist 与 denylist

| 面 | 内容 | 语义 |
|---|---|---|
| allowlist（可再生产） | `~/.cache`、`/tmp`、`/var/tmp`、`/var/cache`、apt/pacman/dnf/yum 缓存、`~/.local/share/Trash`、`/var/log` | 只读统计存在性与体积 |
| denylist（生存根基） | `~/.ssh`、`~/.gnupg`、`~/.password-store`、`~/.netrc`、`~/.aws`、`~/.kube`、`~/.docker`、`~/Documents`、`~/Downloads`、浏览器 profile、`/etc/ssl/private`、`/etc/pki` 等 20 项 | **完全不扫描、不统计、不清理** |

- allowlist 与 denylist 展开后**必须无交集**（`check_exclusive()` 模块加载即校验，相交即拒绝工作，测试强制）；
- 体积统计**不跟随符号链接**（防软链越界到 denylist 的诡计）、不读取任何文件内容；
- 深度/条目超上限即截断——宁少算，不拖死扫描（道法自然：不为难系统）；
- 构建产物目录（node_modules/target 等）语义上可再生，但位于用户项目目录内、误伤风险高，
  **只作文本指引，不进扫描面**。

### 2.3 原路返回

清理建议仅以文本交还用户（先用只读报告确认、用包管理器自带接口、回收站先确认、
日志交给 logrotate/journalctl），由用户沿原路执行——本子系统不删除、不移动、不改写任何数据。

### 2.4 落点

| 层 | 文件 | 内容 |
|---|---|---|
| 权威源 | `data/matrix_refs.json` | allowlist/denylist/分类/指引/合规声明 |
| native | `native/matrix.py` | 只读扫描（`scan`/`dir_size`/`check_exclusive`）、报告、环境概览 |
| tasks | `tasks/matrix.py` | `matrix_report`（只读观测）、`matrix_reclaim_guidance`（规范指引） |
| CLI | `sysweeper matrix [--env ...]` | 端到端只读观测 |
| GUI | 「周天星斗大阵」面板 | 维度选择 + 只读报告 |
| 测试 | `tests/test_matrix.py`（16 项） | schema/红线/扫描语义/理念/无写调用/四入口 |

## 3. 十二都天神煞大阵 · fail2ban 学习应用（f2b）

### 3.1 概念

fail2ban 以单一守护进程统观全部日志源、按规则集中响应，如**十二都天神煞**环绕一周、
周遍防御（「十二」取周遍之义：每接入一个受监控服务就如添一尊神煞，十二乃至更多）。
本仓库学习其架构模式与分级响应思想，落为**只读咨询**。

### 3.2 许可证边界：引入分析学习，不 vendored

fail2ban 为 **GPL-2.0（强拷贝左）**项目。本仓库的纪律：

- **不 vendored 其源代码**（本仓库宽松许可，强拷贝左不得进入源码，`scripts/check_repo_guard.py` 强制）；
- 只引用官方源（fail2ban.org / github.com/fail2ban/fail2ban / readthedocs）并在
  `data/f2b_refs.json` 显式登记；
- 所有模式总结均为**本仓库原创表述**（六层模式：jail/filter/action/threshold/daemon/client），
  非其文档译文。

学习不等于打包，引用不等于拷贝。

### 3.3 模式学习（都天神煞的布阵之道）

| 层 | 模式 | 教训 |
|---|---|---|
| jail | 日志源+过滤器+动作+阈值绑定为可命名监控单元 | 响应策略按服务维度封装，而非散落规则堆 |
| filter | failregex 刻画失败模式 + ignoreregex 白名单 | 任何自动响应都须内置「不误伤」视角 |
| action | 响应动作可组合（action_ 链式），与触发解耦 | 触发与响应分层，可分级升级 |
| threshold | maxretry/findtime/bantime 三元组，bantime 可递增 | 响应强度按事实分级，永久封禁是最粗暴下策 |
| daemon | server 常驻统一观测 + sqlite3 持久化 | 集中观测须有持久记忆，重启不丢 |
| client | status/get 只读与 set 写操作两类命令面 | 读写分权：只读可开放，写须显式可审计 |

### 3.4 原路返回

- 配置建议（SSH 基础防护/白名单防误封/累犯分级升级）**仅以文本**交还用户，
  是否写入 `/etc/fail2ban/jail.local` 由用户决定；
- 只读探测安装状态、只读解析 jail.local/jail.d；对 `fail2ban-client` **仅调用白名单
  只读子命令**（status/version/get），写操作子命令一律不碰；
- 未安装则降级为模式学习，**不虚构战果**（活在当下）。

### 3.5 落点

| 层 | 文件 | 内容 |
|---|---|---|
| 权威源 | `data/f2b_refs.json` | 官方源/GPL-2.0 边界/六层模式/常见 jail/咨询模板 |
| native | `native/f2b.py` | 探测/ini 只读解析/模式学习/只读咨询 |
| tasks | `tasks/f2b.py` | `f2b_report`（只读咨询）、`f2b_jail_guidance`（规范指引） |
| CLI | `sysweeper f2b [--env ...]` | 端到端只读咨询 |
| GUI | 「十二都天神煞大阵」面板 | 模板选择 + 只读报告 |
| 测试 | `tests/test_f2b.py`（15 项） | schema/许可证边界/ini 解析/降级/红线/四入口 |
