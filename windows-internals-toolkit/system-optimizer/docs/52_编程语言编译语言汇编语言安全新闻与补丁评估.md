## 2. 头条：eMudhra 中间 CA 事件（2026-10-17 ~ 10-21）——本月跨全部语言生态的最大补丁

### 2.1 事件本身

- **根因**：eMudhra（eMudhra Inc.，证书颁发机构）2025-04-30 的一次密钥仪式存在 wrap/unwrap 缺陷，导致其下 **P-384 私钥仅约 3–8 bit 熵**（理论上可被暴力还原）[1][2]。
- **受损面**：8 张中间 CA 证书——EM DV/EV/OV TLS CA G3B、G3C 三张 TLS 签发 CA + 2 张 OV 代码签名 CA 等 [1][2]。
- **拦截**：Mozilla 于 2026-10-17 三小时内在 OneCRL 完成拦截（含 intermediate distrust）；各浏览器与信任库跟进 [1][2]。
- **在野利用**：截至 2026-10-21 **未观测到**利用受损证书的公开报告 [1][2]（标注：这是「未观测」而非「不存在」）。

### 2.2 跨语言响应一览（这是本新闻对「编程语言」最直接的冲击面）

| 语言 / 生态 | 响应 | 补丁性质 |
|---|---|---|
| **Go** | 1.27.3 / 1.26.10 加急发布，CVE-2026-111943：`crypto/x509` 硬编码 8 个受损 CA 的 SPKI SHA-256 列表 [3] | **必须重编译**——重装 Go 工具链或重打依赖后重新 `go build`，否则运行期仍信任受损 CA |
| **OpenJDK** | 10-21 周期外发布，CVE-2026-91403（`javax.net.ssl`，CVSS 9.1），影响 27.0.1 / 25.0.5 / 21.0.13 / 17.0.21 / 11.0.33 / 8u512 及更早 [4] | standalone JDK 替换 `blocked.certs`（JDK 8 为 `blacklisted.certs`）或启用吊销检查；发行版 JDK 跟系统证书包（FreeBSD / Homebrew 例外需单独处理）[4] |
| **Python** | 10-21 加急 3.15.1 / 3.14.9 / 3.13.17；pip 26.2.2 + certifi 2026.10.19 [5] | 换解释器 / 升级 certifi 即生效 |
| **Node.js** | 三线 `ca-cert` 依赖更新（随 10-21 安全发布）[6] | 换运行时即生效 |
| **Rust** | `webpki-roots` 1.0.10 [7]（二手核实） | 改依赖版本 + 重编译 |
| **Debian** | DSA-6572-1 / DLA-4845-1 [7]（二手核实） | 发行版证书包 |
| **Firefox / NSS** | Firefox 158.0.1 / NSS 3.131.1 [7]（二手核实） | 信任库本体 |

> **对本仓库的意义（comp 概念系统新增概念的种子）**：eMudhra 事件把「补丁响应时钟」的
> 语言差异暴露得前所未有地清晰——解释型语言换运行时即生效，编译型语言必须**重编译
> 部署**才生效。Go 的 CVE-2026-111943 是教科书级案例：安全公告写得明白，但开发者
> 只是 `go install golang.org/x/tools/...@latest` 而不重编主程序，等于没打。

## 6. 工具链本体：LLVM / binutils(GAS) / GCC / Rust

### 6.1 LLVM [11][12]

- **23.1.4** 于 2026-10-20 发布（当前 llvm_docs.json 在册为 0.6.42 时代的 23.1.x 线，changelog 随 v0.6.86 增补）。
- **CVE-2026-27144**（2026-04-08 公布，CVSS 7.1 高）：memmove 指针解包致**运行期内存损坏**，有修复 [11]。
- CVE-2026-13573 / CVE-2026-13574：影响 llvm-project ≤22.1.6；**项目方口径为「超出文档化安全范围」**——与第三方评估存在口径分歧，如实记录为 `needs_verify`，不据此要求本仓动作 [12]。
- 对本仓库：`research/llvm/` 交叉编译研究面 + `llvm_docs.json` 知识层；23.1.4 为发布线更新登记。

### 6.2 binutils / GAS（汇编语言工具链——对应用户「汇编语言」关切）[13][14]

CVE 一串，均修于 **binutils 2.48**（本机 2.42 不在受影响面）：

| CVE | 组件 | 要点 | 修复状态 |
|---|---|---|---|
| CVE-2026-91781 | `elf_x86_64_common_section_index` | 空指针（patch 7322e9bc） | 已修于 2.48 [13] |
| CVE-2026-90803 | `ld` `elf_x86_64_relocate_section` | **堆溢出**（patch 471130b） | 已修于 2.48 [13] |
| CVE-2026-90829 | `bfd_elf_set_group_contents` | SHT_GROUP 空指针，公开 PoC | **尚无确认修复** → needs_verify [13] |
| CVE-2026-18220 | DLX 后端 `dlx_rtype_to_howto` | 越界写 → FSOP 任意代码执行演示（Red Hat CNA 评 7.8） | 仅 `--enable-targets=all` 构建可利用 [14] |

> 对本仓库：**汇编语言子系统（asm）的安全教训**——处理不可信输入的目标文件时，
> `objcopy`/`ld` 本身就是攻击面。sysweaver 的 asm 任务层只做只读探测（`as --version`、
> 版本面登记），不解析不可信二进制，风险面结构性收敛。

### 6.3 GCC [15]

- **CVE-2026-102010**：libstdc++ `__gnu_pbds` binary_heap_tag `erase_if` UAF（AISLE Research + Red Hat；GCC bug 127656；Debian tracker 显示 gcc-11..16 仍 open）。
- 对本仓库：`src/` 无 C++ 代码使用 PBDS；登记到 comp 概念系统即可。

### 6.4 Rust [7][16]

- **rustc 类型检查器漏洞藏近 11 年**：可溯 Rust 1.4（2015）——违反内存安全的代码仍可编译通过；高优先级，修复提案审查中。**二手报道，needs_verify**（未读到 rustsec / 官方公告原文）。
- RUSTSEC-2026-0368（2026-10-17）：`zip` 9.0.0 修 `ZipArchive::extract` 符号链接逃逸。
- CVE-2026-41677：rust-openssl PEM 回调越界读（<0.10.78，仅 OpenSSL 1.x；NVD 评 9.1 vs 项目自评 Low——口径分歧如实记录）。
- Rust 1.100 停止 32 位 Windows 主机工具。
- Cargo 新增全职受资助维护者（AWS 出资）——供应链维护能力新闻。
- 对本仓库：Rust 版 PE 查看器位于 `Windows/` 侧研究代码；不引入 zip  crate 即无该 advisory 面。
