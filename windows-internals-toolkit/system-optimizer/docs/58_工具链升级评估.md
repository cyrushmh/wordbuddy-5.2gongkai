> 配套 `toolchain_catalog.json` 的 `version_freshness.needs_action`（2026-10-24 联网核实）。
> 数据真相源：catalog 的 `needs_action` 11 条；评估口径：docs/52《编程语言编译语言汇编语言安全新闻与补丁评估》九项评估表。
>
> **本文档性质**：**只评估、不执行**。toolchain 子系统红线（与全工具一致）——
> 只探测与编目，绝不安装 / 卸载 / 构建 / 下载。下文「升级路径」是给人看的**逻辑顺序**，
> 不是自动执行队列；是否升级、何时升级由宿主持有者决策（见各条「责任归属」）。
>
> 维度定义：
> - **优先级**：`应升`（有命中 CVE / 已 EOL，建议升）· `可选`（有新线但非紧急）· `无动作`（CVE 不命中本机面 / 随发行版钉死）· `宿主持有者责任`（本仓无法代决，登记等待）。
> - **随发行版滚动**：Ubuntu 24.04 钉住的宿主（gcc / clang / binutils / ruby 等），发行版发新点后自然获得，无需手工。
> - **补丁响应时钟**（comp bringup 域 `toolchain-security-response`）：解释型（Python / Node / Deno / OpenJDK 换运行时即生效）vs 编译型（Go / Rust / C 必须重编译部署）。

## 1 · OpenJDK 20（应升 · 已 EOL · 宿主持有者责任）

- **风险**：20（2023-03-21）已退出支持窗口，无公开安全补丁；`tasks/jdk.py` 把解释器版本作为一等字段登记。
- **升级路径（逻辑顺序，非自动）**：
  1. 评估升 LTS 21.0.13（保守）或现行 LTS 25.0.5（支持至 2030-09）；
  2. 复核本仓 Java 实现 `Windows/src/java/peinfo` 与 `parity_test.py` 的 `java` 后端在新 JDK 下一致；
  3. 切换 `/usr/lib/jvm` 默认 + `JAVA_HOME`，重跑 parity_test 跨语言一致性。
- **优先级**：应升（但本仓无 Java 生产负载，属宿主持有者责任，登记等待）。
- **是否随发行版滚动**：Ubuntu 24.04 默认 `openjdk-21-jdk` 已在源，切换即获，无需手工追上游。
- **验收口径**：`java -version` 显示 21/25；`python3 Windows/src/python/parity_test.py` 的 java 后端逐字段一致。

## 2 · Node.js 22.13.1（应升 · 含 10 项 CVE）

- **风险**：22.23.4 含 Brotli 越界写 RCE 等 10 项 CVE（docs/52 头条评估）；`novel-website` 直接以 `node server.js` / `node publish.js` 运行，属解释型——换运行时即生效。
- **升级路径（逻辑顺序）**：
  1. `node` 升 22.23.4（同 22.x 大版本，ABI 稳定，无需改 `package.json`）；
  2. `npm audit` 复核依赖树；
  3. 重跑 `node server.js` + `node publish.js` 冒烟；
  4. `novel-website/package.json` 的 `version` 与 CalVer 口径（`2026.10.24`）不变。
- **优先级**：应升（本仓 novel-website 构建前升级，docs/52 九项评估表已定性）。
- **是否随发行版滚动**：否（Ubuntu 24.04 的 `nodejs` 是 20.x，需 NodeSource 或 `nvm` 取 22.23.4）。
- **验收口径**：`node -v` == 22.23.4；站点本地起站 + publish 冒烟通过；`npm audit` 无高危。

## 6 · Rust 1.93.0（可选 · 稳定线升级）

- **风险**：上游 1.99.0（2026-10-01），1.98.1 次新；本仓 `classics-rs` 依赖 Rust，编译型——升级需 `cargo build` 重编产物。
- **升级路径（逻辑顺序）**：
  1. `rustup update stable` 到 1.99.x；
  2. `cargo build --release --offline` 重编 classics-rs（离线优先纪律保持）；

- **优先级**：可选（稳定线，非安全紧急）。
- **是否随发行版滚动**：否（rustup 自管，非 apt）。
- **验收口径**：`rustc --version` 1.99.x；`cargo metadata` 离线版本一致；wasm 产物三端口齐。

## 12 · 红线与责任边界（贯穿评估）

- **本文档不触发任何宿主变更**：升级动作的「是否 / 何时 / 由谁」由**宿主持有者**决定；toolchain 子系统只探测与编目。
- **明确动作项仅 2 个**：Node（#2，本仓 novel-website 构建前必升）、OpenJDK（#1，持有者责任登记）。
- **其余 9 项为「观察 + 随滚」**：Ubuntu 24.04 钉死的（GCC/Clang/binutils/Qt/Python 等）随发行版点发自然获得；rustup / NDK / OHOS SDK 自管的按 §6–§8 路径择机升级。
- **交叉链独立性**：NDK/OHOS 自带 clang，不受宿主 LLVM 18 版本影响；升级评估不影响已交叉实证的 Android×3 / OHOS×1 成果。
