## 四、三仓可学习点（仅笔记，不新增概念）

### 4.1 CF-Workers-TGProxy —— 边缘无后端代理 + 多 lane 并发模型

- **传输层透传**：Worker 解开客户端 MTProto 的 64 字节 obfuscation 头（AES-CTR 重签），内层 mtp 载荷端到端加密，Worker 不接触、不做 mtp 加解密。对照本仓：native 只读层同样「只登记事实、不替你执行」——代理只搬运字节，信任边界在客户端。
- **多 lane 替代 Durable Object**：每条 Telegram 流 = 一条独立 WebSocket（`tproxy-lane-v1.<token>.<sid>`），全部 lane 落在同一 isolate，session/lease 为 isolate 内 `Map`；单会话上限 128 lane。避免了 DO 单线程 + 固定实例路由的排队瓶颈。可对照本仓「单 isolate 承载多会话」的资源模型思维，但本仓当前无边缘代理工程面，仅作架构范式记录。
- **小包汇聚 + 严格 CSP + 禁 WS 压缩**：上行 upPack=20KB、下行 dnPack=32KB/dnMs=1ms 削减高频小 frame 调度成本；页面 `frame-ancestors http://127.0.0.1:*` 限制嵌入源；握手显式清空 `Sec-WebSocket-Extensions`（高熵数据压缩是负优化）。

### 4.2 is-rust-gui-ready —— Rust GUI 选型参照（印证 classics-rs 选 egui）

- 清单把 Rust GUI 分五档：**Stable**（gtk/gtk4/FLTK/wxDragon/native-windows-gui/cacao）、**Desktop-first**（slint/egui/cushy/rosin/xilem/wabou/gpui/iced/mirui/agg-gui/Ribir/Floem/vizia/Freya/winio）、**Webview-based**（tauri/dioxus/sciter/async-ui）、**Web Apps**（leptos/MoonZoon/sycamore）、**Other**（imgui/libui-ng/rinf/flutter_rust_bridge）。
- 最成熟跨平台工具包：**flutter / React Native / Kotlin Multiplatform / slint**（含 Hot Reload / Live Reload / a11y 对照）。
- 印证：本仓 classics-rs 的 `peview-egui`（PE 查看器的 Rust GUI 半身）选用 **egui**，而 egui 在该清单中 Cross/Mobile/Web/a11y 全标 Yes，落在成熟梯队——本仓选型与社区成熟度判断一致。清单「unmaintained 不入册」的排除纪律，同构本仓「不臆造、只登实测」。

### 4.3 dsh-our-free-model —— 插件化协议适配 + 省 Token（LLM 客户端范式）

- **三协议归一**：OpenAI Chat Completions / Responses + Anthropic Messages + SSE，由 `src/stream.js` 解码归一、`src/forward.js` 独立 OpenAI 兼容监听器承接。对照本仓 comp 概念系统「协议适配」桥接思路——多上游协议收敛到统一内部表示。
- **免密上游网关**：opencode / kilo 公开免密额度，插件不含任何密钥；聚合 76 家提供商注册表（`providers/registry.json`）。对照本仓「免密 / 自托管优先」的工具链纪律（零第三方依赖是结构性防线）。
- **省 Token（RTK）**：请求发出前就地重写 `tool_result`（git diff/status/log、grep、find、ls、tree、构建日志等），实测 40KB `git diff` 移除 90% 字节，对全部车道生效。这是「省上下文」的工程化范例，可对照本仓日志/产物体积纪律。
- **安全基线**：Ed25519 发布签名（信任根 pin 公钥）+ AES-256-GCM 凭据密文（密钥三片掩码分片即时派生，明文不落盘）+ SHA-256 逐文件校验 + 0600 权限文件。对照本仓「凭据不落盘、权限收紧」的红线。
