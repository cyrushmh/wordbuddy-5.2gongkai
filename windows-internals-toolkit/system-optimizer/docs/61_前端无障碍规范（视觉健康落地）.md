# 61 · 前端无障碍规范（视觉健康落地）

## 一、范围与定位

| 项 | 说明 |
|----|------|
| 适用 | 本仓所有**自研前端产物**（单文件静态页、Deno/TS 报告查看器、GUI 面板等）的视觉健康与无障碍基线 |
| 不覆盖 | 显示器硬件、灯具蓝光危害、屈光不正/青光眼/白内障临床管理——见 §八诚实边界与 docs/60 |
| 与 docs/60 关系 | docs/60 是「查据」（标准来源与量化阈值）；本规范是「契约」（本仓必须怎么做、如何验收）。查据以 docs/60 为准 |
| 已落地范本 | `system-optimizer/concept_gui.html`（由 `tools/gen_concept_gui.py` 生成）：双主题变量 / 开关 / 减动效 / 非颜色编码均已在其中验证，本规范以其为参考实现 |

## 二、双主题 CSS 变量契约（强制）

所有前端产物**必须**以 CSS 自定义属性声明双主题，禁止硬编码颜色。范本变量（concept_gui.html，已实测达标）：

```css
:root{ color-scheme:dark;
  --bg:#0f1216; --bg2:#161b22; --bg3:#1c232c;
  --line:#2a323d; --line-strong:#646c78;
  --fg:#d8dee6; --dim:#8b97a6;
  --acc:#4a9eff; --ok:#3fb950; --warn:#d29922; --bad:#f85149;
  --dao:#d4af37; --shen:#9d6cff; --ren:#3fb950; }
:root[data-theme="light"]{ color-scheme:light;
  --bg:#f4f6f9; --bg2:#ffffff; --bg3:#e7ebf0;
  --line:#d3dae3; --line-strong:#7c8490;
  --fg:#1a2230; --dim:#5a6573;
  --acc:#1b6fd6; --ok:#1a7f37; --warn:#8a6300; --bad:#c0392b;
  --dao:#9a7d12; --shen:#6d3fd6; --ren:#1a7f37; }
@media (prefers-color-scheme: light){
  :root:not([data-theme]){ /* 系统偏好初值，与 light 同值，不再重复列 */ }
}
```

契约要点：
- **暗色为默认**（`:root` 无 `data-theme` 即 dark），但**必须**提供浅色等效选项——散光用户在亮底暗字下更清晰（docs/60 §五·1），故不主张暗色「更护眼」。
- `color-scheme` 必须声明 `dark light`，使 UA 原生控件/滚动条/表单配色同步。
- 浅色可由**系统偏好**（`@media prefers-color-scheme`）或**手动覆盖**（`[data-theme="light"]`）启用，手动覆盖优先于系统偏好。

## 三、主题切换开关组件规范（强制，ARIA switch）

任何主题切换控件**必须**是真正的 switch，不得用 checkbox 或裸 button 冒充：

| 项 | 契约 |
|----|------|
| 角色 | `<button role="switch" aria-checked="true|false" aria-label="深色模式">` |
| 状态语义 | `aria-checked="true"` = 当前为深色；`false` = 当前为浅色。标签恒定，不随状态改写文字 |
| 键盘 | Space / Enter 切换；焦点须可见（不移除 outline） |
| 持久化 | 选择写入 `localStorage`（键如 `concept-gui-theme`），下次访问由早期脚本读取 |
| 防首屏闪烁（FOUC） | `<head>` 内**早期脚本**（位于 CSS 之前）同步读取 localStorage 并 `documentElement.setAttribute("data-theme", …)`，避免浅色用户首屏闪暗 |

参考实现（concept_gui.html）：

```html
<meta name="color-scheme" content="dark light">
<script>try{var t=localStorage.getItem("concept-gui-theme");if(t==="light"||t==="dark"){document.documentElement.setAttribute("data-theme",t);}}catch(e){}</script>
<button id="themeSwitch" type="button" role="switch" aria-checked="true" aria-label="深色模式"><span class="ts-thumb"></span></button>
```

```js
const sw=document.getElementById("themeSwitch"), root=document.documentElement;
function sync(){ sw.setAttribute("aria-checked", root.getAttribute("data-theme")==="light"?"false":"true"); }
sw.addEventListener("click",()=>{
  const goLight=root.getAttribute("data-theme")!=="light";
  root.setAttribute("data-theme",goLight?"light":"dark");
  try{ localStorage.setItem("concept-gui-theme",goLight?"light":"dark"); }catch(e){}
  sync();
});
sync();
```

## 四、减动效规范（强制，prefers-reduced-motion）

| 项 | 契约 |
|----|------|
| 触发 | `@media (prefers-reduced-motion: reduce)` |
| 必须停用 | 所有装饰性动画（流光/呼吸/循环）、过渡（transition）、自动播放 |
| 例外 | 必要的信息性状态变化（如焦点指示）可保留，但不得有位移/缩放类动效 |
| 前庭安全 | 旋转、大幅位移、视差类动效在 reduce 下必须归零 |

范本（concept_gui.html）：reduce 下 `.edge.hot{animation:none;stroke-dasharray:none}` 与 `.ts-thumb{transition:none}`。

### 4.1 闪烁 / 光敏癫痫硬约束（强制，WCAG 2.3.1）

除「减动效」外，本仓前端**必须**遵守 **WCAG 2.3.1（Level A，Three Flashes or Below Threshold）** 对闪烁的硬约束——这是光敏性癫痫（photosensitive epilepsy）防护的 Web 内容层落点，与「圆光术」视觉范式（光、辉光、呼吸式光晕）直接相关，故明确纳入前端契约与验收清单，不得因「装饰光效好看」而破界。

| 项 | 契约 |
|----|------|
| 频率上限 | 任何内容在 **任意 1 秒内不得闪烁超过 3 次**（three flashes）；满足下方阈值者除外 |
| 一般闪光阈值（General Flash Threshold） | 闪烁峰值亮度 **≤ 20.0 cd/m²**（对 0.1° 视角内、相对面积 ≥25% 的区域组合判定） |
| 红色闪光阈值（Red Flash Threshold） | 更严，红色闪烁峰值亮度 **≤ 6.0 cd/m²**（红闪阈值独立于一般阈值，单独卡控） |
| 充分条件（技术 G19） | 把任何组件闪光控制在 **≤3 次/秒** 且每次闪光满足上两阈值 → 即满足 2.3.1，可免逐帧 PEAT 实测 |
| 检测工具 | **PEAT**（Photosensitive Epilepsy Analysis Tool，Trace R&D）可逐帧分析视频/动画的闪频与亮度，判定是否触发阈值；本仓静态页以「≤3 闪/秒 + 无红闪超阈」为设计基线，不引入需 PEAT 复核的高频光效 |
| AAA 红线（2.3.2） | **完全禁止任何闪烁**（Level AAA，无任何例外）；本仓不采用「允许用户关闪烁」之外的折中，纯装饰光效默认低于 3 闪/秒且可随 `prefers-reduced-motion` 归零 |

契约要点：
- 「闪烁」按 WCAG 定义：相对亮度在 10% 以上的对立变化（亮→暗或暗→亮）即计一次闪光；光晕/呼吸式亮度脉动若频率 >3 次/秒即触发 2.3.1。
- 「圆光术」视觉范式中的辉光、呼吸、流光等**设计为低频**（≤3 次/秒）且随 `prefers-reduced-motion: reduce` 归零，默认不出现红闪超限。
- 本约束与 §四主表「减动效」互补：减动效针对前庭/舒适，2.3.1 针对光敏性癫痫安全，二者独立卡控，缺一不可。

## 五、非颜色编码规范（强制，SC 1.4.1）

| 项 | 契约 |
|----|------|
| 禁止 | 单靠颜色区分状态、类别、数据（色觉缺陷患病率：北欧裔男性 ≈8%、女性 ≈0.4%） |
| 必须附加 | 字形（○●◆▽ 等）、形状、文本标签、图案或亮度差中**至少一种**非颜色维度 |
| 数据可视化 | 系列区分用形状/纹理/标签 + 颜色（颜色为增强，非唯一编码） |

范本（concept_gui.html）：九系统节点用「字形 + 文本标签 + 形状」三重区分，色板仅作增强。

## 六、对比度验收阈值（强制，实测为准）

所有文本/图形对比度**必须**经 sRGB 相对亮度公式 `(L1+0.05)/(L2+0.05)` 实测，不得目测或四舍五入过关。范本实测（已独立复算，与 docs/60 一致）：

| 指标 | dark | light | WCAG 阈值 | 结论 |
|------|------|-------|-----------|------|
| 正文 `--fg` vs `--bg` | 13.9:1 | 14.8:1 | SC 1.4.3 ≥4.5 / SC 1.4.6 AAA ≥7 | 超 AAA |
| `--dim` vs 实际落面（`--bg2`/`--bg`） | 5.8:1 | 5.5:1 | SC 1.4.3 ≥4.5 | 达标 |
| `--acc` vs 实际落面（`--bg2`） | 6.3:1 | 4.9:1 | SC 1.4.11 非文本 ≥3 | 达标 |
| `--line-strong` vs `--bg` | 3.5:1 | 3.5:1 | SC 1.4.11 ≥3 | 达标 |

验收口径：
- 正文 ≥4.5:1（AA）；高对比基线目标 ≥7:1（AAA，本页已达，可作全仓高对比基线）。
- 大字（≥18pt 或 ≥14pt 粗体）、UI 边界 ≥3:1。
- 功能性图形对象（矩阵单元格、开关轨道等）理解所需部分 ≥3:1（不四舍五入）。

> 注：`--dim` / `--acc` 按实际渲染落面（`--bg2` 卡片面 / `--bg` 页底）测量；正文与 `--line-strong` 按 `--bg` 测量。改色板后须重新逐对计算，不得沿用旧值。

## 七、缩放 / 回流 / 文字间距（标注，SC 1.4.4 / 1.4.10 / 1.4.12）

| 项 | 契约 | 本仓现状 |
|----|------|---------|
| SC 1.4.4 缩放 | 文本可放大至 200% 不失内容/功能；不得用脚本阻止 UA 缩放 | 依赖浏览器整页缩放；SVG 矢量放大不丢清晰 |
| SC 1.4.10 回流 | 320×256 CSS px 无二维滚动；表格/图形/地图/演示等二维布局**例外** | 拓扑图为固定 SVG 画布（图形），属 WCAG 对 graphics 的例外，**如实标注** |
| SC 1.4.12 文字间距 | 行高≥1.5、段距≥2、字距≥0.12、词距≥0.16 × 字号，调大不失真 | 文本型内容应支持；图形内嵌文字不强制 |

诚实标注：固定画布/图形类产物不必重排，但须在页面标注此例外，不得谎称满足回流。

## 八、诚实边界（不冒充，红线）

1. **散光 = 深色模式护眼反例**：暗底亮字更模糊，亮底暗字更清晰 → 本仓**保留浅色主题**，不主张暗色「更护眼」。
2. **青光眼/白内障 → 对比敏感度下降 → 高对比需求**（SC 1.4.3/1.4.6）；其临床管理（眼压控制、角膜、手术）**不属** Web 前端职责。
3. **弱视/低视力 ≠ 色盲**：低视力靠放大 + 高对比（SC 1.4.4/1.4.10/1.4.12），色盲靠非颜色编码（SC 1.4.1），分别处理，不可混为一谈。
4. **真「护眼」= 符合 ISO 9241 的亮度/对比/眩光控制 + WCAG 对比度 + 支持缩放 + 减少动效/频闪**——皆本仓已落地的 Web 内容层；暗色模式只是可选手段之一，不是充分条件。
5. **IEC 62471 / IEC-TR 62778 蓝光危害（RG0–RG3）是灯具/显示硬件标准，非 Web 内容标准**：软件暗色模式仅降整体像素亮度、间接减蓝光发射，**不是「护眼」保证**，不得在文案中宣称。
6. **本仓前端当前无音视频 / 自动播放音频（呼应 docs/63 §六 opt-in ③）**：concept_gui.html 与 report_viewer 均为纯静态视觉产物，不含 `<audio>/<video>`、无自动发声、无需要字幕/转录的时基媒体 → WCAG **1.2.x（时基媒体）、1.4.2（音频控制）、1.4.7（低/无背景音频）暂不适用**，留作契约基线。若未来引入任何音视频或自动音频，必须按 1.2.x / 1.4.2 / 1.4.7 做媒体无障碍改造（字幕/文本转录、可暂停的音频控制、背景音频较前景 ≤20 dB 且可关闭），并补入 §九接入清单与 PR 前自检；本仓不主动引入听觉媒体，避免凭空新增无障碍负债。
