## 三、分主题学习笔记

### 3.1 rohit267/net-merge —— 多出口聚合的极简分发

- **问题定位**：单条网络出口会随 Wi-Fi 抖动、蜂窝切换、网卡故障而中断或降速；多出口设备（笔记本 Wi-Fi + 蜂窝、台式多网卡）的带宽/可用性未被聚合利用。net-merge 把多条出口聚合成单一高可用/高带宽连接（类 Speedify 的多路径聚合）。
- **分发形态**：macOS/Linux 一行安装（`curl -fsSL …/install.sh | sh`）；Windows 走 PowerShell；macOS 真正启用需 `sudo net-merge install` 一次性授权（安装系统级网络钩子/服务）。
- **可复用纪律（仅纪律层面）**：① **一行安装 + 一次性授权**的极简分发 ↔ 本仓 release 工件（deb/压缩包/多架构二进制）即装即用；② **多出口聚合的故障转移/带宽叠加**思路 ↔ 本仓 netsys 网络诊断概念同域，但本仓无聚合 client counterpart，不落地。

### 3.2 jeessy2/ddns-go —— 多提供商抽象 + Web 自管的轻量守护

- **问题定位**：家庭/小企业宽带多为动态公网 IP，域名解析需随 IP 变动自动更新；不同 DNS 提供商接口各异。
- **技术要点**：统一抽象多数提供商（阿里云/腾讯云/Cloudflare/DNSPod/华为云/Google Domain 等）+ 部分路由器；自带 Web 管理界面；Docker + 各平台二进制分发；IP 变动事件驱动更新。
- **可复用纪律**：① **多提供商适配层 + 自托管 Web** 的零依赖形态 ↔ 本仓 Python 只读层 + Deno console 自托管查看器同构；② **事件驱动复检**（IP 变动触发）↔ 本仓探针「变动复检」纪律。

### 3.3 charmbracelet/bubbletea —— 消息驱动的不可变状态机范式

- **范式**：基于 The Elm Architecture——`Model`（状态）+ `Update(msg)`（纯函数返回新 Model + 命令）+ `View`（渲染）；消息驱动、状态不可变、副作用（I/O）显式建模为 Command。charm 生态（gum/soft-serve/glow/lazygit 等）广泛采用。
- **可复用纪律**：① **纯函数 update 的幂等可重放** ↔ 本仓只读报告 `--check` 幂等纪律同构；② **框架与业务分离**（Model/Update/View 解耦）→ 本仓 native（只读消费）/ tasks（任务层）/ registry（接线）分层同构。本仓无 TUI 框架 counterpart，不落地。

### 3.4 libressl.org（LibreSSL）—— 安全事件驱动的分支与精简审计面

- **起源**：OpenBSD 项目于 2014 年 Heartbleed 后从 OpenSSL 分出安全导向分支，目标代码精简、可审计、可移植（OpenBSD/Linux/macOS/Windows）。
