## 三、分主题学习笔记

### 3.1 直链解析：本地"翻译官"式适配层

- **原理（多篇文章一致）**：LinkSwift 本质是浏览器里的本地解析脚本——用户选中网盘文件后，脚本在本地调用各网盘**公开 API** 端点，把文件 ID / 认证头打包发过去，换回一条真实直链；再交给 Aria2/IDM 等下载器多线程拉取。它**不走破解路径**（不突破任何技术保护措施），所有请求在本地完成，不收集账号密码、不上传文件信息、不连第三方服务器。
- **可复用纪律**：① **适配层下沉到平台专属配置**（`config/ali.json`、`config/quark.json`…每个网盘一套解析规则）↔ 本仓 `native/linkage.py`「各端各自规范、兼容层兜底」同构；② **协议归一**（不同网盘直链统一转 Aria2 RPC / BitComet 标准格式）↔ 本仓 IPMsg「与 iptux/飞秋互通」的协议归一思维同构；③ **本地解析、零云端依赖、不收集凭证** ↔ 本仓 `meshchat` 四条安全底线（附件不自动落盘、不解析解码、有上限、不执行对方下发内容）同构。本仓**不落地**网盘直链代码（无 counterpart）。

### 3.2 传输优化四件套：分块 / 并发 / 断点续传 / 校验

- **要点（多篇文章一致）**：① **分块下载**（高达 10MB 一块）+ 多线程（IDM 16 连接分段、Aria2 分片）充分压榨带宽；② **断点续传**保证网络波动不丢进度；③ **内置缓存**重复文件秒下（去重）；④ 可调**连接超时 / 重试次数 / 缓冲区大小 / 并发任务数**。
- **可复用纪律**：这是**与传输介质无关的通用工程纪律**，本仓**当前 mesh 文件传输未实现字节层**（仅 `meshchat.send_files` 的 IPMsg 属性通知，真实字节走 TCP 且推迟到上层 manual），故**只沉淀原则、不落代码**。若本仓未来实现 mesh 字节传输，应优先采纳：分块 + 并发上限 + 断点续传 + 校验和（保证完整性）——但必须**在不破坏 `meshchat` 四条安全底线（尤其附件绝不自动落盘、绝不解析解码）前提下**设计，且仍走 IPMsg 同网段 UDP/TCP 2425 通道，不与任何广域网第三方下载器耦合。

### 3.3 合规与自约束：速率 / 并发不榨干

- **要点**：单 IP 并发连接数控制在 8 以内、下载速度不超过带宽 80%、大文件分时段下载，避免触发平台反滥用机制；官方 API 使用规范（遵循各网盘开放平台开发者协议）。
- **可复用纪律**：① **速率/并发自约束**（不榨干、不滥用）↔ 本仓人体工程学「有上限、不伤」底线同构；② **技术中立、只用公开 API** ↔ 本仓「不越权、只读查据、不代查不代下载」同构。本仓组网能力本就是 LAN 内合规 P2P，无外部平台反滥用风险，但「自约束不伤邻」的精神一致。
