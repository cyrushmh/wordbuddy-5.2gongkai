## 一、缺口定位与路线选择（先探测再决策，不臆造）

上一轮挂号的 8 位运行层缺口，本轮开工前先做存在性探测：

| 候选路线 | 探测结果（实测，非推断） | 结论 |
|---|---|---|
| pip `pyz80` | 装上后导入成功——但它是 **Z80 汇编器**（Andrew Collier 的 COMET 语法汇编器），不是模拟器 | 排除（诚实记录：包名有误导性） |
| apt Z80 模拟器 | `apt-cache search z80` 只有 binutils-z80/crasm/d52（汇编/反汇编）；fuse-emulator（Spectrum）、openmsx（MSX）、tilem（TI）均存在但**无法无头加载裸 Z80 二进制并捕获端口输出**（需快照格式/ROM/显示层） | 排除 |
| 自写 Z80 内核 | 纯 Python、无外部依赖、可入仓复现、可与独立反汇编器交叉核对 | **采用** |

决策依据：缺口的本质是「宿主机可观测地执行 Z80 指令并取证」，不是「跑某个具体
操作系统」。自含内核 + dz80 独立反汇编的交叉核对，比「找一个黑盒模拟器但无法
取证」更符合本仓「证据口径」纪律。

## 二、自含 Z80 执行内核（research/comp/z80core.py）

覆盖范围（模块 docstring 文档化，不夸大）：

- **全基础集**：256 槽全解（含未文档化的 SLL 与 DD/FD 前缀下 H/L→IXH/IXL 别名）
- **CB 全块**：8 组循环移位/移位 + BIT/RES/SET 全 256 槽
- **ED 常用块**：LDI/LDD/LDIR/LDDR、CPI/CPD/CPIR/CPDR、INI/IND/INIR/INDR、
  OUTI/OUTD/OTIR/OTDR、NEG、RETN/RETI、IM 0/1/2、LD I/R 与 LD A,I/R、RRD/RLD、
  ADC/SBC HL,rr、LD (nn),rr / LD rr,(nn)、IN/OUT (C)；其余 ED 槽按 Zilog 惯例
  解为 8T NOP
- **DD/FD 前缀 + DDCB/FDCB**：IX/IY + 位移 + CB 操作，全解码执行
- **标志位**：S/Z/F5/F3/H/P-V/N/C 全语义（含未文档化的 bit 3/5 位）

**已知答案自测 22/22**（`python3 z80core.py --selftest`）：ADD/SUB/INC 的
H/V 标志、DJNZ  taken/fallthrough、LD (nn),A 往返、OUT (n),A 端口钩子、
RLC B、BIT 7,A 命中/缺失、CALL/RET 栈行为、DAA 两种 BCD 修正、RLCA 标志
保持、LDIR 三步复制与重复回转、SBC A,A 借位、PUSH/POP 往返。

## 三、运行器与闭环程序（research/comp/z80_runner.py + hello8run.c）

- **hello8run.c**（sdcc -mz80，ANSI C，618B ihx）：向 OUT 端口 0x01 发
  「Z80-RT-OK」横幅，再把计数器终值以两位十六进制字符发出，最后 HALT；
  计数器同时留在 RAM 供回读。设计值：0x55 + 9 字符 + 0x0A = **0x68**。
- **z80_runner.py**：Intel HEX 解析（含校验和验证）、OUT 端口捕获、.map
  符号回读、HALT 停机、指令 trace、dz80 交叉核对，产出证据文件。

**实测闭环（Z80RUN.TXT）**：

```
image      : hello8run.ihx  sha256=939522f7a0be…
loaded     : 207 bytes
entry      : PC=0000 (Z80 RESET vector), SP=F000
execution  : 196 instructions, ~1710 T-states (nominal)
halted     : YES @ PC=0264
port OUT(01) hex : 5A 38 30 2D 52 54 2D 4F 4B 36 38 0A   ("Z80-RT-OK68\n")
memory     : _counter@8000 = 68h                        (与设计值一致)
xcheck     : dz80 vs z80core 拼接流线性反汇编：助记符序列 197/197 一致
verdict    : ROUNDTRIP-OK-8BIT
```

三个独立证据面互相咬合：**端口字节流**（行为）、**内存回读**（状态）、
**停机点**（控制流）——加上 dz80 的第四面（解码一致性）。

## 四、独立交叉核对（dz80，d52 包 3.4.1）

dz80 与本内核无共享代码。核对方法：把 trace 中**已执行指令字节按序拼接**成
合成镜像交给 dz80 线性反汇编——若内核的指令长度解码有任何一处错误，拼接流的
边界立即错位，dz80 解出的助记符序列必然分叉。结果：**197/197 一致**。

探测中发现并已记录的 dz80 行为（写进 runner docstring）：dz80 只接受相对于
cwd 的裸文件名（传绝对路径会回落成 '.hex' 而失败）；输出只给跳转目标打地址
标签；尾部 equ 符号块需过滤。

## 五、工程坑实录（内核调试入账）

| # | 坑 | 修法 |
|---|---|---|
| 1 | x=0/z=2 行寄存器对索引误用 y（0x0A=LD A,(BC) 被读成 DE），msg 指针取错、循环即退 | 该行须用 **p=y>>1**：p=0→(BC)、p=1→(DE)、p=2→(nn)+HL、p=3→(nn)+A |
| 2 | JR 行条件写反：0x28 是 JR Z（y=5），误配成 y=4 | JR 行正确映射 **y=4→JR NZ、y=5→JR Z、y=6→JR NC、y=7→JR C**（与 cc 表的 NZ/Z/NC/C 不同，JR 行无 PO/PE/P/M） |
| 3 | `LD rp,nn` 与 `ADD HL,rp` 被误加 `_imm16()`——前者变「旧值+立即数」、后者多吞 2 字节 | 两条指令均无立即数；ADD HL,rr 补上 H(bit11)/C(bit15)/N=0 标志语义 |
| 4 | trace 字节用「PC 跨度」切片，跳转指令把目标距离算进指令长度，T 态虚高 | 改用**取指计数** `_fetch_count` |
| 5 | DJNZ 曾写成无条件跳转 | 先减 B 再判跳 |
| 6 | EX AF,AF' 分支残留错乱 PC 操作 | 只换寄存器，不动 PC |
| 7 | ED 块指令位域两轮搞反（先 z 后 y） | 正确结构：**z 选指令**（0=LDI/1=CPI/2=INI/3=OUTI），**y 选变体**（4=基、5=递减、6=重复、7=重复+递减） |
| 8 | asz80 绝对寻址裸写 `ld a,_sym` 被拒（error a） | 须括号 `ld a,(_sym)`；OUT 立即数十进制 `out (1),a`（`1h` 后缀不可，`0x01` 可） |

坑 1/2/7 是 Z80 解码表的结构性错误，全部由自测用例与端到端行为（端口流错字）
暴露——这正是「已知答案自测 + 端到端取证」双层的价值。

## 六、诚实边界（不夸大半句）

- 内核是**自含实现，非参考级**：不建模中断接受/菊花链、精确 T 态（T 态为标称
  近似，证据文件中标注 nominal）、内存竞争；R 寄存器只按文档模式递增。
- 覆盖范围限于上述指令集；对未覆盖槽位的失败会**显式抛异常**而非静默吞掉。
- qemu/MAME/FCEU 维持存在性只读探测（不启动、不下载 ROM）——「本机无 8 位
  原生执行路径」的物理事实不变，变的是「模拟执行层已可复现地闭合」。
- 交叉核对证明的是**解码一致性 + 行为符合设计值**，不证明「与真实 Z80 硬件
  逐周期一致」——后者超出本仓证据口径，不做此声称。
