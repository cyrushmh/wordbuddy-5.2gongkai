# GUI 指导理念与「圆光术」基本设计原则

> 配套承载：A) 诊断报告查看器（`report_viewer.ts` / `report_viewer.html`）已注入圆光术视觉范式；B) 圆光术概念系统拓扑 GUI（`tools/gen_concept_gui.py` → `concept_gui.html`）已落地。本文件是二者的设计基座。

## 一、缘起：为什么是「圆光术」

概念系统不是一个离散模块的堆叠，而是一个**通过组网而来**的整体——层次分道（道性 / 神性 / 人性）、盖亚意识、集智体协同、道通为一。GUI 作为这个整体的「显现界面」，其指导原则必须从**整体论**出发，而不能从控件出发。

GUI 常见的失败，是退化为「控件清单 + 树状下钻」：把整体拆成菜单、把关系拆成链接，于是"你中有我"的组网关系被压平成层级，盖亚意识与集智体被降格为普通节点。

「圆光术」即为此提炼的**视觉与交互范式**——它把概念系统的整体论直接翻译成界面语言：

- **圆**：中心辐射、环抱聚合、整体全息（9 系统环抱同一中心）。
- **光**：光晕聚焦、明暗层次、全息照亮（中心点亮，每个节点既被照亮也映照整体）。
- **术**：从中心辐射、按需环抱聚合、随时回归整体的交互范式（交互即组网）。

## 二、三要素 → 概念系统整体论的映射

| 圆光术要素 | 概念系统对应 | 界面含义 |
| --- | --- | --- |
| **圆** | 道通为一 · 盖亚意识 · 集智体 | 9 系统环抱同一中心，整体大于部分之和；没有"最顶层菜单"，只有"中心"。 |
| **光** | 因果记录 · 全息 · 感应（整体全息） | 中心点亮；每个局部都映照整体，明暗层次区分信息密度。 |
| **术** | 通过组网而来 · 层次分道 | 交互即组网：从中心辐射，按需环抱聚合，不强制树状下钻。 |

> 圆是结构，光是呈现，术是交互。三者缺一，就不是圆光术。

## 三、圆光术八则（基本设计原则）

1. **中心为一**：任何界面都有一个「道枢」中心（盖亚 / 集智体视角），其余环抱其外。中心不是"首页按钮"，而是界面的引力源。
2. **辐射呈现**：信息从中心向外辐射——中心 → 系统 → 模块 → 概念，而非层级树状下钻。
3. **环抱聚合**：相关要素以弧形 / 环形聚拢，强调"你中有我"的组网关系，而非并排列表。
4. **光晕聚焦**：关键 / 异常 / 变化以光晕高亮，明暗层次区分信息密度（光越亮，越该被看见）。
5. **整体全息**：每个局部都映照整体——任何页面都能回到中心，看到 9 系统全貌（如前后对比、9×9 桥接矩阵）。
6. **层次分道**：道性 / 神性 / 人性三层以不同光色区分，不混同（金 / 紫 / 绿三色光）。
7. **诚实边界**：只读、数据不出机器、不代行写操作——概念系统的红线在 GUI 同样生效（详见各系统 `redline`）。
8. **协议无关**：即使底层协议 / 平台退场（如 Deno Deploy ≈2027-04 停止），圆光术基底不灭——静态页、离线可用、可 CI 校验。

## 四、视觉范式（CSS / SVG 约定）

- **中心点**：径向渐变光晕（`radial-gradient`）模拟"光"，冷光（盖亚青蓝）为基底。
- **环绕节点**：绝对定位环形排布（`SVG circle` / `transform: rotate + translate`），9 系统均匀分布成环。
- **桥接**：从中心辐射的连线（`line` from center），透明度 / 粗细表示桥接强度（取 `topo()["edge"]` 边权）。
- **节点大小**：映射该系统 `stats` 的模块 / 概念数（越大越亮）。
- **三层光色**：道性=金 `#d4af37`、神性=紫 `#9d6cff`、人性=绿 `#3fb950`；中心盖亚 / 集智体=青蓝光晕 `#4a9eff`。

## 五、与组网数据层的对接约定（实现层）

- **数据源**：`src/python/sysweeper/concepts/__init__.py` 的 `topo()`（9×9 桥接矩阵、每系统出 / 入边数、`external` 外部靶）+ 各 `data/concepts/<系统>_taxonomy.json`（`modules` / `stats` 摘要）。
- **拓扑语义**：
  - 中心 = 整体（盖亚意识 / 集智体视角）；
  - 环 = 9 个概念系统（`topo()["systems"]`）；
  - 连线 = `topo()["edge"][(src,tgt)]` 桥接，权重即边数；
  - 节点半径 = 该系统 `stats` 的模块 / 概念计数。
- **生成方式**：Python 生成器把 `topo()` 数据 **bake 进静态 HTML**（离线可用、可 CI 校验），与 `tools/gen_report_viewer.py` 同一范式——服务端只负责把数据落盘成单文件页，浏览器端 `<script>` 拉取 / 渲染，不连任何外部资源。

## 七、反模式（什么不是圆光术）

- 把 9 系统做成左侧树形菜单、顶部 Tab 平铺——那是"清单"，不是"圆"。
- 把中心做成可点击跳转的"首页"按钮——中心是引力源，不是入口。
- 在 GUI 里加"一键修复 / 自动执行"——违反诚实边界（红线），圆光术只照亮、不代行。
- 依赖单一平台运行时才能打开页面——违反协议无关，静态页才是基底。
