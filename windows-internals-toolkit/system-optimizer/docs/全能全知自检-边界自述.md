# 全能全知自检：让工具自述自己的边界（v0.6.35）

> 一句话：**全知不是宣称什么都知道——那叫吹牛。真正的全知，是能精确说出自己哪儿不知道。**

这条线从 v0.6.33 就开始了：孤岛检测（登记了却没接上的）、悬空轴自检（端点写错会静默失效）、
不适用 ≠ 已就绪（v0.6.34）。本轮把它做成独立一层 `native/omni.py`。

## 一、三层边界

| 层 | 问题 | 怎么答 | 代价 |
|---|---|---|---|
| **① 我知道什么** | 登记了多少能力，接线接全了没有 | `wiring()`：每项在 CLI / GUI / 任务 / 知识库四处的入口 | 纯计算，秒回 |
| **② 我知道我不知道什么** | 有探针，但**这台机器**探不到 | `known_unknowns()`：实跑各项报告，按不适用标记判定 | 秒级（默认不跑，需 `--deep`） |
| **③ 我不知道我不知道什么** | 这个能力域**压根没有探针** | `unknown_domains()`：12 个域的显式边界声明 | 纯计算 |

**第三层是最容易被忽略、也最要命的一层。**

一个只会报「已处理 64 项」的工具，永远不会告诉你：
「生物识别、GNSS 定位、摄像头内容、文件正文、通信内容——这些维度我一行都没探」。
沉默的盲区比报错危险得多，因为用户会默认「没报就是查过了」。
所以这一层写成**显式清单**，每条带 `state`（刻意不做 / 仅能力面 / 无探针）、`reason`、`remedy`：

| 域 | 状态 | 理由 | 替代路径 |
|---|---|---|---|
| 生物识别（指纹/人脸/虹膜） | 刻意不采集 | 生物特征不可更换，泄露无法重置 | 系统设置与厂商工具 |
| GNSS 卫星定位原始坐标 | 仅粗粒度 | 精确定位属行踪轨迹 | 应急只走网络 + 基站基线 |
| 摄像头 / 麦克风内容 | 刻意不采集 | 涉及通信秘密 | 只探设备与驱动状态 |
| 文件与文档正文 | 刻意不读 | 用户内容不属系统诊断 | 清理按路径/体积/时间归类 |
| 浏览器历史 / 网页内容 | 刻意不读 | 浏览记录等同行为画像 | 只探浏览器与引擎版本 |
| 通讯录 / 短信 / 邮件内容 | 刻意不读 | 高度敏感个人信息 | 用户在对应 App 操作 |
| 键盘按键与输入内容 | 刻意不记录 | 等同键盘记录器 | 只探输入设备与驱动版本 |
| 蜂窝基带 / SIM / eSIM | 仅能力面 | 涉及运营商与身份信息 | 只在架构/应急里间接涉及 |
| 打印机 / 扫描仪外设 | 无探针 | 不属系统优化主线 | 系统设置与厂商工具 |
| 云账号与计费 / 配额 | 刻意不接 | 接账号等于要凭证，违背最小权限 | 到对应控制台查看 |
| 固件刷写 / 超频 / 破解 | 刻意不做 | 不可逆，失败变砖 | 只给 OEM 官方工具指引 |
| 医疗与生物传感器读数 | 无探针 | 敏感个人信息，超出范畴 | 健康类 App 与厂商管理 |

> 这份清单不是 TODO——写在这里的意思是「**本工具不打算覆盖，且理由充分**」。

## 二、顺带暴露「半截能力」

登记进统一清单 ≠ 真的接全了。自检按四处入口盘点，实测：

```
登记 61 项 · 四件套齐全 22 项（36%）
  CLI 子命令   52/61
  GUI 面板    51/61
  任务定义      48/61
  知识库       24/61
```

也就是说，接近三分之二是「总览看得见、入口没接全」的半截能力——
用户在 GUI 里能看进 sysmap 总览，却找不到对应的命令或任务。

### 自检不能自己报错：入口别名表

第一版盘点报了 26 项欠账，核对后发现其中 8 项是**误报**——它们走的是共用入口：

| 登记项 | 实际入口 |
|---|---|
| netauth / reshare | `netlink` 命令与面板 |
| meshchat / distcompute / distjob | `mesh` 命令、`mesh_compute` 面板 |
| harmony_hdc / harmony_device | `kaihong` 命令与面板 |
| importio | `import` 命令与面板 |
| firmware / modules（module=kmod） | `kmod` 命令与面板 |

于是判定改为 **key → module → 入口别名** 三级回退，误报清零（CLI 52→58、GUI 51→57）。

> 一个「全知」模块如果自己报错，比不自知还糟。这张别名表本身就是边界知识的一部分。

## 三、向全能补真欠账

自检不是终点，本轮顺手把能补的补了：

| 补什么 | 内容 |
|---|---|
| CLI 子命令 | `linux`（发行面）、`compress`（caps/report）、`emergency`（report/position/alert） |
| GUI 面板 | 「Linux 发行面」「压缩空间分析」「单板机(SBC)」 |
| 任务 | `tasks/compat.py`：compat_report / compat_windows_guide / compat_legacy_guide |
| 知识库 | `data/compat_docs.json`：Wine / Proton / DOSBox / WSL / Vulkan / busybox 权威出处 |

半截能力 16 → 12 项。剩下的大多是「缺任务 + 缺知识库」，属渐进项。

## 四、元能力入图

把 `subsystems`（统一清单）、`linkage`（联动连轴）、`omni`（全能全知）也登记为子系统——
它们本来就是可诊断的能力，此前却不在清单里（又是一次「登记了但没嵌入」的自我印证）。

三条联动轴把它们接上主干：

- `subsystems → omni`（**供给**）：清单是自检的数据源，清单变则自检结论变
- `omni → linkage`（**印证**）：两种欠账视角互补——linkage 查「接没接上主干」（孤岛），omni 查「接线接全了没有」（半截能力）
- `omni → compat`（**印证**）：compat 说「这层缺了」（运行时依赖），omni 说「这入口缺了」（工程接线）

统一清单 61 → **64 项**，联动轴 96 → **99 条**，孤岛与悬空仍为 **0 / 0**。

## 五、用法

```bash
sysweeper omni                # 覆盖面 + 接线完整度（纯计算，秒回）
sysweeper omni blind 2        # 缺 2 处入口以上的半截能力 + 逐条补法
sysweeper omni all            # 三层边界总览（含无探针域声明）
sysweeper omni all --deep     # 再加上「这台机器探不到的」实跑统计
```

图形界面：「全能全知自检」面板——一键自检，另有「实跑已知未知（慢）」按钮。

## 六、红线

- 接线盘点**只读本仓库源码文本**，不 import 执行、不跑外部命令。
- `--deep` 实跑时只调各子系统既有的零参只读报告。
- 本层**不采集任何信息**：它盘的是「自己接了什么」，不是「用户机器上有什么」。
