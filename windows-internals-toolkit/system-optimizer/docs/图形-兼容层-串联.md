# 图形 · 兼容层 · 串联（v0.6.34）

> 主题：**看得见（图形）、接得上（兼容层）、走得通（串联）**。
> 上一轮（v0.6.33）把散落的模块收编进统一清单、并接上了联动轴；
> 这一轮让这些关系**画得出来**，让兼容层**串成一条链**，让联动轴**能沿边走通**。

## 一、兼容层：从四份各说各话的报告，到一条能回答问题的链

此前 `proton` / `dosbox` / `wsl` / `virtgpu` / `legacy` 各自输出一份报告，各说各话。
用户真正想知道的只有一件事——**「我这台机器能不能跑那个平台的软件，缺哪一层」**。

于是把它们按**四层依赖**串起来（新增 `native/compat.py`）：

| 层 | 回答什么 | 由谁供给 |
|---|---|---|
| 1 宿主底座 | 架构 / 内核模块 / 发行版撑不撑得住 | `arch` / `kmod` / `distro` |
| 2 设备与图形 | 有没有可用的图形与虚拟化通路 | `virtgpu` |
| 3 兼容运行时 | 有没有把异平台调用翻译过来的那一层 | `proton`(Wine) / `dosbox` / `wsl` / `legacy` |
| 4 供给 | 缺的东西能不能装、谁来装 | `pkgmgr` |

**串联而非并列**：上层能不能用，取决于下层给不给得了。Proton 要 Vulkan（第 2 层）
与 32 位运行时（第 4 层），缺任何一层，第 3 层就是空转。报告因此按**场景**给结论，
而不是罗列四个模块各自的输出：

```
[场景串联结论 · 缺一层即空转]
  · 跑 Windows 程序/游戏：✗ 缺层（proton）  — 【Vulkan 支撑栈】✗ 缺前提
  · 跑老 DOS 程序：✗ 缺层（dosbox）  — dosbox：未安装
  · 在 Windows 上跑 Linux：— 本机不适用（wsl 不适用）
  · 跑遗留/嵌入式用户态：✗ 缺层（legacy）
```

### 踩住一个真陷阱：不适用 ≠ 已就绪

这是本轮最值得记的一条。本机是 Linux 时，`wsl_report` 返回 **`ok=True`**，
但正文写的是「未识别为 WSL 环境（/proc/version 不含 Microsoft）；其余维度不适用」。

如果直接把 `ok` 当「已就绪」，结论就**反了**——在 Linux 上报「在 Windows 上跑 Linux：✓ 已通」。

所以 compat 把三态彻底分开，并配了专门的回归用例钉死它：

| 态 | 含义 | 判据 |
|---|---|---|
| `ready` | 链路已通 | 依赖的 key 全部 ok 且**无**不适用标记 |
| `missing` | 真缺层 | 依赖的 key 有 ok=False |
| `na` | 本机不适用 | ok=True 但摘要含「未识别/不适用/非 Windows/未安装…」 |

> 教训：**只读诊断的 `ok` 只表示「这次探测跑通了」，不表示「这个能力具备」**。
> 两者混用会把「不适用」报成「已就绪」，比报错更危险。

## 二、串联：从「有边」升级到「能沿边走」

v0.6.33 的联动轴是张关系图，只能回答「谁和谁有关系」。本轮让它**能走**：

| 接口 | 回答什么 |
|---|---|
| `path(A, B)` | A 到 B 的**最短串联链**（BFS，返回轴序列，含每跳性质与说明） |
| `reachable(A)` | A 影响得到哪些节点（它出边的闭包） |
| `longest_chain()` | 全图最深的串联有多深（对所有节点对 BFS 取最长） |
| `chains_report()` | 串联体检：最长链 + 串联深度 Top + 兼容层示范链 |

新增**「串联」性质**（同一条依赖链的上下游），兼容层四层是它的首个实例：

```
$ sysweeper linkage --path arch pkgmgr
串联链：架构/指令集 → 兼容层串联 → 包管理（2 跳）
  1. [门控] 架构/指令集 → 兼容层串联
     架构决定兼容层能不能成立：x86 才能原生跑 Win32，ARM 上 Wine/Proton 口径完全不同
  2. [串联] 兼容层串联 → 包管理
     缺的运行时由包管理补上：串联的最后一跳是「谁来装」
```

**最长串联链实测 10 跳**，跨了五个面：

```
iOS 设备 → Android 设备 → Linux 本机发行面 → 发行版能力 → 兼容层串联
        → WSL 子系统 → 网络接口/路由 → DNS 解析 → Tor 覆盖层 → ZeroTier 虚拟组网 → 本地自组网
```

一条链从移动端一路走到自组网——这才是「你中有我」该有的样子：不是两两点对点，
而是能顺着走下去。

## 三、图形：画得出来，也带得走

| 产物 | 用途 |
|---|---|
| `graph()` | 结构化图数据（节点带层与度、边带性质与颜色），GUI 与 SVG 共用 |
| `layout()` | 分层布局纯函数（按层分列、层内等距竖排），**可单测** |
| `svg()` | **纯标准库生成**的 SVG（零依赖、可离线看、可直接贴网页） |
| `ascii_graph()` | 命令行分层邻接图（按层分组列出出边目标） |

GUI 新增「联动图」窗口（Tkinter Canvas，纯标准库）：

- 分层布局，边按性质着色：**供给绿 / 门控红 / 印证蓝 / 闭环紫 / 串联橙 / 关联灰**
- 点越大 = 联通度越高（一眼看出谁是枢纽）
- **点节点看它的入边与出边**（谁喂它、它喂谁，逐条带性质与说明）
- 一键导出 SVG 留档（走系统另存为对话框，路径由用户定）

命令行：`linkage --graph`（ASCII）、`--svg PATH`（导出）、`--path A B`（串联链）、
`--chains`（串联体检）。

> 红线：SVG 只**返回字符串**，不写任何文件；是否落盘、落到哪里由调用方决定
> （CLI 显式给 `--svg PATH`，GUI 走另存为对话框）。

## 五、红线

- `compat` **只调既有零参只读报告**，不安装、不启用、不改配置；缺什么只给官方路径。
- `linkage` 的串联与图形**纯计算**：只读清单与关系表，不调用任何诊断函数、不写任何状态，
  因此无论图多大，开销恒为零。
- SVG 不自动落盘；导出路径由用户显式指定。
