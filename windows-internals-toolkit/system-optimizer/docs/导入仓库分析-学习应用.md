# 导入仓库分析 · 学习应用报告

> 背景：用户要求导入三个 GitHub 仓库，分析其架构与工程实践，并提炼可「学习应用」到本仓库（system-optimizer / sysweeper，Windows 内部工具箱：Python 逻辑层 + Deno/TypeScript HTTP 外壳 + uni-app/Vue 移动前端）的要点。
> 导入方式：三个仓库均浅克隆至 `/workspace/imports/`（outline-sdk 因 github.com:443 瞬时 TCP 连接超时重试两次后成功）。
> 日期：2026-10-10。

## 一、三仓库速览

## 二、逐仓库分析

### 2.1 outline-sdk —— Go 网络 SDK（最值得学的是「工程纪律」）

- **架构**：两个解耦的 Go module，无 `go.work`。
  - 根模块 `golang.getoutline.org/sdk`：稳定核心 `transport/`（StreamConn/PacketConn 连接抽象）、`dns/`（解析器）、`network/`（IP 设备、包中继、DNS 拦截/截断、用户态协议栈 lwip2transport）。
  - `x/` 模块 `golang.getoutline.org/sdk/x`：高层扩展与实验库（shadowsocks、socks5、split、tls、tlsfrag、quicprelude、httpconnect、httpproxy、websocket、smart、mobileproxy、sysproxy、report…）。`x/go.mod` **固定根模块的已发布版本**，不允许本地 `replace`。
  - 可组合接口：`StreamConn`/`PacketConn`（连接）、`StreamDialer`/`PacketDialer`（可嵌套的拨号器）、`dns.Resolver`（解析器）。传输可层层包裹：TCP → TLS → HTTP → QUIC。
  - CLI 工具在 `x/tools/`：`resolve`、`fetch`、`fetch-speed`、`test-connectivity`、`http2transport`。
- **可复用工程实践**：
  1. **稳定核心 / 实验扩展分离 + 版本钉死**：新库先在 `x/` 长，验证后才毕业到根；跨模块改动不能原子合入（先改根→发版→再升 `x/` 的 pin）。强「API 稳定性 / 依赖隔离」纪律。
  2. **`AGENTS.md` / `CLAUDE.md`**：面向 AI 编码代理的仓库文档（`CLAUDE.md` 直接 `@AGENTS.md` 引用）。写清模块结构、命令（`go test -race`、两个模块都要 `staticcheck`、`go-licenses` 校验）、坑点、工作流（约定式提交，scope 用包名 `fix(packetrelay):`）。
  3. **许可证白名单强制**：CI 跑 `go-licenses check --allowed_licenses=Apache-2.0,Apache-3,BSD-3-Clause,BSD-4-Clause,CC0-1.0,MIT`，**只接受宽松（notice 类）许可，拒绝所有 copyleft**——因为要分发到移动端且本身是 Apache-2.0。
  4. **跨平台纯层规则**（`docs/cross-platform.md`）：用 `GOOS`/`GOARCH` 纯 Go 交叉编译；**避免 Cgo 才能保持可交叉编译**；Android 走 NDK + `adb`（`run_on_android.sh`）。
  5. **网络相关测试用 build tag 隔离**（`-tags nettest`）：单元测试离线/便宜，网络测试单独跑。
  6. **vanity import path**（`golang.getoutline.org/sdk`）与 GitHub 物理位置解耦。

### 2.2 windows-2000-supermium —— Windows 内部兼容工程（最值得学的是「可复现变换 + 完整性校验」）

- **`compat/*.c`（1854 行）**：Chromium 用到的 Vista+ API 在 Win2000 上的原生实现——SRW 锁/条件变量（`w2k_sync.c`）、Job 对象（`w2k_job.c`）、串口（`w2k_s232.c`）、VEH（`w2k_veh.c`）、WTS（`w2k_wts.c`）。每个都通过 `NtQueryInformationProcess` 等底层 NT 接口补齐缺失 API。这是一份**Windows API 版本差目录**——与 sysweeper 的 kmod/diagnose 子系统定位直接对应。
- **`manifests/*.json`**：**可复现二进制补丁链**——声明式 JSON 描述每个文件的变换：`os_version`(before/after)、`subsystem_version`、`import_redirects`。配合 `SOURCE-MANIFEST.sha256`、`RELEASE-ASSETS.sha256` 做哈希校验。强模式：**把变换写成数据、可复现地施加、用 SHA 校验**。
- **`diagnostics/collect-system.vbs`**：VBScript 系统数据采集（适合遗留/离线 Windows）。另有 `package-scripts`、`tests`。
- **`certificates/`**：Win2000 根证书存储安装（`INSTALL.cmd`/`VERIFY.cmd`/`W2KROOTS.EXE`）+ `cacert.pem` + 逐证书 SHA256 清单——一套**遗留根证书供给 + 校验**工具。
- **`docs/`**：BUILDING / CERTIFICATES / COMPATIBILITY / DIAGNOSTICS / TESTING，分类清晰；另有 `RELEASE_NOTES.md`、`UPSTREAM.md`、`THIRD-PARTY-NOTICES.md`、`SECURITY.md`。
- **学习点**：Windows API 兼容目录（kmod/diagnose 的参考素材）、声明式补丁清单 + SHA 校验模式、遗留系统采集脚本、证书供给套件、文档分类法。

### 2.3 mihomo-kubernetes —— k8s 透明代理（最值得学的是「运维健壮性」）

- **`mihomo-deployment.yaml`**：`apps/v1`，namespace `mihomo`，`nodeName: master`，`securityContext: privileged: true` + `capabilities: [NET_ADMIN]`，lifecycle `postStart` 跑 `iptables.sh`，config 用 `subPath` 挂载；暴露端口 53/7890/9999/7893。
- **`mihomo-config.yaml` / `mihomo-iptables.sh`**：iptables tproxy 透明代理。
- **`cronjob-restart.yaml`**：**每日重新部署 mihomo 以绕开其内存泄漏**（上游 issue #405）。
- **multus-cni + macvlan**：把 Pod 挂到 LAN 接口当网关；K3s 3 节点，OpenWrt 上行。
- **核心运维教训**：当依赖的上游有你修不了的内存泄漏时，**用「定时重启 / 健康检查」把它包起来，而不是去 patch 上游**。诚实且务实。
- **学习点**：k8s 透明代理模式、看门狗/重启绕过敏感依赖的运维模式、基础设施即代码的清晰度。
