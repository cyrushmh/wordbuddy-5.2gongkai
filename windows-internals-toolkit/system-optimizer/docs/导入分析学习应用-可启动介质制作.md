# 导入分析学习应用 —— 可启动介质制作（livecd / live DVD / live BD / 可启动 USB）

> v0.6.20 新增 `native/livemedia.py` + `tasks/livemedia.py`，只读核验本机「制作何种可启动
> 介质的能力」。延续「你中有我、系统的看待一切」：把 live 介质制作这条跨工程链路，拼成一张
> 能力地图，而非堆一座新孤岛。

## 一、学到什么（技术要点）

可启动介质 = 一个「能直接从光盘或 U 盘启动并运行」的系统镜像。制作链路是一套跨多层的工程：

| 层 | 干什么 | 关键工具 / 规范 |
|---|---|---|
| 镜像构建 | 把文件/目录打成 ISO | `xorriso`（GNU，mkisofs/genisoimage 现代继任者，原生 El Torito/isohybrid/UDF）/ `mkisofs`（cdrtools）/ `genisoimage`（Debian 系 GPL 复刻）/ `grub-mkrescue`（一键 BIOS+UEFI 双启 rescue 镜像）/ `mtools`（造 EFI FAT 映像） |
| BIOS 引导 | 老机器从光盘/MBR 启 | ISOLINUX(`isolinux.bin`)/SYSLINUX(`extlinux`)/GRUB(`i386-pc`) |
| UEFI 引导 | 新机器从 EFI 启 | GRUB-EFI 产出 `grubx64.efi`，标准入口 `/EFI/BOOT/BOOTX64.EFI`；`systemd-boot`(`bootctl`) |
| El Torito | ISO 9660 的可启动扩展（BIOS） | `-no-emul-boot`/`-boot-load-size 4`/`-boot-info-table`；UEFI 替代 `-eltorito-alt-boot -efi-boot` |
| 混合镜像 | 同个 ISO 既能刻盘也能 dd 到 U 盘 | `isohybrid`（SYSLINUX 或 xorriso 的 `-isohybrid-mbr`）；MBR(≤2TB)/GPT(>2TB) |
| 压缩根系统 | Live 系统的只读压缩根 | `squashfs`(`mksquashfs`/`unsquashfs`)；写时叠加 `overlayfs`；持久化钩子 `casper`(Debian/Ubuntu) |
| U 盘写入 | 把镜像落到设备 | `dd`（混合镜像直接块复制）/ `Ventoy`（多 ISO 启动器）；Rufus/balenaEtcher 为 Win/macOS 工具 |
| 固件模式 | 本机现在怎么启 | `/sys/firmware/efi` 存在=UEFI，否则 BIOS(Legacy)；决定回启动介质须含哪种入口 |
| 介质规格 | 容量/文件系统 | CD 650/700MB(ISO9660)/DVD 4.7GB 单层·8.5GB 双层(ISO9660/UDF)/BD 25GB 单层·50GB 双层·100-128GB BDXL(UDF 2.50+，可启动)/USB 任意(FAT32 ESP 或 isohybrid 直 dd) |

**关键认知**：
- **BD 可启动**：蓝光用 UDF 2.50+ 文件系统，且同样支持 El Torito 引导（xorriso 一条命令即可
  产出生成 BD 可启动镜像），不是只有 CD/DVD 才能做启动盘。
- **UEFI 入口约定**：可移动介质（U 盘/光盘）的 UEFI 引导固件默认找 `\EFI\BOOT\BOOTX64.EFI`
  （x86_64）/ `BOOTIA32.EFI`（32 位）；缺它 UEFI 模式下就「启不动」——这是最常见的自制 ISO
  翻车点。
- **双启 Live USB 标准做法**：用 `xorriso` 或 `grub-mkrescue` 产出 isohybrid 镜像 → `dd` 到 U 盘。
- **Live ≠ 安装盘**：Live 系统根在 `squashfs`（只读压缩），要能改就靠 `overlayfs` 叠一层，
  持久化靠 `casper` 在 initramfs 阶段挂 persistence 分区/文件。

## 二、在 sysweeper 里怎么落（只读诊断，不制作）

新增模块只做**能力核验**，绝不执行任何写入/构建命令：

- `native/livemedia.py::livemedia_report(iso_path=None)` 输出八大段：
  1. ISO 构建工具链　2. BIOS/UEFI 引导加载器　3. El Torito·混合镜像能力
  4. 压缩根系统(squashfs/overlayfs/casper)　5. U 盘写入工具　6. 本机固件/启动模式
  7. 介质规格知识（CD/DVD/BD/USB）　8. 可选：给定 ISO 的只读可启动性校验
- 可选 `--iso <path>`：对给定镜像只读元数（`file`/`isoinfo -d`/`xorriso -report_el_torito`），
  均只读、不改、不解包。
- `tasks/livemedia.py` 注册为 `livemedia_capability`（platform=any / category=maintenance / risk=low）。
- 接入 `registry.py`（两处延迟 import）、`cli.py`（`livemedia` 子命令 + `--iso`）、
  `gui.py`（「可启动介质」按钮 + 只读窗口）、`native/__init__.py`（`__all__` + docstring）。

## 三、红线（与全工具一致，零执行）

> 绝不 `mkisofs`/`xorriso` 实际打包、绝不 `dd` 到任何设备、绝不挂载/解包 ISO、绝不
> `modprobe overlay`、不改固件变量。仅 `shutil.which` + 目录与 `/sys` 存在性 + 给定 ISO 的
> 只读元数据。

## 四、「你中有我」的关联

- 可启动介质制作 = `storage`(块设备/分区表) + `kernel`(overlayfs 模块) + `osi`/`network`
  (若 Live 系统要联网) + `media`(若 Live 含图像优化工作流) + 固件(启动模式) 的交汇点。
- `sysmap` 总览现已能把它作为「本地介质制作能力」维度纳入关联图（需制作 Live 修复盘时，
  先回看本机是否具备 xorriso/squashfs/isohybrid）。
- 与 v0.6.17 网络模块、v0.6.19 图像管线的关系：若 Live 系统要内置网络诊断或图像优化，
  制作方需在本机先具备对应工具链——本模块给出「能不能做」的前置判定。
