## 二、代码落地模块（全只读，守住红线）

### 1. WSL 环境诊断（`native/wsl.py`）
- 是否 WSL：`/proc/version` 含 Microsoft
- 版本 1/2：`osrelease` 含 `-microsoft-standard-WSL2`（2）或 `-Microsoft`（1）；退化用 `cmdline` 的 `initrd`
- 内核版本：`uname -r`，对照 wsl2-linux-kernel 标签（最新 6.18）
- 根文件系统：`findmnt /` 的 FSTYPE（virtiofs / 9p drvfs）
- systemd：`wsl.conf [boot] systemd=true`
- interop：`/etc/resolv.conf` 由 systemd-resolved 生成 → nameserver 即 Windows 主机 IP
- 红线：不写 wsl.conf/.wslconfig、不 `wsl --shutdown`、不连校外网

### 2. 虚拟化与 GPU 虚拟化诊断（`native/virtgpu.py`）
- 虚拟化：`/proc/cpuinfo` hypervisor 标志 + vmx/svm；细分 KVM/QEMU、VMware、Xen、Hyper-V/WSL
- virtio 设备：`/sys/bus/virtio/devices`
- virtio-gpu：设备 modalias 含 `virtio:...gpu` → Venus 协议后端，免直通加速
- 显示卡：`/sys/class/drm/card*`（`card\d` 为 GPU 实体，`card*-*` 为连接器符号链接，已过滤）
- 红线：不加载模块、不装驱动、不改 QEMU/crosvm

### 3. 浏览器与引擎检测（`native/browser.py`）
- 探测：which chromium/chrome/firefox + `--version`；引擎 Blink(Chromium 系)/Gecko(Firefox)
- Web 兼容知识参考：演示 mdn/bcd 的「特性→支持等级」结构（WebGPU / Container queries / :has() / Top-level await / SharedArrayBuffer），极简静态子集，非实时数据库
- 红线：不下载 BCD 全量 JSON、不连校外网、不改浏览器配置

### 4. DNS 解析健康度（`native/dnshealth.py`，与 `network.nm_resolved` 互补）
- `network.nm_resolved` 管「连接管理与 resolved 配置」；本模块专看「解析链路本身」
- nameserver 来源：`/etc/resolv.conf` 是否 systemd-resolved 生成
- stub：`systemd-resolved` 监听 127.0.0.53:53；与 resolv.conf 不一致是「能 ping IP 不能开网页」常见根因
- 解析探测：默认一次良性 A 查询（`getaddrinfo example.com`）测延迟，只读不改状态；`--no-query` 关闭
- 红线：不写 resolv.conf、不重启 resolved、不改 DNS

## 三、MINIX3 微内核架构对照（知识沉淀）

MINUX3（ZoranWong 学习版）是**微内核**教科书案例，与本项目运行的 **Linux 宏内核**形成对照：

- **微内核**：只把最基础服务（进程调度、地址空间、IPC）放进内核；文件系统、网络栈、设备驱动都是**用户态服务/驱动**，崩溃可重启单服务而不崩内核。
- **宏内核（Linux）**：驱动/文件系统/网络栈均在**内核态**，一个坏驱动可拖垮整机——这也是本项目大量只读探测、避免写操作的现实动机之一。
- **吸收**：本项目对驱动的只读探测（如 `hardware`/`edge`/`virtgpu` 走 sysfs 而非 `insmod`）、对系统改动的 opt-in 高危指引，本质是「把危险操作挡在内核态之外」的工程化——与微内核「最小化内核信任面」哲学一致。
