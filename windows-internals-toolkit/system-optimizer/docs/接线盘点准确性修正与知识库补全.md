# v0.6.37 · 接线盘点准确性修正 + 知识库批量补全

> 承接 v0.6.36「闭环：缺口分类与按需补齐」。v0.6.36 把「全知自检」从「能说出缺什么」推进到
> 「能说出怎么补」，并暴露了 33 项真缺口。本版做两件事：**修掉盘点自身的失真**，
> **用 v0.6.36 造的脚手架把真诊断缺口的知识库一次性补全**。

## 1. 发现的根因 bug（调试）

v0.6.36 的 `omni gaps` 跑出来 33 项「真缺口」，但其中混了两类**误报**：

### 1.1 data 检查用 `<key>*.json` 前缀，漏掉语义命名

团队约定知识库**按语义命名**，不按子系统 key 前缀起名。盘点却用前缀猜：

| 子系统 key | 实际 data 文件 | 旧判定 | 正确判定 |
|---|---|---|---|
| `netlink` | `link_protocols.json` | 误报「缺 data」 | 有 data ✅ |
| `thirdparty` | `net_interop_refs.json` | 误报「缺 data」 | 有 data ✅ |

### 1.2 借 module 名「继承」误判

`kaihong` / `harmony_hdc` / `harmony_device` 三项是鸿蒙变体，共用 `harmony`
模块。`wiring()` 的 data 检查把 module 名也算进去，`harmony*` 前缀匹配到
`harmony_docs.json`，于是三项被误判成「有 data」——其实它们没有**自己的**知识库。

### 1.3 运行期数据被当成缺口

`reshare` / `distcompute` / `meshchat` 的「data」是**运行期**生成（peer 列表 /
offer / 审计日志 / 节点发现），不是包内静态知识库；`webnews` 是运行期聚合（本身就是
知识源）；`plugins` / `plugins_allowlist` 是代码侧安全白名单。这些在 v0.6.36 被并进了
「真缺口」，拉低了「真缺口」比例的信噪比。

> 顺带确认：`reshare` 旧版代码引用 `~/.config/sysweeper/reshare.json`（用户运行期配置），
> **不是**包内知识库——所以不生成 `data/reshare.json`（生成反而会造成包内/运行期两份
> 同名文件的混淆），直接归 by-design。

## 2. 修法

### 2.1 `DATA_FILE_ALIASES`（omni.py）

新增显式别名表，让 data 检查读 native 模块**实际加载**的文件，而非猜前缀：

```python
DATA_FILE_ALIASES = {
    "netlink": ("link_protocols.json",),
    "thirdparty": ("net_interop_refs.json",),
    "kaihong": ("harmony_docs.json",),
    "harmony_hdc": ("harmony_docs.json",),
    "harmony_device": ("harmony_docs.json",),
}
```

`wiring()` 的 `has_data(key)` 改为：**先查别名文件是否存在 → 回退 `<key>*.json` 前缀
→ 不再借 module 名继承**。harmony 三子项因此正确判成「有 data」（它们确实引用
harmony_docs），netlink/thirdparty 不再漏报。

### 2.2 扩展 `BY_DESIGN_KEYS`

把运行期数据 / 机制类加入设计如此清单，使其不污染「真缺口」比例：

```
webnews, plugins, plugins_allowlist, distcompute, reshare, meshchat
```

每项都写了理由（`_BY_DESIGN_REASON`），说明「data 是运行期生成 / 本身即知识源 / 代码侧
白名单，非包内静态知识库」。

## 3. 用脚手架批量补全真诊断缺口

修正后，真缺口收敛为 **26 项**（设计如此 13 项）。其中 **24 项**属「诊断维度应有知识库
但缺 data」——用 v0.6.36 造的 `omni gen-stub` 脚手架一键补全：

```bash
python -m sysweeper omni gen-stub <KEY> --write
```

对全部非 by-design、且 data 缺失的子系统跑了一遍（gen-stub 自带 by-design / 完整项
拒做与幂等保护，安全）。**24 个占位知识库落盘**，40 个跳过（by-design 或已齐全），0 拒做：

```
osi, dnshealth, tor, zerotier, netauth, wsl, proton, virtgpu, browser,
jdk, kmod, firmware, modules, distro, edge, imagefmt, dos, legacy,
busybox, dosbox, livemedia, emergency, linux, compress
```

每个占位是带 `_note` 的空壳（`references: []`、`items: []`），待人工补全权威来源——
本工具只读引用，不自动填充正文（守住 v0.6.36 的红线）。
