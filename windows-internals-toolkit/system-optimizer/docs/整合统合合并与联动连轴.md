# 整合统合合并与联动连轴（v0.6.33）

> 一句话：**把「有模块、没登记」的假嵌入全部收编进统一清单，再给它们之间接上
> 有方向、有性质的联动轴，并且让「没接上」这件事自己暴露出来。**

## 一、问题：登记 ≠ 嵌入

v0.6.22 建了统一子系统清单（`native/subsystems.py`），v0.6.32 又把 `durability/
remote/cert` 收了进去。但把 native 层目录和清单一比对，发现一个更尴尬的事实：

```
native 模块未登记: compress, fonts, harmony(子项), linux, media, snapshot …
```

也就是说，**有六个模块一直在干活，却从来没进过统一开关、也没进过 sysmap 总览**。
用户在 GUI 里关不掉它们、在总览里看不见它们——它们在同一套代码里，却不在同一个系统里。
其中 `linux` 最离谱：这是工具的主战场之一，居然从来没被登记过。

同时，sysmap 的关系图（`RELATIONS`）只画「谁和谁有关系」，三个问题一个都答不了：

1. 这条边**是什么性质**？A 喂数据给 B，和 A 决定 B 成不成立，断掉的后果完全不同。
2. 有没有**接不上的**？登记进清单却一条边都没有的项，是"登记了但没嵌入"的假嵌入。
3. 边有没有**写错**？端点 key 拼错会**静默失效**——不报错、不显示，就那么悄悄没了。

## 二、方案：合并 + 连轴

### 1. 合并：补齐六项登记（54 → 60）

| key | 标签 | 指向 | 备注 |
|---|---|---|---|
| `linux` | Linux 本机发行面 | `linux.linux_report` | **新写**零参聚合 |
| `snapshot` | 系统快照/对比 | `snapshot.snapshot_report` | **新写**零参摘要 |
| `compress` | 压缩空间分析 | `compress.compress_report` | 既有函数，零参可跑 |
| `fonts` | 字体与文本规范化 | `fonts.text_normalize_report` | 既有函数 |
| `harmony_hdc` | 鸿蒙 HDC 设备桥 | `harmony.hdc_report` | 既有函数 |
| `harmony_device` | 鸿蒙设备信息 | `harmony.device_report` | 既有函数 |

两个新写的零参报告（都严格只读）：

- **`linux_report()`**：发行版（`/etc/os-release` → `lsb_release` 降级）／包管理器／
  systemd 日志体积／根分区用量（空闲 <10% 给提示）。**只报告不清日志**——
  收缩 journal 只在任务层以命令文本给出。
- **`snapshot_report()`**：`capture_snapshot(include_probes=False)` + `summarize()`。
  刻意**不跑全量探针**——各子系统的探针由它们自己的报告负责，这里只取基线指标，
  避免 60 项总览里重复跑一遍。

登记即自动生效于 CLI 开关、`subsystems` 子命令、GUI「模块开关」面板、`sysmap` 总览。

### 2. 连轴：新增 `native/linkage.py`

每条联动轴 = `(from_key, to_key, kind, desc)`，四性质 + 一兜底：

| kind | 含义 | 断掉的后果 |
|---|---|---|
| **供给** | A 的产出直接喂给 B（数据/能力流） | B 拿不到输入，能力打折 |
| **门控** | A 决定 B 能否成立（约束/前提） | B 的前提没了，结论不可信 |
| **印证** | A 与 B 交叉验证同一事实 | 少一面镜子，误判风险上升 |
| **闭环** | B 的结果回流 A，形成保护/优化回路 | 只剩单向诊断，没有闭合动作 |
| 关联 | 既有 `sysmap.RELATIONS` 归并来的，未细分 | — |

接口：`all_axes()` / `enabled_axes()` / `degrees()` / `isolated()` / `dangling()` /
`linkage_stats()` / `linkage_report()` / `capabilities_report()`。

**去重以标注轴优先**——它带方向与性质，信息量高于「关联」兜底分类；
反向的同一对（A→B 与 B→A）不算重复，那是两条不同的轴。

### 3. 体检：孤岛与悬空

- **孤岛检测** `isolated()`：登记进清单却总度为 0 的项。这是全模块最有价值的一个函数——
  它把「嵌入了但没接上」从隐性欠账变成显式清单。
- **悬空轴自检** `dangling()`：端点 key 不在清单里的轴。写错即静默失效，这里抓出来。

## 三、首跑结果：抓出 8 个孤岛，其中跨平台 OS 五面全裸

```
子系统 60  轴总数 73  生效 73
孤岛: ['ios', 'macos', 'bsd', 'unix', 'windows', 'thirdparty', 'webnews', 'legacy']
```

**Windows / macOS / BSD / Unix / iOS 五面，登记了却一条联动边都没有。**
这五个面各自有完整的 native 模块、CLI 子命令、GUI 面板，看起来五脏俱全——
但在「你中有我」的关联图里，它们是五个互不相干的孤岛。

按性质逐条补轴后：

- **安卓 → Linux（门控）**：安卓跑在 Linux 内核上，内核面决定它能用哪些调度/省电手段
- **iOS ↔ macOS ↔ Unix ↔ BSD（印证）**：Darwin/BSD/Unix 同源链，两侧结论应能对上
- **iOS ↔ Android（印证）**：移动端两端互为对照
- **Windows → 桌面 / 存储（供给 / 印证）**，**Windows ↔ Linux（印证）**：跨平台兼容口径对照
- **第三方互联 → 网络（供给）**、**资讯 → 设备保护（供给）**、
  **遗留总览 → DOS / busybox（供给）**
- 新登记六项各自接上主干（Linux→发行版/包管理/存储/系统软件/内核、压缩→存储、
  快照→硬件/设备保护、字体→桌面、HDC→设备信息→KaihongOS）

最终：**87 条轴 · 孤岛 0 · 悬空 0 · 联通覆盖率 60/60**。

## 四、联动不是画图，是数据真的流过去

值得单独说的几条**闭环**（B 的结果回流 A，形成回路）：

| 轴 | 实际发生的事 |
|---|---|
| 快照 → 设备保护 | 连续快照的时间序列给出保养包络的**衰减斜率**——没有历史就没有斜率 |
| 设备保护 → 存储 | 保养建议（留余量、少写入）回流到存储健康面，形成诊断→建议→再诊断 |
| 设备保护 → 证书 | 证书临近到期被写进资产保护清单，由设备保护侧推动续期，保护才闭合 |
| 远程接入 → 设备保护 | 明文通道风险并入设备保护清单，统一收口到「通信能力保护」 |
| 共享计算 → 设备保护 | 共享算力时长受保养包络约束：先问设备答不答应 |

## 五、红线

- 新增登记项全部**只读**：`linux_report` 只报告不清日志，`snapshot_report` 只采集不落盘
  （落盘只在 GUI/CLI 显式 save 时发生），`compress_report` 不压缩/不解压/不删除。
- `linkage` 模块**纯计算**：只读清单与关系表，**不调用任何报告函数、不写任何状态**，
  因此无论清单多大，开销恒为零。
- 关闭的子系统不参与联动（其轴整体失效），与 sysmap「关闭即不诊断不展示」同口径。

## 六、用法

```bash
sysweeper linkage            # 联动连轴体检（性质分组 + 联通度 + 孤岛 + 悬空）
sysweeper linkage --stats    # 额外打印结构化统计
sysweeper sysmap             # 总览已含 60 项与新增关系边
```

图形界面：底部按钮「联动连轴」——一键体检 + 能力自检，可反复重新体检。
