# 新硬件：单板机 / ARM SBC（edge，v0.6.11）

「新硬件」不止是安卓手机。树莓派、Orange Pi、NanoPi、RK3399/RK3566 这类**单板机（SBC）**
跑着完整 Linux，却有一套桌面/服务器没有的痛点：SD 卡掉速、被动散热降频、供电不足触发
under-voltage、启动盘类型决定寿命。本层只做**只读探测 + 建议**，不替你改任何设置。

## 探测对象（都是 Linux 上真实可读的接口）

| 项 | 接口 | 说明 |
|---|---|---|
| 板型 | `/proc/device-tree/model` 或 `/sys/firmware/devicetree/base/model` | 设备树在几乎所有 ARM SBC 都有，最稳的「这是什么板」来源 |
| 温度 | `/sys/class/thermal/thermal_zone*/{type,temp}` | Linux 通用 thermal 子系统，毫摄氏度→摄氏度 |
| 降频/欠压 | `/sys/devices/platform/soc/*/throttled` 位掩码（Broadcom） | 其它平台退化到「看温度」判断，不硬猜 |
| 启动盘 | `/proc/self/mountinfo` 回溯根设备 | 判定 SD / eMMC / NVMe / SATA |

Broadcom `throttled` 位掩码（与 `vcgencmd get_throttled` 同义）：bit0 欠压、
bit1 ARM 降频、bit2 当前被节流、bit3 软温度限速。

## 红线（写死）

- **只读**：不写 sysfs、不调 `vcgencmd` 改频率/电压、不装任何散热服务。
- **惰性守卫**：非 SBC（x86 笔记本/服务器）上 `detect_board` 返回 None，所有函数优雅降级，绝不因「没有设备树」而崩。
- 建议带「为什么」：SBC 用户需要懂因果，不是被按头改。

## 典型建议

- 温度长期 >80°C：加散热片/风扇、避免密闭外壳、降负载（被动散热 SBC 长期高温会降频、伤寿命）。
- 供电不足（under-voltage）：换 5V≥3A 电源，太细/太长的线会掉压，降频会直接拖慢一切。
- 启动盘是 SD 卡：根分区换 eMMC/NVMe，SD 只做应急启动并定期备份（SD 不支持 fstrim，意外断电易损文件系统）。

## 任务

| id | 平台 | 风险 | 说明 |
|---|---|---|---|
| `edge_advisory` | any | low | 板型/温度/降频/启动盘只读探测 + 带因果建议 |

非 SBC 上该任务会明确说「未识别为单板机」，不走桌面/服务器的硬件优化任务。

## 代码位置

- `native/edge.py`：探测与建议（所有路径走模块级 `_SYS_ROOT`，测试可重定向到临时目录喂假 sysfs）。
- `tasks/edge.py`：任务定义。
- 测试：`tests/test_edge.py`（假 sysfs 树，不碰真机 `/sys`、`/proc`）。
