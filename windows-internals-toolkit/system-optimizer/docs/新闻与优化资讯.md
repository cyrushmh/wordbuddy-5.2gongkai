# 新闻与优化资讯系统（webnews，v0.6.11）

把「新闻或网站」拿来优化整体——但分两步，且**绝不**把网上抓来的东西当命令执行。

## 它做什么

1. **拿来**：从你配置的新闻源 / 网站（RSS 2.0 / Atom / 普通网页）抓取内容。
   - 只允许 `http` / `https`，带 8 秒超时与 2 MiB 体积上限。
   - 失败源如实报「未能获取」，**绝不编造**内容。
2. **读懂**：把条目按平台/分类抽取成「可落地的优化知识点」，带来源归属，写进本地缓存（XDG `~/.config/sysweeper/webnews.json`）。
3. **当建议展示**：任务层 / GUI / CLI 读缓存，把知识点按分类摆出来——**只读建议**。

## 红线（写死）

- **只抓你配置的 http(s) 地址**，不碰 `file://` / `ftp://`，不发任何写请求。
- **抓来的永远只是文本**：本层没有任何执行路径——不 `eval`、不起子进程、不把网页内容当命令、不自动改系统设置。优化建议由你决定要不要做。
- **默认来源为空**：不默认联网。在 `native/webnews.py` 的 `DEFAULT_SOURCES` 加入你信任的地址才会去抓。
- 缓存只存 URL / 标题 / 摘要 / 知识点文字，**不存任何可执行片段**；损坏优雅降级。

## 分类（与项目一致）

`windows` / `macos` / `linux` / `android` / `network` / `security` / `privacy` /
`hardware` / `storage` / `battery`。抽取是**启发式**——命中关键词只代表「这条信息可能与该分类优化有关」，不是现成操作步骤，需点开来源自行核对。

## 任务

| id | 平台 | 风险 | 说明 |
|---|---|---|---|
| `webnews_fetch` | any | medium（仅因联网，零写入） | 抓已配置来源 → 解析 → 抽知识点 → 缓存 |
| `webnews_knowledge` | any | low | 读缓存 → 按分类摆出知识点（不带网） |

## 代码位置

- `native/webnews.py`：抓取 / 解析 / 抽取 / 缓存（纯标准库 `urllib` + `xml.etree`）。
- `tasks/webnews.py`：两个任务定义。
- GUI：「新闻与优化资讯」窗口（只读报告 + 抓取按钮）。

## 测试

`tests/test_webnews.py`：解析（RSS/Atom）、抽取、来源白名单、缓存、报告——联网用注入的假 `fetch_fn`，不真正出网。
