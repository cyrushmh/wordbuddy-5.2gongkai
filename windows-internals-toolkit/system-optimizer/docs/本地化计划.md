# 本地化计划（Localization Plan）

> 配套实现：`src/python/sysweeper/i18n.py`、`locales/`、`tools/make_mo.py`
> 源语言 = **zh_CN（简体中文）**；默认界面即中文，译文按需挂载。

---

## 1. 目标与边界

让 system-optimizer 的**人类可读界面**（CLI 输出、lowcode 五层讲解、级名/进制名/对照表头）支持多语言，同时**后台数据（opcode、寄存器、字节、解析逻辑）保持原样**，不翻译、不注释污染。

- **要翻译的**：用户能直接读到的串——进制名、五层 `name`/`desc`、对照表头、explain 文案、machine 注记、CLI help。
- **不翻译的**（机器数据，属"后台"）：x86/RISC-V 助记符（`add`/`mov`/`xadd`）、寄存器名（`x0`/`rax`/`rsp`）、立即数与字节、`0x` 十六进制、解码结构本身。
- **原则**：界面显示改成人可读（十进制为主、中文为源），后台解析零改动，边界用注释说明即可。

---

## 2. 标准依据

采用 **GNU gettext** 体系，符合 PO 文件规范与 MO 二进制格式：

| 项 | 规范要点 |
|---|---|
| 源串 | `msgid`（源语言=zh_CN，msgid 即中文串） |
| 译文 | `msgstr`（按语言目录填写） |
| 文件编码 | `Content-Type: text/plain; charset=UTF-8` |
| 复数 | `Plural-Forms` 按语言设：en/de `nplurals=2; plural=(n != 1);`、fr `nplurals=2; plural=(n > 1);`、ru `nplurals=3`（1/2-4/其他）、ja `nplurals=1; plural=0;`（无复数）；zh_CN 源语言默认无复数 |
| 目录约定 | `locales/<lang>/LC_MESSAGES/<domain>.mo` |
| 二进制格式 | magic `0x950412DE`，头部 7×uint32，原语表+译文表各 8 字节/条，字符串数据置于表后 |
| 运行时 | 标准库 `gettext.translation` 解析 `.mo`（零第三方依赖） |

**为何自写编译器**：CI 镜像缺 `msgfmt`/`xgettext` 工具链，故 `tools/make_mo.py` 实现零依赖 `.po → .mo` 编译，可单测、可复现。

## 3. 目录结构

```
src/python/sysweeper/
├── i18n.py                      # 翻译基础设施：set_locale / _ / ngettext
└── locales/
    ├── zh_CN/LC_MESSAGES/sysweeper.po   # 源语言（msgid 即中文，msgstr 同）
    ├── zh_CN/LC_MESSAGES/sysweeper.mo   # 编译产物（回退用，与 msgid 一致）
    ├── en/LC_MESSAGES/sysweeper.po      # 英文译文（联合国五常：英美）
    ├── en/LC_MESSAGES/sysweeper.mo
    ├── fr/LC_MESSAGES/sysweeper.po      # 法文（联合国五常：法国）
    ├── fr/LC_MESSAGES/sysweeper.mo
    ├── ru/LC_MESSAGES/sysweeper.po      # 俄文（联合国五常：俄罗斯）
    ├── ru/LC_MESSAGES/sysweeper.mo
    ├── de/LC_MESSAGES/sysweeper.po      # 德文（额外：德国）
    ├── de/LC_MESSAGES/sysweeper.mo
    ├── ja/LC_MESSAGES/sysweeper.po      # 日文（额外：日本）
    └── ja/LC_MESSAGES/sysweeper.mo
```

- **domain** = `sysweeper`；**source locale** = `zh_CN`。
- **支持语言（7）**：联合国五常对应中(zh_CN)/英(en)/法(fr)/俄(ru) + 德(de) + 日(ja) + **繁中(zh_TW)**。中文为源、英文已建；法/俄/德/日为 v0.6.5 新增；**繁中由 OpenCC 从简体源串自动转换**，不是手译（见 §5.3）。
- 新增语言：复制 `en/` 目录为 `locales/<lang>/LC_MESSAGES/`，翻译 `sysweeper.po`，跑 `make_mo.py`。
- 繁体语言：**不要手译**，跑 `tools/gen_zh_tw.py` 让 OpenCC 转——手译会在下次生成时被覆盖，且与简体源串走偏。

## 4. 切换机制（显式优先，不自动探测）

- CLI：`--locale en`（默认 `None`）。
- 环境变量：`SYSWEEPER_LOCALE=en`。
- 解析顺序：`set_locale(None)` → 读 `SYSWEEPER_LOCALE`，无则回退 `zh_CN`。
- **不做 `LANG` 自动探测**：否则测试/CI 在 `LANG=en` 环境下会意外翻译、破坏断言。
- 回退链：完整码（`en_US`）→ 语言码（`en`）→ 源语言（`zh_CN`）。无 `.mo` 时 `_()` 原样返回 msgid（即中文），保证默认零配置可用。

## 5. 翻译工作流

1. **改源串**：直接在 `zh_CN/sysweeper.po` 的 `msgid` 落定最终中文（它是源语言真相）。
2. **加译文**：在 `en/sysweeper.po` 对应 `msgid` 填 `msgstr`。
3. **编译**：`python tools/make_mo.py`（输出两个 `.mo`）。
4. **冒烟**：`python -m pytest tests/test_lowcode.py`（含 i18n 用例）或手动 `set_locale("en")` 后调 `_("...")`。

> ⚠️ **字典型源串必须过 `_()`**：如 `bits.base_name()` 中 `BASE_NAMES` 的字面中文值，须 `_(BASE_NAMES.get(base, ...))` 包裹，否则 `.get()` 直接返回未翻译的字面量（已修，测试 `test_i18n_default_zh_and_switch_en` 守住）。

### 5.1 常规流程

即上面 1–4 步：改源串 → 加译文 → 编译 → 冒烟。

### 5.2 多语言（en / fr / ru / de / ja）

逐条给译文，**占位符（`%s` / `%d` / `%d%%`）必须与 `msgid` 完全一致**——脚本会校验，
不一致直接报错。字节单位按各语言习惯本地化（fr：`o/Ko/Mo/Go/To`，ru：`Б/КБ/МБ/ГБ`，
de/ja 与英文同形）。

### 5.3 繁体中文（zh_TW）：OpenCC 自动生成（v0.6.6）

繁体不是「另一门语言」，而是**同一种语言的另一种字形**。手译上百条既费时，又会与简体
源串走偏（改了简体、忘了同步繁体）。所以用 OpenCC 机械转换：

```bash
pip install opencc-python-reimplemented      # 仅生成期需要
python3 tools/gen_zh_tw.py                   # 从 zh_CN 转出 locales/zh_TW/.../sysweeper.po
python3 tools/make_mo.py                     # 编译 .mo
```

- 默认档位 `s2t`（简 → 繁正体字形，**不动地区词汇**），保住系统工具的术语一致性；
  想要台湾本地化用词用 `--config s2tw`（如「字节」→「位元組」），`s2hk` 为香港繁体。
- **OpenCC 只用于生成期**：编译好的 `.mo` 进仓库，**运行时零第三方依赖**——
  用户机器上没装 OpenCC 也照样显示繁体（与 `tools/make_mo.py` 的零依赖思路一致）。
- **不要手改 `zh_TW.po`**：下次生成会覆盖。要改就改源语言 `zh_CN.po`，再重跑脚本。

## 6. 已覆盖范围（本轮）

| 模块 | 翻译点 |
|---|---|

| `lowcode/machine.py` | note 行、原子性行、x86/RISC-V/原子样例渲染头 |
| `lowcode/chars.py` | 报错串（空输入/未知编码/未知方案/字节非法…）、Base 对照/转义/乱码面板标题与列头、`\\x` 转义标签 |
| `lowcode/comm.py` | 报错串（HDLC/SLIP/线路码帧错误）、校验和/成帧/线路编码/波特率分频表标题与列头、汉明状态、波形标签 |
| `lowcode/logic.py` | 报错串（空表达式/无法识别字符/缺右括号/未知节点）、真值表/卡诺图/QM/加法器面板标题与列头 |
| `lowcode/__init__.py` | `summary()` 五层 `name`/`desc` |
| `cli.py` | overview 头、`code` 子命令 help、`--locale` 参数 |
| `native/compress.py` | 压缩/归档只读报告全部界面串：分类标签、可省估算结论、格式能力表、报错、字节单位（v0.6.6，54 条） |
| **任务库（364 项）** | `title` / `desc` / `caveats` / `notes` + 分类标签，共 **1550 条**（v0.6.7，见 §6.2） |

> 注：五层实际为 `bits/chars/comm/logic/machine`，无独立 `concur`/`net` 文件（原路线图措辞的"多并发/网络并发层"已并入 `machine` 的 x86 原子指令与 `comm` 通信码层）。控制字符名、Unicode 类别名、标准引用（RFC/GB/ITU-T/ISO…）属后台数据表，按设计不翻。

### 6.1 支持语言（联合国五常 + 德/日 + 繁中，共 7）

| 语言 | 代码 | 类别 | Plural-Forms | 状态 |
|---|---|---|---|---|
| 简体中文 | `zh_CN` | 源语言 | —（默认无复数） | 内置回退 |
| 英语 | `en` | 五常（英美） | `nplurals=2; plural=(n != 1);` | v0.6.2 已建 |
| 法语 | `fr` | 五常（法国） | `nplurals=2; plural=(n > 1);` | v0.6.5 新增 |
| 俄语 | `ru` | 五常（俄罗斯） | `nplurals=3`（1 / 2-4 / 其他） | v0.6.5 新增 |
| 德语 | `de` | 额外（德国） | `nplurals=2; plural=(n != 1);` | v0.6.5 新增 |
| 日语 | `ja` | 额外（日本） | `nplurals=1; plural=0;` | v0.6.5 新增 |
| 繁体中文 | `zh_TW` | 字形转换（非独立翻译） | `nplurals=1; plural=0;` | v0.6.6 新增，**OpenCC `s2t` 自动生成** |

- 切换示例：`--locale fr`、`SYSWEEPER_LOCALE=ru_RU`（完整码 `ru_RU` 自动退化为 `ru`）；未知码回退 `zh_CN`。
- 全语言加载与回退链由 `test_i18n_locales_full` 锁定；compress 层七语言译文由 `test_compress_strings_translated_in_all_locales` 锁定。

> **zh_TW 与其他语言的本质区别**：fr/ru/de/ja 是「翻译」（换一种语言），zh_TW 是「字形转换」（同一种语言的另一种写法）。所以 zh_TW **由脚本从 zh_CN 机械生成**，改简体后重跑脚本即同步，永远不存在「简体改了繁体没跟」的漂移。

### 6.2 任务库串（v0.6.7）：364 项任务 × 4 类字段 = 1550 条

任务串**不在 `_()` 字面量里**（写在 `tasks/*.py` 的 `Task(...)` 字段中），
静态扫描器抓不到，所以走的是「运行时抽取 + 显示层过翻译」这条路：

```
tasks/*.py（中文原文，即 msgid）
   ↓  tools/extract_task_strings.py   ← 从加载后的任务库全量抽取，追加进各 .po
locales/<lang>/LC_MESSAGES/sysweeper.po
   ↓  tools/gen_zh_tw.py（仅 zh_TW，OpenCC s2t）
   ↓  tools/make_mo.py
locales/<lang>/LC_MESSAGES/sysweeper.mo
   ↓  Task.display_title() / display_desc() / display_caveats() / display_notes()
界面 / 命令行
```

| 语言 | 任务串覆盖 | 说明 |
|---|---|---|
| `zh_CN` | 1550 条（源语言，无需译文） | msgid 入册，运行时直接回退 msgid |
| `zh_TW` | **1694 条真实繁体**（47 条纯英文/数字无字形变化） | OpenCC `s2t` 自动生成，与简体永远同源 |
| `en` / `fr` / `ru` / `de` / `ja` | 0（回退中文，**不显示空白**） | msgstr 留空 = 未翻译；**.mo 里不编入空译文** |

两条硬纪律（都由 `tests/test_task_i18n.py` 守住）：

1. **空 msgstr 不得进 `.mo`**——编进去会被 gettext 命中并返回空串，
   界面上就是一片空白，比「回退源语言」更糟。已对齐 GNU msgfmt 行为修入
   `tools/make_mo.py`（编译时跳过未翻译条目并报数）。
2. **`.po` 文件头必须带 `charset=UTF-8`**——头部元数据丢了，gettext 会按
   ASCII 解码中文而直接崩（真实踩过一次，已加断言防止回归）。

补译工作流（其余 5 语言按批次推进，填 msgstr 即可，不用改代码）：

```bash
python3 tools/extract_task_strings.py --locales en   # 缺的 msgid 自动补（已译的保留）
#   → 编辑 locales/en/LC_MESSAGES/sysweeper.po，填 msgstr
python3 tools/make_mo.py                             # 只编已填译文的条目
PYTHONPATH=src/python python3 -m pytest tests/test_task_i18n.py -q
```

## 9. 决策记录

| 决策 | 理由 |
|---|---|
| 源语言=zh_CN | 项目文档/界面原生中文；默认零配置即中文，译文按需挂载 |
| 显式 `--locale` / `SYSWEEPER_LOCALE` | 避免 CI `LANG=en` 误翻译破坏断言 |
| 自写 `make_mo.py` | CI 镜像无 gettext 工具链，零依赖可单测 |
| 机器数据不进 PO | 后台保持原样，翻译无意义且损可复现 |
