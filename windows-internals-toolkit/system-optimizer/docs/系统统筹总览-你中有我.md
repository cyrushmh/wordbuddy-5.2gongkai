# 系统统筹总览（v0.6.18）——「你中有我，我中有你」

> 承上：v0.6.11–v0.6.17 把网络栈从「本机 L1–L4」延伸到「DNS → Tor 覆盖层 → ZeroTier
> 虚拟组网 → 本地 mesh」，并导入 Proton/WSL/VirtIO-GPU/浏览器引擎/内核/单板机/优化资讯
> 等只读诊断模块。模块不少了，但仍是「各看各的孤岛」。
>
> 本阶段不新增又一个孤立模块，而是把既有模块**编排成一张系统地图**，落实用户的统筹要求：
> **统筹系统与局部兼顾、你中有我我中有你、全面健康有序的科学发展。**

## 一、落点：一个只读编排层（不堆第 N 个孤岛）

新增 `native/sysmap.py`，只做一件事——**只读聚合 + 关联**：

- 调用 13 个既有只读子系统的单入口报告函数（`*_report()`），不新增任何写/执行路径；
- 把结果收敛成四段总览：**整体健康汇总 / 局部本征状态 / 关联关系图 / 有序深入建议**；
- 某子系统诊断异常时只标「异常」并跳过，不影响整体。

接入面：`registry`（注册 `sysmap_overview` 任务）、`cli`（`sysmap` 子命令）、
`gui`（顶栏「系统总览」只读窗口）、`tasks/sysmap.py`（`platform=any / category=maintenance / risk=low`）。

## 二、你中有我，我中有你（关联即系统）

总览显式画出子系统耦合——一个问题会传导到另一个，而不是各看各的：

| A | B | 关系（一个出问题会传导到另一个） |
|---|---|---|
| 网络接口/路由 | DNS 解析 | 网络连通以解析为前提；dnshealth 与 nm_resolved 互补 |
| DNS 解析 | Tor 覆盖层 | Tor 启用 DNSPort 时解析经洋葱流转，隐私提升 |
| Tor 覆盖层 | ZeroTier 虚拟组网 | 同为覆盖层：Tor 偏匿名、ZeroTier 偏组网，可叠加 |
| OSI 七层 | 网络接口/路由 | OSI 以 L1–L4 本征为底座，逐层上探 |
| Proton 兼容层 | 虚拟化/GPU | 游戏渲染依赖 Vulkan/VirtIO-GPU(venus) 后端 |
| Proton 兼容层 | 内核模块 | 兼容依赖 NTSync/fsync 同步原语（内核版本门控） |
| Proton 兼容层 | 发行版能力 | 32 位 i386 运行时由发行版包管理供给 |
| 浏览器引擎 | DNS 解析 | 引擎兼容依赖解析链路健康 |
| 浏览器引擎 | 字符标准 | 网页渲染依赖系统字体/emoji 中文回退 |
| ZeroTier 虚拟组网 | 本地自组网 | 跨网虚拟组网 vs 近场自组网，是组网两端 |
| 虚拟化/GPU | 内核模块 | GPU/虚拟化受内核模块与 CPU 虚拟化标志约束 |
| WSL 子系统 | 网络接口/路由 | WSL2 经 virtio-net，可与宿主机网络/ZeroTier 叠加 |

## 三、统筹系统与局部兼顾（整体 + 局部同一视图）

- **整体**：13 子系统按 `正常 / 提示 / 不适用 / 异常` 四档收敛，先看清全局；
- **局部**：每个子系统只看状态（深入用对应子命令钻取 `tor/zerotier/dnshealth/proton/...`）；
- **有序深入**：给出科学排序的排查路径，而不是随手点开：
  1. 网络异常：`硬件/网卡 → 发行版网络管理 → OSI(L1-L3) → 网络(L4+/路由) → DNS → 覆盖层(Tor) → 虚拟组网(ZeroTier) → 本地自组网`
  2. 兼容/游戏异常：`内核(NTSync/fsync) → GPU(Vulkan/VirtIO) → 发行版(i386) → Proton`
  3. Web/应用兼容：`DNS → 字符标准 → 浏览器引擎`

## 四、红线（与全工具一致，本层更严）

- 仅做**只读聚合与关联**：不启停任何服务、不改任何配置、不连控制端口写命令、不写入任何系统状态；
- 单个子系统异常只在总览标「异常」并跳过，绝不因一个模块报错而整体崩。
