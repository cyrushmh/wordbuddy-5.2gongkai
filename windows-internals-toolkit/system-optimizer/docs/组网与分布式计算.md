# 组网通信与分布式计算（v0.6.8）

三件事：**同网段能说话**、**闲着的核能用起来**、**入网后本机也能变强**。
每件事都有一条不能越过的安全线。

---

## 1. 组网通信（meshchat）：iptux / 飞鸽传书 / wall

### 1.1 为什么兼容现成协议而不是自创

IPMsg（飞鸽传书）是 1996 年 H. Shirouzu 定下的公开协议，Linux 上的 **iptux**
就是它的开源实现。按它的包格式走，**网里已有的飞鸽 / iptux 客户端能直接收到
我们的消息——不用说服所有人装新软件**。

自创协议在真实环境里等于没人可用：你没法让办公室里已经装了飞鸽的同事
为了收你一条通知再装一个东西。

| 要素 | 取值 |
|---|---|
| 端口 | **2425**（0x0979），消息走 UDP，文件走 TCP |
| 包格式 | `版本:序号:用户:主机:命令字:附加`，命令字 = 基本命令 \| 选项位（十进制） |
| 基本命令 | `BR_ENTRY`(上线) / `BR_EXIT`(下线) / `ANSENTRY` / `SENDMSG` / `RECVMSG`(回执) / `GETFILEDATA` … |
| 常用选项位 | `SENDCHECK`(要回执) / `FILEATTACHOPT`(带附件) / `BROADCAST` / `UTF8OPT` … |

**全体广播**就是 `wall` 的语义：往受限广播地址发一条，同网段终端都能收到。
断网时这是**最可靠的通知方式**——不依赖任何外部服务器。

### 1.2 消息类型：载荷不同，通道同一条

文字 / 图片 / 视频 / 文件 / emoji / 颜文字，**只是载荷类型不同**，不需要为每种
类型各造一套协议。emoji 走 Unicode 标准码位（UTS #51）；颜文字是普通字符拼组
（＾▽＾ 之类），零依赖、任何终端都能显示——**在老设备和纯文本环境里比 emoji 更可靠**。

### 1.3 安全边界：收到的东西不自动落盘

文件类载荷一律进**待收清单**，给出大小与来源，**由你显式接受才落盘**。

> 自动接收 = 别人能往你机器里塞东西。这条口子绝不开。

附件的传输方向也是**对端来拉，不是我们推**：先发消息包（含文件属性串），
对端主动来 TCP 2425 取——这样对端可以拒绝。超大载荷有上限，超限直接拒绝并在
清单里标注，不硬扛（防止内存被吃光）。

### 1.4 已知边界

- IPMsg 是**明文且默认无认证**的协议，只适合可信局域网。跨公网请另走加密通道。
- 广播会影响网段内所有设备；公共网络慎用，勿用于打扰他人。

## 2. 分布式计算（distcompute）：BOINC 式，但砍掉信任链

### 2.1 与 BOINC 的根本差异（不是细节）

BOINC 的模式是**项目方下发可执行程序**，你的机器下载并运行它。
信任链是"我信任这个项目方"。这条链一旦断——项目方被入侵、镜像被劫持、
DNS 被污染——你就是在自家机器上跑别人的二进制。

本层**砍掉这条链**：只跑**内置可验证算子**（白名单里三个，就在
`native/distcompute.py` 里写着），**绝不下载、绝不执行任何外部代码**。

| | BOINC | 本层 |
|---|---|---|
| 计算内容 | 项目方下发的任意程序 | 内置白名单算子（3 个） |
| 信任基础 | 信任项目方 | **不信任任何人**，只信复算结果 |
| 能算什么 | 真实科学项目 | 只有内置算子能表达的活 |
| 风险面 | 远程执行通道 | 无远程执行能力 |

代价是算不了真实的科学项目；收益是——**网里任何一台机器入网，都不会因此获得
在你机器上执行代码的能力**。这个交换值得：我们要的是"把闲着的核用起来"，
不是"再开一个远程执行通道"。

### 2.2 可验证性：校验必须比计算便宜

这是冗余双投能成立的前提：

| 算子 | 校验方式 | 校验成本 |
|---|---|---|
| 哈希原像搜索 | 对找到的 nonce 做一次哈希 | O(1)，远便宜于搜索 |
| 分块矩阵乘法 | 抽一行一列重算 | O(n) 而非 O(n²) |
| 蒙特卡洛求 π（固定种子） | 同种子原样复算 | 同量级但可控 |

两份独立结果一致才接受，不一致就标**存疑并重投**——
**不信任任何单个节点的自述**，这是分布式计算的常识。

### 2.3 调度：用硬指标做上限，不用信任做上限

```
可捐献评分 = 核心数归一化 × 空闲度 × 供电系数 × 网络计费系数
```

- **电池低于 20% → 评分归零**（不派活）；用电池时系数降到 0.6。
- **计量网络**（手机热点 / 按量计费）降权到 30%：不是安全考量，
  是**别让人替你交流量费**。
- 忙碌的机器评分自然低，闲着的自然高——不需要谁"声明"自己闲。

### 2.4 预算纪律

默认**只出计划不真跑**；真跑也有硬性时间预算（默认 2 秒），**跑满即停**，
绝不为了跑完而拖慢机器。本地自测的意义是"先确认这条链是通的"——
在没验证过的链路上派活，等于把问题放大 N 倍。

credit 只在本地记一笔（谁干了多少活），**不换任何东西、不上链、不结算**。

## 2.5 跨机派活（`native/distjob.py`）：把计划真正派出去

只有计划不派出去就是纸上谈兵。本层把 WU **经组网文本通道**派出去、把结果收回来：

```
SW-WU1:{"job":"…","op":"mc_pi","i":0,"p":{…},"budget":2.0}   派活
SW-RES1:{"job":"…","i":0,"r":{…},"ms":12.3}                  回结果
```

**为什么不新建协议**：组网通道已经有了（meshchat，UDP 2425），WU 描述与结果都是
短文本（几百字节），塞进一条普通消息即可。网里已有的飞鸽 / iptux 客户端会把它
显示成一条普通消息——**不会干扰它们**，只是看不懂而已。

**信任模型不因跨机而放宽**：

| 环节 | 做法 |
|---|---|
| 收到 WU | **只跑白名单算子**，`op` 不在 `OPS` 里连解析都不认 |
| 收到结果 | **必须复算校验**，通过才算数，不通过标"存疑" |
| 时间预算 | 取"派活方给的 budget"与"本机上限"的**较小值** |
| 默认行为 | `dispatch()` 默认 `dry_run=True`——**只编码不出网** |

> 通道里传的是**参数不是代码**。别人发一句"请执行 xxx"是发不进来的。

本地回环自检（`loopback_report()`，不通网）七步：编码 → 解码 → 计算 → 回传校验 →
**伪造结果能否混过（必须被打回）** → 坏包处理 → **白名单外算子必须被拒**。

真实通道也有测试守着：往 127.0.0.1 真发一个 WU，用 `serve_once()` 接住、算完、
回传——不是模拟。

## 3. 入网后的能力优化（捐与借是同一件事的两面）

参与组网不只是"捐算力"，也是"借能力"：

| 维度 | 做法 | 边界 |
|---|---|---|
| **计算** | 把可切分的活派给评分高的节点，本机只做汇总 | 限核与"仅空闲时"的让渡策略由你在系统设置里定，工具不代改 |
| **图形** | 按登记的 GPU/NPU 型号把渲染/转码类的重活派给有卡的机器 | **只登记型号，不跑负载、不改驱动、不超频**；不自动调用网内 GPU（那等于远程执行） |
| **网络** | 认准计量网络并降权；大块传输走有线或可信 Wi-Fi | 别替别人交流量费 |

## 4. 安卓优先构建：8 与 14 两头卡住

- **Android 8（API 26）是下探底线**：本项目对安卓的支持从这里起步，
  再往下连一批基础接口都变了形，硬撑就是在报告里写假话。
- **Android 14（API 34）是现行主流**：新机大多在这条线上，权限与后台限制
  也是最严的一档——**能过 14，中间版本基本都能过**。

实测矩阵：

```
Android 8  (API 26): 112 项任务；风险 low 95 / medium 16 / high 1
Android 14 (API 34): 113 项任务；风险 low 96 / medium 16 / high 1
仅 14 有：1 项（and_app_hibernate）
```

`tools/build_android.py` 只生成**目标配置**（存任务 id 与元信息，不存任何命令）。

**要说清楚的一点**：本工程在安卓上是以 **Termux / adb shell 方式运行脚本**，
**不产出 APK**。别让人以为能装一个 App。

其他平台按你的要求：**只提交代码跑测试，不构建**（`--target other`）。
