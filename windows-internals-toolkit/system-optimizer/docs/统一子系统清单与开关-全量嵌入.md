# 统一子系统清单与开关：全量嵌入整体系统（v0.6.22）

> 目标：把「硬编码零散子集」升级为「**统一清单 + 可配置开关 + 全量嵌入**」。
> 所有已导入/自研、能嵌入整体系统（sysmap 关联总览）的只读诊断，必须嵌入；
> 每一项都可用选项单独开/关。

## 一、要解决的问题

v0.6.21 及之前，`native/sysmap.py` 里 `PROBES` 只硬编码了约 18 个子系统，
而 native 层实际有 50 个只读诊断模块。大量可嵌入的维度被漏在外面：

- 用户点名但未被显式登记的：**firmware（固件）**、**plugins（插件）**、**modules（内核模块）**
- 有子报告却没有主聚合、因此无法整体嵌入的：kernel / storage / container / hardware
- 已导入分析学习但只挂在各自子命令里的：openwrt / jdk / pkgmgr / miniapp / meshchat /
  netlink / netauth / distcompute / distjob / emergency / reshare / syssoftware / arch /
  跨平台 OS 探测（android / ios / macos / bsd / unix / windows / desktop）

同时，原先也没有「子系统级开关」——只有 `Task.opt_in` 这种**任务级风险开关**
（网络/ITU 深度调优），管不了「这个模块要不要进总览」。

## 二、方案：三层

### 1. 单一事实源清单（新建 `native/subsystems.py`）

每项登记为一个 `Subsystem(key, label, layer, module, fn, default_on=True)`：

| 字段 | 作用 |
|---|---|
| `key` | 唯一标识；配置文件与 `RELATIONS` 端点都按 key 定位，不用 label 免重名歧义 |
| `label` | sysmap 展示标签（中文） |
| `layer` | 所属层，用于 sysmap 分组展示 |
| `module` / `fn` | 指向既有的只读报告函数（零参，返回 `(bool, str)` 或 `list`） |
| `default_on` | 默认全开，向后兼容「全量嵌入」 |

覆盖 **49 项**，含用户点名的三类：

| 维度 | key | 指向 |
|---|---|---|
| 固件 firmware | `firmware` | `kmod.firmware_report` |
| 插件 plugins | `plugins` / `plugins_allowlist` | `plugins.plugin_report` / `allowlist_report` |
| 内核模块 modules | `kmod` / `modules` | `kmod.kmod_report` / `loaded_modules_report` |

### 2. 可配置开关

- 配置落点：`~/.config/sysweeper/subsystems.json`（键=子系统 key，值=bool）
- 读配置时与默认合并，**未知 key 自动忽略**；配置损坏则安全回退默认，绝不阻断总览
- API：`default_states / load_states / save_states / set_enabled / is_enabled /
  enabled_subsystems / enabled_probes / list_subsystems`

### 3. sysmap 改为清单驱动

- 从 `subsystems.enabled_probes()` 取探测项，**即调即求值、尊重开关**——
  关闭的子系统**既不诊断也不展示**（其报告函数根本不会被调用，见测试 `test_disabled_subsystem_not_diagnosed_nor_shown`）
- 兼容两种返回：`tuple → (ok, msg)`、`list → (True, 拼接)`
- `RELATIONS` 扩到 **48 条**，且**只在两端都已启用时**才画出
- 新增「模块开关状态」段，让用户一眼看见当前嵌入了几项
- `PROBES` / `RELATIONS` 仍作为模块级常量对外暴露（供既有测试），从清单派生、标签一致

## 三、补的四个零参聚合报告

`kernel` / `storage` / `container` / `hardware` 原本只有子报告、没有主聚合，
因此无法作为整体的一项嵌入。各补一个零参 `*_report()`，串联既有子报告：

| 模块 | 新增 | 串联的子报告 |
|---|---|---|
| kernel | `kernel_report()` | sched / oom / psi / thp_compaction / vm_dirty / tcp / tcp_congestion / net_core / rps |
| storage | `storage_report()` | btrfs / xfs / zfs / lvm / fstrim / smart / swap + environment |
| container | `container_report()` | docker / podman / containerd / buildkit / oci / lxc / cri + environment |
| hardware | `hardware_report()` | bus / thermal / zram / nvme / watchdog / cpuidle |

全部只读，任一子报告异常即跳过该项，不影响整体。

## 四、用法

```bash
sysweeper subsystems --list              # 列出全部子系统及开/关
sysweeper subsystems --disable tor       # 关闭某项
sysweeper subsystems --enable tor kmod   # 开启多项（空格或逗号分隔）
sysweeper subsystems --enable-all / --disable-all
sysweeper --list-subsystems              # 顶层快捷列出
sysweeper --disable firmware             # 顶层快捷开关
sysweeper sysmap                         # 总览只枚举已开启项
```

图形界面：主窗口顶部「控制台」、底部「控制台(全模块)」打开**系统控制台**——
左栏按层分组列出全部子系统，每行「勾选开关 + 点诊断就地执行」，右栏输出。

## 五、红线

- 新增与改动**全部只读**：只登记、只开关、只聚合，不启停服务、不改配置、
  不连控制端口、不写入任何系统状态（唯一写的是用户自己的开关配置文件）。
- 关闭的子系统连报告函数都不会被调用——不是「算了不展示」，而是真的不诊断。
- 真正会改系统的动作仍只走主窗口「执行选中项」，且需显式勾选 `--apply` + `--yes`。

## 六、测试

新增 `tests/test_subsystems.py`（10 项）与 `tests/test_sysmap_embed.py`（6 项）：

- 清单含 firmware/plugins/modules 等点名维度；key 与 label 均唯一
- 默认全开；每项都指向真实存在的只读函数
- 关闭后 `enabled_probes` 不再枚举、sysmap 不再展示、报告函数不被调用
- 关联图只画两端均已开启的耦合
- 配置落盘后回读一致；配置损坏安全回退默认
- 测试用 `monkeypatch` 把配置落点隔离到 `tmp_path`，绝不污染真实用户配置

全量：`685 passed, 3 skipped`。
