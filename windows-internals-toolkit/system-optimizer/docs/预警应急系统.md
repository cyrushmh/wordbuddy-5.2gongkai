# 预警应急系统（v0.6.8）

一句话立项：**预警只有落在"离我多远"上才有意义。**

一条 300 公里外的红色预警，和一条 3 公里外的黄色预警——后者才该让你现在就动。
所以本层的第一件事不是"接预警源"，而是**先把位置与距离算清楚**。

---

## 1. 定位口径（本层最关键的设计）

按使用者定的口径写死三条：

| # | 口径 | 为什么 |
|---|---|---|
| 1 | **首选基线 = 网络定位 + 基站定位** | 室内、地铁、隧道、省电模式下常常没有导航信号，但网络与基站几乎总在。先用它，保证**任何情况下都有一个可用的地理位置与距离**，不出现"定位不可用"就说不了话的空洞 |
| 2 | **有导航定位时，导航 + 首选基线共同综合** | 不是"有导航就丢掉基站" |
| 3 | **两源互相校核**，偏差超 2 km 标**存疑** | 两套结果都摆出来，**不替用户判定哪个对** |

### 1.1 为什么"共同综合"不是直接逆方差

导航精度（~8 m）比基站（~1500 m）高两个量级，纯逆方差加权会让基线权重趋近 0
（8² : 1500² ≈ 1 : 35000）——那就退化成"只用导航"，不是你要的"共同综合"。

所以给**基线留 5% 最低话语权**：

```
w_nav  = 1 / acc_nav²          w_base = 1 / acc_base²
share_nav = w_nav / (w_nav + w_base)，上限压到 95%
share_base = 1 - share_nav，下限 5%（基线内部再按各自精度分配）
融合点 = share_nav · P_nav + share_base · P_base
融合精度 = √(share_nav²·acc_nav² + share_base²·acc_base²)
```

效果：导航主导但不独占，**一次 GNSS 跳变不至于把位置甩到几公里外**；
基线始终参与校核。实测（基站 ±1500 m + 网络 ±5000 m + GPS ±8 m）：

```
模式 nav+baseline | 权重 gnss 95.0% / cell 4.6% / network 0.4%
综合 31.231010,121.474486 ±72.2 m
基线 31.231193,121.474220 | 导航 31.231000,121.474500 | 偏差 34 m（一致）
```

### 1.2 拿不到坐标时诚实报"没有"

Linux 上没有 ModemManager / GeoClue，或没有基站经纬度库时，**就是拿不到坐标**。
此时报告写"未取到"，列出"基站可见（LAC=… CID=…）但无坐标"——
**绝不凭 IP 编造一个位置出来**。编造的定位比没有定位更危险。

## 2. 预警评估

字段对齐 **OASIS CAP 1.2**（`event / severity / urgency / certainty / area /
effective / expires / instruction`），四色预警（红/橙/黄/蓝）只作显示映射，
不改变判定逻辑。

每条预警给出：

- **距你多远**（Haversine 大圆距离）
- **是否落在影响半径内**，不在则给出到边界还差多少
- **粗估多久到达边界**（按事件类型典型速度：地震 P 波约 6 km/s、台风移速约 8 m/s）
  ——报告里明确写**"仅供量级参考，不是预报"**
- **你的位置精度**（例如 ±72 m）——避免把"14.2 km"当成精确值

按**由近到远**排序：预警场景下距离就是优先级。

> **没有预警就是没有预警。** 本层不会凭空生成预警，也不会把"未取到数据"
> 包装成"安全"。

## 3. 应急功能

| 功能 | 说明 | 边界 |
|---|---|---|
| 避险点排序 | 你填的集合点按直线距离由近到远排 | 工具不知道你那儿哪儿能躲，**凭空列"附近避难所"是造假**；直线距离 ≠ 步行距离 |
| 物资核对 | 10 项"3 天自救"基线清单 | 只核对，不替代官方指引 |
| 呼救文本 | 组装位置 + 精度 + 最近避险点 + 已通知的人 | **只生成文本，绝不发送** |

呼救文本里的位置**带精度**（例如 ±72 m）——报一个 ±1.5 km 的坐标却不说明精度，
是害人不是救人。

发送通道由你自己选：可以贴到组网通信（飞鸽传书 / iptux 兼容）的全体广播，
在断网时的同网段内发出去；也可以自己打电话。工具不碰任何发送动作。

## 4. 手动开关（真生效）

| 开关 | 默认 | 关掉会怎样 |
|---|---|---|
| `locate_enabled` | 开 | 不再探测本机定位，只用手动录入的坐标（给不想被探测的人留的出口） |
| `prefer_cell_network` | 开 | 不再以网络 + 基站为首选基线 |
| `fuse_with_nav` | 开 | 导航不再与基线综合（只用导航） |
| `alert_enabled` | 开 | 预警评估整体关闭 |
| `feed_enabled` | **关** | 不联网订阅预警源 |
| `sos_enabled` | 开 | 呼救文本功能关闭 |
| `shelter_enabled` | 开 | 避险点排序关闭 |
| `kit_enabled` | 开 | 物资核对关闭 |

关掉的功能**直接返回关闭提示**，不做"关了还偷偷跑"这种事（有测试守着）。

开关只存**布尔值与坐标数字**，落在 XDG `~/.config/sysweeper/emergency.json`，
**不存命令、不存代码**；文件损坏就回退默认，绝不拖垮界面。

图形界面：顶部「预警应急」按钮 → 窗口底部勾选即生效。

## 5. 红线（写死，任何情况下不越）

1. **不自动报警、不拨号、不发短信。** SOS 只生成文本。
2. **不擅自联网抓预警源。** 订阅默认关闭；开了也只拉你自己填的 http(s) 地址，
   拉不到就报"未能获取"。非 http(s) 地址直接拒绝（防本地文件被当源读）。
3. **不凭 IP 编造坐标。**
4. **不把"没数据"包装成"安全"。**

## 6. 已知边界（不装作没有）

| 边界 | 现状 |
|---|---|
| Android 定位 | 需 adb 且设备授权调试；读的是系统**最后已知位置**（last location），非实时 |
| Linux 定位 | 无 ModemManager / GeoClue / 基站经纬度库时拿不到坐标，只报"可见但无坐标" |
| 粗估到达 | 只按事件类型典型速度算量级，不考虑地形、建筑、实际路况 |
| 避险点 | 需你手动填，工具不内置任何真实场所数据 |

## 7. 任务清单

| 任务 id | 内容 |
|---|---|
| `emergency_locate` | 定位与距离综合（先网络 + 基站，有导航再共同综合） |
| `emergency_alert_assess` | 预警评估（距你多远 / 是否在影响范围内） |
| `emergency_sos` | 应急呼救文本生成（只生成，绝不自动发送） |
| `emergency_preparedness` | 应急准备度核对（避险点排序 + 物资清单） |
| `emergency_switches` | 手动开关（逐项开/关，持久化记住） |

五项均为 `platform="any"` + `risk="low"`，动作只有只读报告与手动指引。

## 8. 标准出处

- OASIS **CAP 1.2** Common Alerting Protocol（预警消息交换格式）
- **WGS 84**（NIMA TR8350.2）定位坐标基准
- **Haversine** 球面大圆距离公式
- **Inverse-variance weighting** 逆方差加权（多源融合通用方法）
- 国家突发事件预警信息发布四色预警（红/橙/黄/蓝）
- ITU-R 早期预警与灾害减灾相关建议书
